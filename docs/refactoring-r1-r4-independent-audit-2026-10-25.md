# Независимый финальный аудит рефакторингов R1–R4 PlaceLens

Дата: 25.10.2026. Статус: независимый аудит фактического рабочего дерева. Продуктовый код, тесты и существующие документы не исправлялись. Единственное добавление в проект — этот отчёт. Протоколы реализации использованы как перечни проверяемых утверждений.

## Вердикт

Подтверждённых блокирующих дефектов R1–R4 не обнаружено. **Серию можно закрыть.** Принятие относится к исследованным frontend-сценариям и границам ниже; это не формальное доказательство эквивалентности любого исполнения и не новый acceptance backend/GIS.

| Этап | Решение | Основание |
|---|---|---|
| R1, общий loader | Можно принять | Один compiler/evaluator, явные import boundaries; потребители исполняют настоящие TS/SFC. Миграция стендов исследована отдельно от переносов R2–R4 |
| R2, useTripsState | Можно принять | Владение состоянием перенесено целиком; транспортный guard и предметный epoch защищают разные операции; DOM остаётся странице |
| R3, useComparisonLink | Можно принять | Один координатор общей ссылки; query, fragment и предметные ячейки сохраняют отдельное владение; короткие последовательности дополнительно проверены |
| R4, tripOverlay | Можно принять с необязательным замечанием A-O1 | Подготовка данных отделена от renderer и камеры; актуальность кандидатов проверена точным adapter, включая одинаковые координаты в разных контекстах |

Обязательных задач исправления не предлагается. A-O1 — небольшое усиление постоянной регрессии, не условие закрытия.

## 3. R1 — общий тестовый загрузчик

Основной участок: [support/vue-component.mjs](/home/daba/projects/web_gis/tests/frontend/support/vue-component.mjs:9). Поиск по frontend tests оставляет один `ts.transpileModule`, один evaluator `new Function` и один SFC compileScript в этом support. Прежние независимые regex-преобразователи потребителей устранены. Другие regex в тестах исследуют HTML/текст, а не разрешают TS/Vue imports.

AST учитывает default, named, aliases, named re-export и type-only bindings; runtime `require` отклоняет неизвестную зависимость и отсутствующий необходимый экспорт. CommonJS default допускает сам экспортированный объект/функцию, а `__esModule` namespace требует настоящий `default`. Дополнительная независимая проверка исполнила CommonJS function default, namespace import, export-star, aliased default re-export, type-only export и отсутствующий re-export. Всё прошло.

Модули не имеют общего evaluator cache. Globals передаются аргументами конкретного вычисления; отдельные mocks/локальный счётчик дают независимые результаты. Независимая проверка также подтвердила отсутствие записи тестового global в globalThis. Переданные объекты зависимостей при этом не клонируются: если стенд сам разделяет mutable mock, это его ответственность. Текущие shared tables преимущественно содержат чистые утилиты; жизненный цикл и state создаются в стендах.

`loadComponent` использует настоящий Vue compiler и runtime, сохраняет props/slots и SSR/client режимы. AddressPicker исполняется в Vue in-memory renderer; map-тесты вызывают настоящий setup с управляемыми lifecycle hooks и cleanup. `loadSetup` намеренно исполняет сырой script setup с явным списком bindings двух страниц: он не проверяет шаблон, SFC macros, браузерный DOM или полную семантику mount. Эти границы дополнены SFC/SSR и browser smoke. Расширять его до Vite resolver не требуется.

| Граница | Настоящее исполнение | Подмена и её назначение |
|---|---|---|
| Общий loader | Установленные TypeScript, Vue compiler/runtime/SSR | Явные namespaces и локальные browser globals |
| State /trips | useTripsState, в прямых state-тестах также useTripAnalysis | fetch/promises и lifecycle; часть старых page/SSR fixtures подменяет транспорт для контролируемого результата |
| State сравнения | useComparisonTrips, useComparisonLink; прямые link-тесты также useAddressComparison | Управляемые API и history/window |
| Карта | Настоящие CityMap, tripOverlay, tripMap и чистые map helpers | FakeMap/DOM/observers/RAF; CSS и worker URL обозначены явно |
| Browser | Настоящий app, Vue, MapLibre, события, worker и camera | Синтетический API и локальный пустой basemap; обращения к backend исключены стендом |

Заглушек, возвращающих ожидаемое поведение новых composables или нового overlay вместо настоящих модулей, не найдено. Подмена карты/picker/icons в отдельных SSR-тестах оправдана их областью. Оставшийся прямой тест старой MetricCard — прежняя граница набора, уже отмеченная первоначальным аудитом, а не регрессия R1.

По исполняемому wiring миграция достаточна для текущих потребителей. Формальное тождество всех возможных TS/ESM/SFC программ не заявляется.

## 4. R2 — ownership и актуальность самостоятельной поездки

Основные участки: [useTripsState](/home/daba/projects/web_gis/resources/js/composables/useTripsState.ts:15), [useTripAnalysis](/home/daba/projects/web_gis/resources/js/composables/useTripAnalysis.ts:5), [TripsPage](/home/daba/projects/web_gis/resources/js/pages/TripsPage.vue:23).

Черновик, road hints, candidate options, dirty/pending/failed и правила сохранения строк принадлежат useTripsState. `analysis/status/error` — те же refs из useTripAnalysis; второй независимо изменяемой копии результата не создано. Временно сохранённые строки при запросе — осмысленный retained result, а не второй источник истины. Потребители страницы читают результаты; записи в analysis/status/error или самостоятельной инвалидации страницы не найдено. Writable draft нужен форме, noticeDismissed — представлению. Возможность внешнего потребителя вручную переписать ref не равна существующему обходу инвариантов; readonly-фасад автоматически не требуется.

`useTripAnalysis.sequence` проверяется до записи transport response/status/error. `useTripsState.runSequence` проверяется после await и закрывает принятие кандидатов/hints, failure bookkeeping, history-effect и актуальность DOM callback. Инвалидация увеличивает предметную эпоху и вызывает transport clear/abort. Поэтому ответ, доставленный вопреки abort, не получает ни права записи ответа, ни права продолжения предметной операции. При unmount обе защиты инвалидируются.

| Последовательность | Проверенный механизм и результат |
|---|---|
| Правка одной цели / общего старта | Sync watcher сохраняет только совпавшие по identity/position независимые строки; старт инвалидирует все |
| Переименование, в том числе при запросе | Не входит в positionKey; не отменяет расчёт и не удаляет маршрут; завершение сохраняет актуальную подпись |
| Удаление средней цели | Сопоставление по объектам, а не старому номеру; перенумеровываются row.index, относящиеся target_index и candidate keys |
| Неполная форма + другой road hint | chooseRoad инвалидирует affected/pending/failed до отказа в отправке; старый успех не остаётся действительным |
| Частичный отказ / повторный технический отказ | Независимые строки сохраняются там, где разрешено; failedChoiceIndices исключают ошибочные старые значения и повторное «воскрешение» успеха |
| Late response после target/start/remove/reset/restore/new request/unmount | Семь существующих прямых сценариев используют реальные state+transport и доставку вопреки abort; проверяют также hints/candidates/history |
| Reset/restore/history | Страница разбирает ссылку и вызывает restore; state сбрасывает эпохи/кандидаты/запрос и перепроверяет восстановленный выбор |

Effects интерфейс не прячет предметных зависимостей: передаёт TripSelection и режим сохранения, а `beginRun(reveal)` возвращает обработчик с проверкой актуальности. В composable отсутствуют DOM selectors, focus, scroll и чтение размеров. Страница захватывает interactionEpoch/время и повторно проверяет актуальность после nextTick. Более сложная система эффектов или универсальная state machine не обоснованы.

## 5. R3 — ссылка, history и профили

Основной участок: [useComparisonLink](/home/daba/projects/web_gis/resources/js/composables/useComparisonLink.ts:8). useAddressComparison владеет адресами/радиусом и загрузкой профилей; useComparisonTrips — целями, ячейками, hints и epochs; useComparisonLink — объединением записей query/fragment и browser navigation. ComparePage делегирует сохранение query, не содержит конкурирующего fragment watcher.

Четыре механизма не являются четырьмя копиями предметного состояния:

- locationKey объединяет search/hash и подавляет повторное восстановление связанных событий;
- lastFragment хранит каноническую подпись прочитанной/записанной ссылки;
- lastSelection хранит полученное состояние и подавляет queued watcher восстановления, включая очищенные адресной навигацией hints;
- pendingSides — очередь сторон, ожидающих правильного профиля, а не результатов маршрутизации.

Каноническая сериализация через прежний parser удаляет пустые hints. Для различения rename и geometry сериализуются пустые label: rename заменяет запись, изменение геометрии/road choice добавляет. Reset явно создаёт запись и сразу запоминает пустой fragment, включая reset до flush. Попарные popstate/hashchange не создают обратный цикл записи.

Перед перепроверкой совпадают текущий selected ID, start ID и profile.address.id; start должен иметь точку. Радиус сам не вызывает расчёт поездок. Замена А не инвалидирует Б; при query history с тем же fragment очищается только устаревший hint изменённой стороны. Очередь удаляет сторону до calculate. Geometry edit отменяет оставшиеся восстановительные продолжения.

Исследованы существующие valid→invalid, restore→reset, edit до flush, query/hash navigation, rename/geometry, unknown version/limits и unmount tests. Дополнительно вне исходников выполнены четыре случая на настоящих composables:

1. Профили приходят раздельно; неверный profile ID не допускает расчёт, затем каждая сторона рассчитывается ровно один раз со своей точкой.
2. Restore→reset→новая цель до flush сохраняет только итоговый выбор; последующее завершение профилей не запускает отменённую очередь.
3. Invalid→valid снимает предупреждение, восстанавливает цели и выполняет по одной перепроверке стороны без history feedback.
4. Queued edit и завершение профиля после unmount не вызывают history, effects или расчёт; handlers сняты.

`disposed` закрывает callbacks и записи истории после unmount. Отложенной общей блокировки nextTick, способной потерять правку пользователя, нет. Представление/focus остаются эффектами страницы, ячейки напрямую координатором не переписываются.

Обычная shareUrl содержит только адресный query; personalShareUrl дописывает fragment. Старые лимиты числа/ID/подписей/размера, unknown-version rejection, privacy warning и clipboard fallback сохранены. Нового storage или логирования личного fragment в исследованных изменениях нет.

## 6. R4 — renderer, camera и GeoJSON worker

Основные участки: [adapter ComparePage](/home/daba/projects/web_gis/resources/js/pages/ComparePage.vue:60), [tripOverlay](/home/daba/projects/web_gis/resources/js/utils/tripOverlay.ts:27), [CityMap](/home/daba/projects/web_gis/resources/js/components/map/CityMap.vue:71), [installTripLayers](/home/daba/projects/web_gis/resources/js/utils/tripMap.ts:43).

CityMap владеет MapLibre instance, initialize/remove, событиями и камерой. Overlay не создаёт карту, не подписывается на события и не вызывает fitBounds/jumpTo. Его getter читает текущий подготовленный GeoJSON, собственное состояние ограничено disposed/layerIds. Ячейки/запросы/цели не копируются в renderer.

ComparePage выбирает ячейку по стороне и стабильному ID цели, преобразует request-local row.index к display index, задаёт подписи и candidate ID. CityMap получает data/sequence и события выбора; он больше не читает TripAnalysis, road groups или контекст цели. Оставшийся placeLabel А/Б относится к общей адресной карте и цветам, а не к частным маршрутным заголовкам.

`tripMapData` остаётся единственным общим построителем GeoJSON. Семь общих layers устанавливаются тем же installTripLayers; добавлены guards наличия source/layer и возвращаемые ID. На отдельном TripMap первая установка по-прежнему создаёт все ресурсы; его DOM markers и lifecycle не заменены вторым renderer. Второго владельца camera нет.

Readiness исследована по реальным точкам вызова: update до появления source безопасен; первая установка выполняется после load и после окружения; первый style.load пропускает install при mapLoaded=false. Retry использует сериализованный текущий style. Повторный style.load при загруженной карте идемпотентно ставит/обновляет overlay текущими данными без fitBounds. Controller сам не является произвольным resolver readiness: его вызывает владелец в нужные моменты.

Ручной trip picking имеет первый приоритет, затем актуальный road candidate, затем прежний dispatch остановок/адресов/окружения. Overlay не добавляет handlers; повторная установка не дублирует ресурсы. Null очищает source пустой коллекцией. Dispose идемпотентен, закрывает дальнейшие операции и удаляет девять принадлежащих этому controller layers и source trips; посторонние sources/layers не затрагивает. Во всех фактических потребителях source trips имеет одного владельца на карту.

Camera остаётся в CityMap. SelectionSequence отменяет две отложенные RAF при hide/reset/update/unmount и initialize. Смена данных без новой команды sequence не подгоняет camera. Общие zoom/bearing/pitch передаются без center. Adapter selectTripContext закрывает несовместимый overlay соседней цели, сохраняя её результат; заголовок не подписывает маршрут к другой цели.

### Асинхронный worker и исходные координаты

`queryRenderedFeatures` может вернуть старый feature после setData. Защита не полагается на завершение worker: adapter кодирует `[side, stable place.id, endpoint key, candidate.geometry]`; overlay принимает только ID из **текущего** data. Затем возвращает координаты найденного текущего feature, а не tile geometry. Смена номера кандидата сама по себе не делает другой road choice; одинаковая координата в той же стороне/цели остаётся тем же допустимым выбором.

Независимое воспроизведение выполнило точный computed-adapter, извлечённый из текущего ComparePage, настоящий tripMapData и настоящий overlay. У двух целей и двух сторон намеренно одинаковые road coordinates. Rendered hit удерживался от старого контекста: выбор отвергнут и для другой цели, и для другой стороны. При округлённом rendered Point выбранные координаты точно совпали с исходным текущим кандидатом.

Проверена чувствительность воспроизведения: только в памяти убрана проверка ID — оба stale-context случая упали; только в памяти выдача координат заменена на rendered geometry — проверка точности упала. Продуктовые файлы и постоянные тесты не менялись. Это подтверждает достаточность текущего candidate ID для исследованной гонки; ожидание реального произвольного тайминга worker для каждого случая не требуется.

Исходные точки и два отдельных соединителя сохранены; соединители не становятся route geometry или метрикой. Null/zero не смешиваются. Непринятый результат не получает выдуманный маршрут. Отдельный /trips остаётся на прежней карте; его поведение дополнительно проходит в полном browser suite.

## 7. Архитектура и стоимость сопровождения

Уменьшение связанности подтверждается местом принятия решений, а не числом строк:

| Правка сценария | После переноса |
|---|---|
| Сохранение/инвалидация независимой строки, diagnostics и кандидатов /trips | Один useTripsState; странице не требуется повторять правило |
| Доставка HTTP и transport errors | useTripAnalysis; state отдельно решает предметное продолжение |
| Канонизация history/restore сравнения | Один useComparisonLink при неизменных владельцах адресов и ячеек |
| Изменение маршрутов/кандидатов/подписей сравнения | Scenario adapter и trip helpers; CityMap не требует знания цели или request index |
| Изменение общей camera/readiness | Единственный владелец CityMap; overlay не конкурирует за неё |

useTripsState остаётся крупным специализированным владельцем связанного состояния. acceptingRoads/selectingCandidate/restoringDraft имеют разные короткие области подавления watcher; dirty/pending/failed отражают разные состояния результатов. Перенос не превратился в универсальный объект всех сценариев приложения. Широкий API соответствует текущему template; конкретного потребителя, обходящего инвалидацию через result refs, не найдено.

В useComparisonLink несколько сигнатур требуют аккуратности, но каждая соответствует реальной границе navigation/state; удаление любой из них без замещающего механизма потеряет рассмотренные случаи. Дополнительный router/store/readonly facade по этому аудиту не обоснован.

Прежние проблемы первоначального аудита — MetricCard вне production graph, Nginx test вне CI, фиксированные output paths диагностических скриптов, общие типы метрик — не объявляются регрессиями R1–R4 и не расширяют нынешнее задание.
