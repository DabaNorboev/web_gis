# Фронтенд PlaceLens

Статус: текущая карта модулей по исходникам, актуализирована 31.10.2026. Датированные протоколы UI вынесены в [индекс](README.md#исследования-и-прошлые-свидетельства); включает переключение интерфейсов G2, состояние самостоятельных поездок R2 и выбор пешего режима.

## Каталоги и соглашения

Vue/TypeScript — `resources/js`, CSS — `resources/css`, оболочка Blade — `resources/views/welcome.blade.php`.

| Каталог в resources/js | Ответственность |
|---|---|
| `pages` | Сборка сценария страницы, связь состояния с UI и DOM-эффектами |
| `layouts` | Общий каркас/навигация, сейчас PlaceLayout |
| `components` | Отображение и конкретные взаимодействия; `map` — карты/управление; `ui` — место для генерируемых shadcn-компонентов по необходимости |
| `composables` | Реактивное состояние и жизненный цикл запросов/выбора |
| `api` | HTTP к Laravel, без GIS и владения состоянием страницы |
| `types` | Контракты ответов и локального выбора |
| `utils` | Чистые преобразования, форматирование, подготовка display data |
| `maps` | Стиль подложки; не источник аналитических показателей |

Компоненты — PascalCase и script setup с TypeScript; composables — use*. Локальные типы держать рядом с кодом, общие — в types. Алиас `@` указывает на resources/js в Vite и tsconfig. TypeScript 6 закреплён для совместимости с vue-tsc; проверка — [testing](testing.md).

## Загрузка и страницы

`app.js` монтирует HomePage на `/`, лениво загружает AddressProfilePage на `/address/:id`, ComparePage на `/compare`, TripsPage на `/trips`. Laravel отдаёт одну Blade-оболочку при прямом открытии/reload. Обычные ссылки и history API покрывают нынешний объём; отдельного Vue Router/глобального store нет.

| Сценарий | Основные модули и ownership |
|---|---|
| Поиск/объект | AddressSearch → useAddressSearch → api/addresses; AddressPicker/useAddressChoice разделяют группу и конкретный объект. Наведение/фокус не подтверждают выбор |
| Главная/точка | HomePage → useTransportAnalysis → api/transport; TransportResults/stopGroups отображают официальные остановки. Координата и радиус принадлежат анализу точки, подпись не меняет их |
| Подпись точки | PointAddressLabel → usePointAddress → api/pointAddress; независимые loading/error/retry и явный выбор при неоднозначности. Используется и в TripPointPicker |
| Профиль | AddressProfilePage/useAddressProfile → api/profiles. ProfileSummary/ProfileMetric и profilePresentation показывают обзор/метаданные; страница владеет радиусом/историей/связью карты |
| Сравнение | ComparePage/useAddressComparison → тот же api/profiles; независимые стороны и общий радиус. ComparisonMetricRow → ComparisonMetric compact → ProfileMetric, сведения — ComparisonData |
| Поездки отдельно | TripsPage → useTripsState → useTripAnalysis → api/trips. useTripsState владеет черновиком, сохранением/инвалидацией результатов и дорожными кандидатами; страница — URL/history, представлением, режимом выбора точки и DOM-эффектами |
| Поездки сравнения | useComparisonTrips владеет целями/ячейками/epoch; useComparisonLink — fragment/restore и согласование записей URL с адресным query; ComparePage — контекст карты и DOM-эффекты. ComparisonTrips/TripPointPicker и ComparisonShare/ComparisonTripData отображают действия/сведения |
| Интересы | useOverviewTopics, OverviewTopics, comparisonFacts; один набор для профиля/сравнения, localStorage с обработкой отказа. Ссылка не передаёт предпочтения |

MetricCard.vue и прежние AreaLayerControls/LinearLayerControls пока остаются в дереве, но не входят в entry graph приложения. MetricCard ещё используется прямым SSR-тестом. Это кандидаты [аудита](research/structure-quality-audit.md), не удалённый этой задачей код.

Оба сценария поездок выбирают `driving`/`walking`. `WalkingTripDetails` показывает
только уличные метрики, отдельные объекты/улицы и неизвестные подходы. Выбор улиц
хранится отдельно от объекта; matched endpoints не становятся явным выбором
автоматически. HTTP-граница `api/trips` сверяет identity и walking scope/null-контракт.
Пешая карта показывает выбранные улицы и проверенную линию, без соединителей
от объекта к улице. Основной контракт поведения и ссылок — [trips](features/trips.md).

## Состояние и побочные эффекты

<a id="два-представления-интерфейса"></a>

### Рабочий интерфейс

Главная `/` всегда открывает workspace, независимо от прежнего `placelens:interface:v1` и доступности storage. `useInterfacePreference` сохраняет совместимый интерфейс для существующих потребителей, но не читает/пишет предпочтение и не включает classic. Старую компоновку не удаляли рефакторингом.

`PlaceLayout` на всех четырёх страницах содержит бренд со ссылкой на `/` и город, без переключателя версий, предварительной пометки и отдельной навигации. Прямые `/compare`, `/trips`, `/address/:id` сохраняют содержимое и ссылки без редиректов.

HomePage нового интерфейса после G3.4: класс `home-v2` включает каркас на всю доступную площадь, компактный ввод слева, карту справа и результаты под ней. `Teleport` перемещает единственный `TransportResults` между прежним местом и постоянной областью результатов, сохраняя `PointAddressLabel`, запрос и раскрытия. `AddressPicker` и `CityMap` тоже остаются единственными экземплярами. На телефоне сравнение, карта и настройки переключаются без размонтирования; HomePage сохраняет их позиции прокрутки. Desktop-результаты можно развернуть/свернуть кнопкой, в том числе для самостоятельного сценария без адресов; минимальная высота карты сохраняет её zoom-кнопки на коротком экране. Подробный сценарий — [point-analysis](features/point-analysis.md).

На новой главной `useHomeWorkspace` единолично владеет А/Б, общим радиусом, активной стороной и контекстом. Он переиспользует один `useAddressComparison`: `HomeAddressResults` показывает один профиль при одном выбранном ID и существующие парные строки при двух; отдельного запроса карточки нет. `useTransportAnalysis` остаётся транспортом анализа произвольной точки; его радиус синхронизируется owner и наружу не имеет отдельного setter. Профили и точка сохраняются при смене контекста. `AddressPicker` один, с сохранением черновика, `CityMap` один. Root query/history обслуживают `homeSelection` и единственный `useHomeLocation`; HomePage передаёт ему оба callback поездок и выбор пространства. URL прежних страниц не менялись.

`useHomeTrips` создаётся один раз рядом с `useHomeWorkspace`, вне условий представления: существующие `useComparisonTrips` и `useTripsState` владеют раздельными черновиками, общим режимом и своими результатами. `HomeTripsPanel` остаётся смонтированной при смене раздела. Второго загрузчика профилей нет. `HomeWorkspaceMap` оборачивает единственный CityMap; контекст, стабильный ID цели, endpoint и исходный sequence сопровождают выбор улицы. `homeStandaloneTrip` связывает самостоятельную цель с объектом черновика, независимо от индекса ответа. Разделение owner, props/events/expose — `types/homeWorkspace.ts`.

G4.1: `HomeTripsEditor` отображает режим, до трёх целей и явный запуск; `HomeTripsPanel` связывает его действия с теми же владельцами и отображает результаты/уточнения/повторы. Единственный редактор перемещается через `Teleport` в постоянный `#home-trip-editor` слева, при возврате к прежнему виду остаётся в панели. Поиск и раскрытые редакторы точек не пересоздаются. Левый ввод прокручивается отдельно, кнопка «Рассчитать поездки от адресов» сопровождается сводкой режима, числа доступных адресов и целей. Радиус подписан как радиус окружения. Подробные значения поездок находятся только в области результатов справа под картой.

Сценарии «Адреса / Отдельная поездка / Остановки» выбирают существующие операции и сохраняют раздельный ввод. В «Адресах» редактор общих целей доступен и при чтении окружения; явный запуск открывает результаты поездок. Восстановленный сценарий показывается без дополнительного запуска. Golos Text поставляется локально из `resources/fonts/golos-text` вместе с OFL, применяется только к новой главной через `resources/css/home-workspace.css`. А обозначен фиолетовым кругом, Б — синим квадратом в редакторе; числа нейтральны. Личные ориентиры подключены отдельным G4.2a ниже. Единственная карта сохраняет свои контракты; агрегация overlay описана в G4.3 ниже.

G4.2: `HomeAddressResults` владеет только представлением — одной навигацией результата, таблицей общих колонок, раскрытием всех метрик и данных. `HomeTripsPanel` публикует scoped slot `results` с `entries`, `actions`, `scenario`, сохраняя редактор и прежние обработчики. `HomeTripCell` отображает конкретную поездку, `HomeMetricCell` — показатель своей стороны; `HomeResultDialog` обслуживает подробности поездок/справки. Типы представления — `types/homeResults.ts`, короткие/полные объяснения окружения и метаданные — `utils/homeMetricPresentation.ts`. `HomePage.section` управляет четырьмя вкладками; таблица не создаёт loaders, не пишет историю и не вычисляет GIS. Контракт результата — [матрица](features/address-comparison.md#матрица-на-новой-главной--g42). Связь с общей картой описана в G4.3 ниже.

G4.2a: `useHomeOrientations` создаётся один раз в HomePage рядом с `useHomeTrips`, вне условий UI. Хранит только настройки в памяти; синхронно удаляет настройки удалённых/пересозданных целей по идентичности объекта, включая URL restore с повторившимся ID. `homeStandaloneTrip` сохраняет стабильную идентичность самостоятельных целей. `groups` — единый типизированный источник состояний `ready/loading/error/need/refinement/unknown`, отношения к ориентиру и общих шкал для таблицы, живого окна и будущей карты. Типы — `types/homeOrientations.ts`, чистое сравнение/валидация/масштаб — `utils/homeOrientation.ts`. Владельцы маршрутов/профилей только читаются; чтение не создаёт ячейки. `HomeOrientationButton` получает контекст через provide/inject, `HomeOrientationStatus` отображает готовую ячейку без новой формулы, `HomeOrientationDialog` управляет полем и точным возвратом фокуса. Акцент и единственное отложенное объявление принадлежат владельцу; новый расчёт снимает устаревший акцент. Контракт — [ориентиры](features/address-comparison.md#личные-ориентиры-на-новой-главной--g42a).

G4.3: `useHomeTrips.overview` готовит несколько `HomeTripMapInput` поверх тех же ячеек; каждый сохраняет собственные trip/mode/epoch и исходные координаты. `homeMapEntity` связывает отображаемую сущность с этим результатом, `homeMapOverview` собирает допустимые слои, маркеры и фильтр показа. `homeMapSignal` только переводит уже подготовленные `groups` в краткую подпись. Никакой формулы ориентиров или второго владельца результатов в карте нет. `HomeWorkspaceMap.overview` дополняет прежний `trip`; событие `entity(id)` проходит проверку текущего набора, context и версии обработчика. Кандидаты остаются только от выбранного `trip` с его исходным sequence. `CityMap` сохраняет единый canvas-click-dispatch; ручной выбор предшествует кандидатам/принятым путям. HTML-метки вызывают тот же проверяемый выбор сущности, не подписываются на MapLibre. Положение подписей — экранное, с учётом zoom/темы/legend/атрибуции; GIS не вычисляется.

HomePage владеет выбранной целью через context, `mapScope`, раскрытием и намерением камеры. `CityMap.automaticCamera=false` отключает только автоматические перемещения новой главной; прежние потребители сохраняют defaults. Явные `focusTrip/resetView/focusRequest` прежние. `HomeMapDetails` отображает существующие entries/actions; выбор стороны и «К строке» направляются в HomePage. Адрес возврата — JSON `HomeTripRef` в `data-home-trip`, дополнительно `data-goal-id/data-side`; `data-home-map-action` — запасная кнопка. Строка и ячейка отражают выбранную цель/сторону. Текущий контракт — [общая карта](features/home-workspace-map.md).

G4.4: HomePage хранит только UI экрана телефона, три позиции прокрутки и одноразовый возврат к стабильной ячейке; changeMobileView не меняет предметный контекст или history. DOM областей сохраняется, скрытые мобильные панели inert. homeDialogKey ограничивает Tab только внутри открытого модального окна. Поведение — [контракт навигации](features/home-workspace-map.md#мобильные-экраны-прокрутка-и-фокус--g44).

`useHomeLocation` пишет root query/fragment и обрабатывает popstate/hashchange с подавлением повторного restore и обратной записи. Обычная ссылка содержит адреса/радиус без личных сценариев; личная сохраняет раздельные `places` и `trip` в прежних версиях. Панель через свой changeScenario показывает восстановленный сценарий без повторного создания owner. Общие поездки восстанавливаются после профиля своей стороны; самостоятельное восстановление уже запускает проверку. Подробный контракт — [trips](features/trips.md#единое-пространство-на-главной).

HomePage владеет DOM-переходами и явным намерением камеры. `HomeWorkspaceMap` сообщает `ready`; раннее «Показать маршрут» ждёт этого события и отменяется при смене context/цели/mode/sequence. Обновление overlay, тема, слой и resize не вызывают focusTrip. Программное выделение объекта передаётся через focus с ID; selectedObject хранит результат выбора. `standaloneEffects.beginRun` проверяет isCurrent и эпоху взаимодействия до перехода к результату.

Постоянные страницы `/address/:id`, `/compare`, `/trips` сохраняют содержимое и ссылки. Стили нового экрана ограничены классами `workspace-interface` / `home-v2`; нового router или хранилища предметного состояния нет.

### Аналитическое состояние

Смена адреса/радиуса очищает устаревший анализ, запросы отменяются, identity/sequence/epoch не дают позднему ответу восстановить прежний выбор. Ошибка стороны/блока не скрывает независимые результаты. В сравнении проверяется ID/радиус ответа; ячейки поездок сверяются с исходными точками.

URL хранит согласованный выбор, не исторические данные. Профиль/сравнение используют search и history; личные точки — fragment с отдельным предупреждением. Переименование цели не удаляет маршрут, смена геометрии инвалидирует зависимые результаты. Подробный контракт — [trips](features/trips.md), [сравнение](features/address-comparison.md), [точка](features/point-analysis.md).

`metricDisplay` форматирует число/дату, не вычисляет GIS. `profilePresentation`/`comparisonPresentation` и facts применяют правила показа/сопоставимости. Неизвестная дата не становится датой импорта, null — нулём; выбранные темы не скрывают отсутствие данных у показанной строки.

`useTripsState` использует единственные refs результата из `useTripAnalysis`, без второй копии analysis. Его синхронный watcher координат/идентичности цели сохраняет независимые строки и перенумеровывает diagnostics/candidates; переименование не считается геометрической правкой. `useTripAnalysis` отвечает за fetch, timeout, abort и защиту записи response. Epoch в useTripsState защищает продолжение после await: принятие road hints/candidates, запись истории и отложенное раскрытие предупреждения. На unmount транспорт отменяется, epoch становится недействительным.

Страница передаёт `saveSelection(value, push/replace)` и `beginRun(reveal)`: последний возвращает DOM-обработчик завершения с проверкой актуальности, захватив время/пользовательское взаимодействие. Восстановление URL и согласование popstate/hashchange остаются странице; composable получает уже разобранный выбор через `restore`. Формат ссылок и алгоритмы расчёта не менялись.

## Карты и адаптивность

CityMap владеет единственным MapLibre, его жизненным циклом, общим click-dispatch и камерой, а также слоями окружения и адресов. `utils/tripOverlay` устанавливает, обновляет и очищает только маршрутный source/layers и обрабатывает дорожные варианты/ручной выбор через этот dispatch. Он получает getter готового GeoJSON, не хранит результаты/epochs поездок, не подписывается на события карты и не вызывает fitBounds. ComparePage готовит GeoJSON через прежний tripMapData: сопоставляет сторону/цель/request-local index, задаёт подписи и обрабатывает событие дорожного выбора своей поездки. TripMap обслуживает самостоятельный /trips без изменения сценария; обе карты используют единственный installTripLayers. Маркеры сравнения — GeoJSON-слои; DOM-маркеры кандидатов самостоятельного TripMap остаются его ответственностью.

Явный показ маршрута поступает в прежний focusTrip CityMap; его selectionSequence общий с выделением/сбросом. Смена/скрытие overlay и unmount отменяют отложенную подгонку. Тема, меню, наведение, фокус и resize не создают новую команду камеры. Повтор подложки устанавливает маршрутные слои идемпотентно и берёт актуальный GeoJSON без подгонки; cleanup удаляет только собственные ресурсы overlay перед удалением общей карты.

MapLayersPanel/MapLayerDetails и Stop/Area/LinearLayerInfo управляют флажками и сведениями, а не HTTP/камерой. Флажки сравнения общие для двух карт, центры независимы, масштаб/ориентация согласованы. Парки, растительность и вода имеют независимые категории.

useMapTheme/mapTheme и MapThemeControl меняют paint без замены аналитических источников/камеры. Адресные подписи AddressMapLabels/mapLabels сохраняют геометрию и разводят экранные метки. Ближайший объект выделяется только при наличии соответствующего ID в геометрии слоя; иначе доступен переход к категории.

Подложка/glyphs требуют сети; worker собирается локально, sprite-ресурсы с происхождением/лицензией лежат в public/maps/osm-openmaptiles. Значки остановок подложки скрыты, чтобы не смешивать OSM с официальным набором. Декоративные POI подложки не становятся данными аналитического API. При отказе карты локальный результат остаётся доступен; текст причины и кнопка повтора целиком помещаются в области карты, включая телефон и короткий экран. Повтор подложки сохраняет локальную геометрию и камеру без повторного аналитического запроса.

На главной мобильная навигация выбирает одну из трёх областей. В профиле desktop-панель прокручивается независимо; колесо карты может передаваться панели, Ctrl/⌘ меняет масштаб. useSidebarWidth/SidebarResizeHandle используются главной/профилем. Сравнение имеет свой split и переключение А/Б на узком экране; вкладки/возврат сохраняют чтение и фокус. Детальные правила — в документах функций и dated-протоколах, не в копии CSS-порогов здесь.

## Стили и UI tooling

Tailwind CSS 4 подключён через Vite, shadcn-vue — components.json/reka-nova/neutral, CSS variables — app.css, cn.ts указан alias генератора. Базовый шрифт Instrument Sans подключается Vite fonts plugin. Существование tooling/dependency не означает, что все готовые UI-компоненты уже установлены или используются.

```bash
docker compose exec node npm run ui:add -- button
docker compose exec node npm run typecheck
```

Первая команда — пример генерации новых исходников, не проверка; выполнять только при потребности в компоненте, проверить CSS/source/lock. Работать в node от пользователя node. Карта имеет собственные темы, а CSS-вариант `.dark` сам по себе не означает готовый переключатель темы всего приложения.

Историческая запись предыдущей версии этой инструкции: первоначальный dependency audit не нашёл production-замечаний, а для dev CLI сообщил 15 замечаний (6 high, 9 moderate), без совместимого исправления; принудительное обновление не применялось. Это прошлое наблюдение, не результат актуального security audit. Перед обновлением tooling состояние проверяется заново отдельной задачей.
