# Структура фронтенда

Vue/TypeScript размещается внутри Laravel в `resources/js`. Стили находятся в `resources/css`, Blade-шаблоны — в `resources/views`.

```text
resources/
├── js/
│   ├── app.js          # точка входа Vite
│   ├── api/            # обращения к REST API Laravel
│   ├── components/     # переиспользуемые Vue-компоненты
│   │   └── ui/         # компоненты shadcn-vue
│   ├── layouts/        # общие каркасы страниц
│   ├── pages/          # компоненты страниц
│   ├── composables/    # переиспользуемая реактивная логика Vue
│   ├── types/          # общие TypeScript-типы и контракты API
│   └── utils/          # небольшие функции без состояния
│       └── cn.ts       # объединение CSS-классов
├── css/
│   └── app.css         # общие стили
└── views/
    └── welcome.blade.php
```

- `pages` собирают страницу из компонентов и используют общий layout.
- `components` содержат UI; компоненты конкретной страницы можно группировать в подпапку по функции по мере появления.
- `composables` содержат логику Vue, например состояние загрузки или поиска. Обычные функции форматирования относятся к `utils`.
- `api` отвечает за HTTP-запросы к Laravel. Компоненты не обращаются напрямую к внешним GIS-сервисам.
- `types` хранит общие контракты. Локальные типы остаются рядом с использующим их кодом.

Vue-компоненты именуются в PascalCase (`SearchInput.vue`), composables — с префиксом `use` (`useAddressSearch.ts`). Общие классы и стили остаются в `app.css`, локальные стили компонента — в его `.vue`-файле.

Приведённые имена — примеры соглашения, эти компоненты ещё не реализованы. Пока используется существующая точка входа `app.js`; новые модули пишутся на TypeScript, компоненты — с `<script setup lang="ts">`. Проверка типов настроена через `vue-tsc`, конфигурация — `tsconfig.json`. Алиас `@` указывает на `resources/js` и настроен одинаково для Vite и TypeScript. Используется TypeScript 6: установленный `vue-tsc` требует API JavaScript-компилятора, отсутствующий в TypeScript 7.

Пустые каталоги содержат `.gitkeep`, чтобы Git сохранял их. GIS-расчёты выполняются на backend/ETL; фронтенд отображает результаты. Подключение Vue к Blade, маршрутизация страниц и продуктовый интерфейс реализуются отдельным этапом.

## Tailwind CSS и shadcn-vue

Tailwind CSS 4 подключён через Vite. shadcn-vue инициализирован с нейтральной палитрой, CSS-переменными и стилем `reka-nova`. Конфигурация генератора — `components.json`, оформление — `resources/css/app.css`. Сохранён шрифт Instrument Sans, который Laravel/Vite подготавливает локально; импорт Google Fonts, добавленный генератором, удалён.

Светлая тема используется по умолчанию; класс `.dark` включает тёмные токены. Переключатель темы пока не реализован. Общий helper `cn()` в `resources/js/utils/cn.ts` объединяет условные классы и разрешает конфликты Tailwind.

CLI shadcn-vue установлен как dev dependency; версия зависимостей закреплена в `package-lock.json`. Компоненты добавляются по мере необходимости:

```bash
docker compose exec node npm run ui:add -- button
```

Команда добавит исходные файлы в `resources/js/components/ui/button` и необходимые зависимости. Это пример команды: компонент Button сейчас ещё не добавлен. Генерацию запускаем из Node-контейнера, затем просматриваем изменения в компонентах, стилях и lock-файле.

Проверки:

```bash
docker compose exec node npm run typecheck
docker compose exec node npm run build
```

Проверка типов также включена в CI. TypeScript-проверка и сборка не заменяют визуальную проверку будущих страниц.

Документация: [shadcn-vue](https://www.shadcn-vue.com/docs/installation/vite), [TypeScript 7 и совместимость инструментов](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/).

По результату проверки зависимостей при подключении: `npm audit --omit=dev` не обнаружил уязвимостей. Полный аудит сообщает 15 замечаний (6 high, 9 moderate) в зависимостях CLI разработки; совместимый `npm audit fix` их не устраняет. Принудительные изменения версий не применялись. Перед обновлением CLI следует повторить аудит.
