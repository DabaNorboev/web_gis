# Frontend PlaceLens

Визуальный ориентир UI — [макеты владельца и правила их применения](plans/place-analysis-ui-reference.md).

## Каталоги и соглашения

Vue/TypeScript отвечает за интерфейс; геометрия отбора и расстояния рассчитываются сервером. `resources/js/app.js` монтирует только `pages/PlaceAnalysisPage.vue`. Клиенты API находятся в `api/`, контракты — в `types/`, lifecycle запросов — в `composables/`, отображение — в `components/place-analysis/`.

## Загрузка и страницы

Единственный рабочий экран открывается на `/`. `/analysis`, `/search`, `/compare`, `/address/{id}` и `/trips` перенаправляются на `/` без переноса query-параметров и восстановления прежнего выбора. Redirect не создаёт сессию, использует no-store/no-referrer. Фрагменты URL не читаются клиентом. Старые страницы, их отдельные визуальные компоненты, search-оболочка и публичное демо удалены по решению владельца. Параметр `demo=1` ничего не включает.

<a id="демонстрационная-страница-анализа-analysis"></a>
### Основной экран анализа

`PlaceAnalysisPage` владеет адресом/точкой, радиусом 200–1000 м, вкладками, выбором POI и настройками слоёв. `types/placeAnalysis.ts` / `api/placeAnalysis.ts` проверяют контракт и эхо; `usePlaceAnalysis` обеспечивает независимые блоки, abort/epochs и повтор одного блока. [Контракт](features/place-analysis.md).

Адрес выбирается явно; группы зданий, этажность, hover/focus и предварительное кадрирование реализованы через [адресный поиск](features/address-search.md). Начальной метки нет. Карточка новой точки выше маркеров. [Адрес-ориентир](features/point-address.md#ориентир-точки-на-analysis) находится под кнопкой анализа; только отдельное действие переводит выбор в адресный.

Обзор содержит три независимые карточки с количествами и состояниями. Обновление значком повторяет блок; «Подробнее» открывает вкладку без запроса. Недоступные источники не получают синтетических объектов, изображений или измерений.

Вкладка объектов содержит фильтр «Все», значки категорий, номера строк, адрес и округлённые метры. Нажатие выделяет строку и маркер без раскрытия подробностей; клик по карте сохраняет «Все», иначе выбирает категорию POI. Источник/версия доступны отдельно под списком. Единый счётчик использует известные значения категорий и found_count остановок, при неизвестном компоненте показывает только количество отображённых строк. [Неизвестный полный итог остановок](data/transport-import.md#подпись-найденного-количества) не подменяется нулём.

<a id="спутниковые-слои-и-даты"></a>
### Спутниковые слои и даты

Во вкладке «Спутник» даты берутся из `available_dates` ответа А10.2. Без выбранной даты показывается каталог и явное «дата не выбрана»; каталог не считается готовым наблюдением. Выбор даты запрашивает только satellite, не перезапрашивая POI и воздух; смена места/радиуса инвалидирует прежний спутниковый результат. Пока новая дата загружается, старые растровые слои скрыты.

`true-color` и `ndvi` — два MapLibre raster source из выданных API descriptors, без расчёта GIS/NDVI и без подмены URL. Переключатель «Снимок/NDVI», видимость, порядок и непрозрачность входят в существующую панель слоёв и сохраняются при переключении вкладок. Ползунок «Непрозрачность» задаёт `raster-opacity`: 0% — слой невидим, 100% — полностью непрозрачен; значения, направление и сохранение настроек не меняются, слой не обрезается по кругу. У готового наблюдения рядом с показателем покрытия сказано, что слой показан на всей подготовленной территории, а показатели рассчитаны для выбранного круга; это пояснение не дублируется в панели слоёв. Средний NDVI подписан как среднее пригодных пикселей. В пользовательском тексте нет номеров zoom и объяснения внутренних запросов; сильное увеличение не добавляет деталей. Технически источник ограничен z10–13: выше MapLibre увеличивает доступные тайлы, но не обещает новую детализацию. Общая легенда берётся из `legend`; неизвестные пиксели прозрачны и не обозначаются как низкий NDVI. Покрытие показывает только переданные доли круга, а предупреждения выбранной даты (например, майский снег и ранняя фенология) и ограничения набора выводятся рядом с датой. Недоступные изображения, отказ PNG и ошибка блока показываются отдельно с повтором только satellite; аналитика круга при этом сохраняется.

## Состояние и побочные эффекты

<a id="два-представления-интерфейса"></a>
### Рабочий интерфейс

Второго runtime-интерфейса и переключателя версий нет. Настройки слоёв и выбранное место живут в памяти страницы. Хранение, обмен и восстановление после reload остаются открытым решением; прежние browser records не читаются, не мигрируются и не удаляются.

### Аналитическое состояние

Место/радиус инвалидируют все блоки. Выбор даты сразу запускает только satellite; выбор станций требует явного запуска и затрагивает только air. Поздние ответы и старые тайлы не становятся текущими. При смене радиуса прежний серверный контур остаётся с пометкой до нового ответа; при смене места удаляется. GIS в браузер не переносится.

## Карты и адаптивность

`PlaceAnalysisMap` владеет одним MapLibre, серверными кругом/bbox, полными геометриями POI, метками, адресным preview и растровыми слоями TCI/NDVI. Метка площадного объекта может лежать вне круга: отбор выполнен сервером по геометрии. Выделение не сдвигает якорь. Подложка/атрибуция и её тема сохраняются; порядок, видимость и непрозрачность слоёв не сбрасываются при переключении вкладок. Растровые слои используют `bounds`, `minzoom`/`maxzoom` из ответа API; ошибка загрузки тайлов показывается над картой с повтором. Свободная точка доступна с клавиатуры через значок на карте, Enter и Escape.

## Стили и UI tooling

Основные стили — `resources/css/place-analysis.css`, общие — `app.css`. Значки — Lucide. `MapThemeControl` и `useMapTheme` переиспользуются. Старые Home/Search CSS удалены; `components.json` не является отдельным публичным интерфейсом.

<a id="ядро-нового-поиска-п1"></a>
## Ядро поиска

Модули `resources/js/search/`, API clients и чистые утилиты прежних функций остаются библиотечным кодом без публичной визуальной оболочки. Их удаление или изменение серверных контрактов в перенос главного экрана не входит.

<a id="хранение-нового-поиска-п3"></a>
## Хранение поиска

Существующие storage/persistence codecs и их проверки сохранены; к новому экрану не подключены. Автоматической миграции или очистки IndexedDB/localStorage нет.

<a id="оболочка-нового-поиска-п41"></a>
## Оболочка поиска

Прежняя `search-ui/` удалена; `/search` — только совместимый redirect на текущую главную.

Typecheck, сохранённые headless/API/storage frontend tests, `PlaceAnalysisPageTest`, browser `place-analysis*.spec.mjs`. Синтетический browser-стенд собирает настоящий entry во временный каталог; рабочая HTTP-проверка отмечается отдельно. Тесты удалённых визуальных сценариев сняты, смешанные тесты сохраняют проверки API/состояния/приватности. А7/А8 не закрываются сменой главной страницы.
