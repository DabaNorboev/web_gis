## Исходное состояние и границы

До правок список неоднозначных кандидатов находился возле карты, после выбора
альтернативы исчезали. Снимок исходного дерева и копии затронутых компонентов
сохранены в `/tmp/placelens-trip-choice-nyx7s3cr/`; существующие незакоммиченные
изменения не откатывались. План проверки: два дорожных варианта, карта/список,
клавиатура, частичный успех, сброс при редактировании, fragment/history/reload,
desktop/mobile; настоящий provider/resolver/PostGIS/guard с fake HTTP.

Радиус 35 м, полоса неоднозначности 1 м, допуск source geometry 0,25 м, бюджет
кандидатов, автомобильный доступ, препятствия и границы не менялись. Пешая
маршрутизация, профиль скоростей, исходные геоданные и runtime вне этапа.

## Поведение

- `SNAP_CHOICE_REQUIRED` — синее немодальное ожидание: маршрут пока не рассчитан,
  нужно выбрать сторону/проезд. Отказы по доступу, ограде, отсутствию кандидата,
  пути, границе и недоступности сохраняют свои сообщения.
- В соответствующей карточке список с теми же индексами, что на карте. Каждый
  вариант показывает расстояние от исходной точки; название берётся только из
  `name` проверенной исходной дороги. У общего узла с разными названиями имя
  опускается. Назначение проезда не предполагается.
- Маркеры — кнопки с доступными подписями и `aria-pressed`. Hover/focus связывают
  подсветку списка и карты; последнее взаимодействие определяет подсветку,
  выбранный вариант остаётся зелёным с галочкой. Близкие значки разнесены только
  в пикселях с тонкими указателями к реальным позициям; координаты неизменны.
- Явный выбор передаётся провайдеру как прежний road hint и заново проходит
  resolver, обе привязки и GIS-защиту. До выбора этой пары HTTP к OSRM нет.
  Исходный маркер сохраняется, выбранная дорожная точка показана отдельно с
  пунктирным соединителем. Соединитель не включён в длину/время.
- Пока выбранный вариант проверяется, его старая линия/метрики очищены;
  соседняя успешная поездка остаётся видимой. Карта, форма и варианты доступны.
  Ответы после изменения исходной точки игнорируются; старый road hint, список
  и результат очищаются. Ошибочный сохранённый hint не помечает неоднозначный
  вариант выбранным.
- Ссылка использует прежний `#trip=` с исходной и дорожной точками; query не
  добавляется. Reload/back/forward заново проверяют выбор. В пределах текущего
  расчёта альтернативы остаются для переключения; ссылка сохраняет выбранную
  точку, а не кэш остальных кандидатов. После открытия она перепроверяется,
  прежние номера альтернатив не являются постоянными идентификаторами.

## Проверено

- Frontend: **78 тестов**, включая нейтральное сообщение, список именно в нужной
  карточке, экранирование имени, hover/focus без выбора/запроса, два явных выбора,
  частичный успех во время ожидания, fragment/history/reload, устаревший hint,
  сброс, неизменность координат при разнесении значков.
- PHP: **25 тестов / 140 assertions**, SQLite in-memory и fake HTTP.
- Routing GIS: **31 тест / 210 assertions**, `web_gis_test` с принудительным
  READ ONLY. Новый сквозной сценарий вызывает настоящий
  `LocalCarRouterProvider::analyze()` → `RoutingGeometryGuard::resolve()` с
  production SQL → fake OSRM → настоящий `review()`. Две синтетические стороны:
  до выбора `CHOOSE`, null route/метрики и ноль HTTP; каждый явный выбор даёт
  `AVAILABLE` с нужным концом. Добавлена проверка отсутствия спорного имени на
  общем узле. Прежние private gate/короткое private edge/стена/граница/обе
  привязки/отсутствие кандидата продолжают проходить.
- TypeScript, `git diff --check` и Vite build во временной копии успешны.
  Vite по-прежнему предупреждает о большом JS chunk; assets проекта не обновлялись.
- Chrome, отдельный preview с заменённым синтетическим API и отключёнными
  request logs: обе кнопки списка, оба маркера карты, Enter в списке/на маркере,
  Tab и синхронная подсветка, выбранное состояние, успешная соседняя поездка во
  время повторного расчёта, изменение исходной точки, прямая fragment-ссылка,
  reload/back/forward. Ширины 1280, 390 и 320 px: переполнения страницы и
