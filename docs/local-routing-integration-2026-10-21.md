## Этап 5: ожидаемый результат и проверки до реализации

Основание — Go для OSRM car из `local-routing-decision-2026-10-21.md`.
Реализовать отдельные закрытый router и Laravel provider, неизменяемый локальный
runtime-снимок из уже подготовленного графа/PBF, проверку обеих привязок и
геометрии, ограниченные запросы/таймауты, независимые результаты пар без fallback.
Не менять схему БД, .env, raw, поиск, адресное сравнение и радиусные расчёты.

Пользовательский результат: отдельная страница поездок без регистрации;
исходная стартовая точка и до трёх важных мест, автомобильный режим, реальные
расстояние/оценка времени только для принятых путей. Карта сохраняет исходные
маркеры, показывает фактические концы принятой линии и пояснение привязок;
сомнительные точки требуют явного уточнения. Ссылка сохраняет выбранные точки,
перезагрузка и back/forward работают. Пеший режим, общественный транспорт и
сплошная область поиска не добавляются.

Проверки этапа: unit/feature-контракты провайдера, некорректные/большие запросы,
изолированные частичные отказы, подготовка guard-данных и их SHA, отсутствие
публичного порта, typecheck и сборка в отдельный каталог. Проверить рабочий
сценарий с несколькими местами до объявления этапа завершённым.

## Что подключено и где проходит граница

- Отдельные `LocalCarRouterProvider`, `RoutingSnapshot`, `RoutingGeometryGuard`;
  действующие профиль, сравнение, поиск и радиусы не используют router.
- `POST /api/v1/trips/analyze`: `mode: driving`, `start: {lon,lat}`,
  `places: [{lon,lat,label?}]`, 1–3 цели. Тело максимум 8192 байта, label до
  80 символов, отдельный throttle 30 запросов/мин. Некорректный запрос — 422,
  слишком большой — 413. Координаты передаются в EPSG:4326, `lon,lat`.
- Пары рассчитываются независимо, без batch-ошибки, стирающей успехи.
  Возможны `AVAILABLE`, `NEEDS_REFINEMENT`, `NO_PATH`, `UNKNOWN`,
  `UNAVAILABLE`, `OUTSIDE_PILOT`. Только `AVAILABLE` содержит route и значения
  расстояния/времени. У остальных route/value/method — null; нулей и прямого
  fallback нет. Неизвестный ответ не объявляется доказанным отсутствием пути.
- URL `/trips#trip=<JSON>` хранит версию 1, режим, исходные координаты и
  пользовательские названия, без округления и адресных ID. Повторное открытие
  пересчитывает выбор по текущему закреплённому снимку; ссылка не архивирует
  прежний результат. Некорректная ссылка даёт явное сообщение и пустую форму.
  Личные названия/координаты входят во фрагмент ссылки, который не передаётся
  серверу при загрузке страницы. Получатель ссылки увидит эти данные. Старый
  query-формат преобразуется через replaceState; его первоначальный HTTP-запрос
  уже содержит query, поэтому серверное журналирование отдельно обезличено.
  Методика доступа и проверки после независимого аудита —
  [исправления приватности и доступа](local-routing-privacy-access-fixes-2026-10-21.md).
- Оба фактических конца GeoJSON сравниваются с исходными точками, независимо
  проверяется смещение до 35 м. Echoed waypoint-координаты не являются
  доказательством. Даже короткий подход проверяется против известных зданий,
  воды, стен и другой стороны дороги. Исходные точки остаются на карте и в ответе.
  Расчёт между дорожными концами не включает нерассчитанный подход.
- На линии проверяются известные препятствия, indoor, доступ с приоритетом
  `motorcar → motor_vehicle → vehicle → access`, направление исходных рёбер,
  conditional-теги и пересечения железной дороги с учётом layer/bridge/tunnel.
  Неподтверждённый доступ, исходное ребро или уровень означает отказ от показа.
  Эти проверки ограничены полнотой OSM и подготовленных препятствий: разрешение
  въезда, все поворотные ограничения, входы и парковка независимо не подтверждены.
- Граф извлечён в bbox `[92.70,55.90,93.20,56.20]` с полными ways. Допустимая
  область запросов — пересечение подготовленной service geometry с bbox,
  уменьшенным на **1000 м** в EPSG:32646. Проверяются обе точки до HTTP,
  полная принятая линия также должна остаться внутри. Это защитный запас,
  не доказательство оптимальности маршрутов, которые могли бы уходить за пилот.
- Набор `osrm-car-20261021-v1`; наблюдение `observed_at:null`, freshness UNKNOWN.
  Подготовка/расчёт не подменяют дату наблюдения. Метрики DERIVED при успехе,
  качество/причина независимы от доступности. `dataset_import_id:null`, поскольку
  граф не импортируется в рабочую БД; отдельно передаётся версия runtime и
  происхождение guard-наборов с их import ID/хешами.
- Нет бессрочного кэша результатов; HTTP `Cache-Control: no-store`.
  Статическая оценка не учитывает актуальные пробки, парковку, ожидание и
  расписания. Автопривязка не подтверждает фактический вход или доступ.
  Подложка остаётся внешней картографией; аналитика работает локально.

## Ограничения ресурсов и изоляция

`docker-compose.routing.yml` дополняет основной Compose: пятый, только
опциональный сервис `local-router`. Основной файл и `.env` не изменены.
Router подключён только к сети `routing` с `internal:true`, портов хоста нет;
из приложения к нему обращается PHP по фиксированному hostname. Корневая ФС,
данные и startup script read-only, capabilities сняты, no-new-privileges.
2 CPU, один worker, RAM 1 GiB, swap запрещён. Проверено на работающем
контейнере: `runtime-isolation.json`, здоровье healthy, в сети только PHP/router.

Provider: connect timeout 0,5 с, полный запрос 1,5 с, максимум ответа 1 MB,
без редиректов/сжатия и выбора внешнего URL. Линия до 10 000 точек, до 40 км,
annotations до 30 000 узлов. Ограничены также поток чтения/декодирование ответа.
Отдельные read-only SQL-транзакции имеют statement_timeout 1500 мс.
Guard-загрузка ограничена 2000 ячейками, 12 MB сырого JSON, 50 000 features,
8 MB на tile и оценкой доступной PHP-памяти; недостающий/изменённый файл — UNKNOWN,
не «препятствий нет». Проверено при PHP memory_limit=128M.
Общий клиентский deadline 20 с, ввод отменяет запрос и очищает старые линии.

Startup проверяет закреплённые SHA manifest, списка графа и всех его файлов;
provider проверяет manifest и каждую прочитанную guard-ячейку. В OSRM 5.27.1
минимальное допустимое `max-viaroute-size` и `max-matching-size` — 3;
provider при этом отправляет только пары. Table limit 16 не является публичным
матричным API приложения. OSRM работает с verbosity WARNING без координатных
query-логов.

```bash
docker compose -f docker-compose.yml -f docker-compose.routing.yml up -d --no-build --wait --wait-timeout 30 php local-router
```

Для точного повторения подготовки использовать сохранённые
`data/reports/local-routing-2026-10-21/` и
`data/reports/local-routing-integration-2026-10-21/guard-export/`.
`scripts/prepare-routing-runtime.py` — стандартная библиотека Python 3.12,
без сети/БД, проверяет входные хеши и отказывается писать в существующий каталог:

```bash
python3 scripts/prepare-routing-runtime.py \
  --guards data/reports/local-routing-integration-2026-10-21/guard-export \
  --output /tmp/placelens-routing-new-replay \
  --prepared-at 2026-10-20T17:46:49.033379+00:00
```

Python должен быть в подходящем ETL-контейнере; здесь команда показывает
аргументы для уже доступного runtime, установка на хост не требуется.
Побайтовое совпадение SHA подтверждено отдельно на Python 3.12-slim с
network=none/read-only (`runtime-replay-python312.json`). Рабочий каталог
при повторении не перезаписывать. `export-routing-guards.php` предназначен
только для явно нового snapshot: требует PGOPTIONS read-only и нового output,
а не выполняется на каждом HTTP-запросе. Обновление данных — отдельная проверка.
