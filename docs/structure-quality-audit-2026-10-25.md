# Аудит структуры и качества PlaceLens перед выборочной очисткой

Исследование: 24–25 октября 2026 года. Только чтение и план; единственное изменение — этот отчёт. Ссылки на строки относятся к исследованному рабочему дереву, а не только к HEAD.

## Десять наиболее полезных находок

1. **F01 — проверка приватности Nginx существует, но не входит в CI.** PHP-тесты и browser smoke не проверяют фактическую обработку журналов и тела запроса самим Nginx. Это пробел автоматической защиты, не доказанная утечка.
2. **F02 — диагностический скрипт может перезаписать исторические свидетельства.** `verify-trips-runtime.py` пишет результаты в фиксированный каталог прошлого задания без отказа при существующем файле.
3. **F03 — есть три старых UI-компонента вне графа приложения.** Два прежних переключателя слоёв не имеют потребителей; `MetricCard` живёт в отдельном тесте и документации. Последний нельзя удалить вместе с полезными проверками качества данных.
4. **F04 — тестовая инфраструктура дублирует преобразование модулей.** Общий загрузчик SFC уже существует, но параллельно работают несколько загрузчиков на регулярных выражениях. Устранять стоит дублирование инфраструктуры, сохраняя сценарии.
5. **F05 — состояние самостоятельных поездок слишком сильно связано со страницей.** В `TripsPage` сосредоточены сохранение независимых результатов, перенумерация, дорожные кандидаты, история, отмена и управление фокусом. Простое изменение формы требует учитывать несколько систем инвалидации.
6. **F06 — общая карта знает частный сценарий поездок сравнения.** `CityMap` объединяет окружение, адресный поиск и маршрутные overlays с обозначениями А/Б. Именно несвязанные обязанности, а не 488 строк сами по себе, повышают стоимость изменений.
7. **F07 — жизненный цикл импортов повторяется.** Особенно близки area/linear importers: блокировка, журнал, транзакция, публикация, завершение и освобождение блокировки. Общую часть можно выделять постепенно; геометрию и правила наборов объединять не требуется.
8. **F08 — документы смешивают текущие правила и историю реализации.** Например, описание frontend всё ещё называет `MetricCard` общей карточкой, а старый отчёт сообщает об уже исправленном сбое теста. Читателю трудно определить действующий контракт.
9. **F09 — общий контракт качества продублирован и привязан к транспорту.** `TransportMetric` и `MetricResult` повторяют основу; поездки получают её через `Omit<TransportMetric, ...>`. Изменение общего контракта приходится согласовывать в нескольких местах.
10. **F10 — ECharts не имеет подтверждённого потребителя.** Он установлен как production dependency, но графиков и импортов не найдено. У других внешне неиспользуемых UI-пакетов есть связь с генератором shadcn, поэтому удалять их одним списком нельзя.

Критических дефектов доступа или доказанной потери пользовательского состояния исследование не установило. Основная часть замечаний — сопровождаемость и сохранность проверок/исследовательских материалов. Десять находок не означают десять аварийных проблем.

## Состояние проекта и сохранность

Архитектура соответствует текущему продукту: локальная аналитика в Laravel/PostGIS, отдельная офлайн-подготовка, Vue для главной, профиля, сравнения и автомобильного пилота. Оснований переписывать приложение, вводить микросервисы, общий state manager или отдельный SPA router по результатам аудита нет.

**Самый важный риск очистки — большое незавершённое рабочее дерево.** Ветка `feature/transport-stops-import`, HEAD `7e8a39a5d340efc6ffecfb291c020d2d23b856f5`. В индексе 106 tracked-путей; 34 tracked-файла имеют unstaged-изменения, включая одно удаление. Staged-изменений нет. Ещё 298 untracked-файлов до создания отчёта. Из них 47 в `app`, 68 в `resources`, 67 в `tests`, 47 в `docs`, 42 в `experiments`; это существенная часть работающей системы.

Удалённый в рабочем дереве `app/Services/Transport/Import/GeoJsonBoundary.php` заменён общим `app/Services/Gis/GeoJsonBoundary.php`. Это уже существующая незавершённая переработка, а не приглашение восстанавливать старую реализацию или удалять новую.

Файла `AGENTS.md` в этом проекте не обнаружено; применены инструкции, переданные пользователем в чате. Изучены README, PROJECT, описание frontend, схема данных, документы поиска/профиля/сравнения, покрытия, GIS-методики, маршрутизации, браузерных проверок и README экспериментов. PROJECT — ignored-файл, а не воспроизводимая часть checkout.

Содержимое `.env`, ключей, рабочих журналов и сохранённых личных ссылок не читалось. Геоданные, графы, архивы, assets и зависимости не разбирались рекурсивно по содержимому. Для крупных деревьев использованы размеры и верхние уровни. Никакие импорты, миграции, HTTP-запросы приложения, реальные поездки, установки, перезапуски, сборки, очистки кэшей и операции изменения Git не выполнялись.

После прерывания повторно сверены ветка, HEAD, Git-статусы и ключевые участки; видимое состояние совпало с ранее исследованным. Временная контрольная ведомость исходников создана вне рабочего дерева. Завершающая сверка подтвердила: 361 исследованный существующий исходный/конфигурационный файл и индекс Git не изменены; единственное добавление к исходному Git-статусу — этот отчёт.

Механизмы генерации:

- Миграции задают схему, generated search/green flags рассчитываются PostgreSQL; поисковый снимок перестраивается функцией БД и импортом до публикации. Эти определения нельзя заменить удалением «дублирующего» SQL.
- `scripts/prepare-osm-linear.py`, `prepare-osm-areas.py` создают производные данные из сохранённого PBF; importers публикуют локальные снимки. В HTTP тяжёлая подготовка не перенесена.
- `scripts/prepare-routing-runtime.py` читает summary/graph/context из исследовательского отчёта и экспорт guards, создаёт отдельный выпуск graph/guards/manifest. Параметр времени подготовки предусмотрен для повторения тех же байтов. Сам факт наличия скрипта не гарантирует повторение выпуска без сохранённых входов.
- `public/build` и manifest создаёт Vite. Проверен небольшой manifest: CSS/app entry и три literal dynamic imports страниц profile/compare/trips совпадают с `app.js`. Содержимое assets не анализировалось; идентичность опубликованных bundles текущим исходникам не доказана.
- Blade view cache, package/service cache, PHPUnit cache, Python bytecode и Playwright outputs генерируются framework/инструментами. Их роль отличается от исходников. Browser server собирает свой frontend в системный временный каталог, но полный Playwright пишет отчёт и test-results в проект, поэтому здесь не запускался.
- shadcn CLI генерирует исходники по `components.json`; `cn.ts` указан в alias генератора, хотя сейчас не достижим из `app.js`. Это заготовка инструментария, а не автоматически мёртвая функция.

## Проверка связей кандидатов

Проверен не только текстовый поиск. Для frontend построен граф относительных и alias imports, включая literal dynamic imports, от `app.js`; сверены маршруты Laravel, Blade/Vite entry points и небольшой опубликованный manifest. Глобальной регистрации UI-компонентов или `import.meta.glob`, подключающего старые controls, в исследованных точках загрузки не выявлено. ### D. Сохранить и лучше документировать

- **Routing runtime и его входы.** `data/prepared/local-routing/...` непосредственно смонтирован в OSRM, а `RoutingSnapshot` читает manifest/guards. `config/routing.php`, `docker/routing/start.sh` и compose закрепляют совместимый выпуск. Дублирование hash pins здесь служит независимой проверке; заменять доверенный pin хешем из того же изменяемого файла нельзя.
- **Часть `data/reports` — не только результаты.** `prepare-routing-runtime.py:32–53` читает `summary.json`, `osrm-driving/*`, `prepared/context.json`, `extract-manifest.json`; `audit-admissions.php:22–26` читает старый PHP guard. Эти связи доказаны исходниками без чтения геоданных/архивов.
- **Приватность в нескольких слоях.** Nginx safe log format, PHP исключения без входа, POST/no-store/no-referrer, fragment вместо query, request limits и тесты проверяют разные границы. Не объединять их в одну «общую» проверку.
- **PostGIS safety infrastructure.** `PostgisDatabase`, `PostgisTestCase`, отдельная конфигурация и read-only/write suites — защита от обращения к рабочей БД. Её объём оправдан.
- **Геометрические отрицательные контроли и исторические клики.** Они закрепляют ограничения доступа, мостов/стен/воды/направлений. Похожие точки не являются дубликатами теста без сравнения ожидаемых причин отказа.
- **Снимки импорта, исходные данные, миграции, индексы.** История не равна лишней версии кода; удаление требует отдельной политики retention и отката.
- **`public/maps`, опубликованный build и прежние assets.** У ресурсов есть runtime-потребители, manifest не описывает все возможные старые вкладки браузера. Для удаления прошлых assets нужна отдельная release/retention-политика.
- **Рабочая инфраструктура Laravel.** `User`, factory/seeder, users/cache/jobs migrations, auth/session/queue config не используются как готовый аккаунт PlaceLens, но имеют framework/convention consumers. Наличие будущих Stage 21–22 не даёт права удалять схему.

## Устройство кода: что уже нормально

- Контроллеры делегируют FormRequest и сервисам; SQL/GIS не попал в Blade/Vue. Query builder и предметный SQL сосредоточены в сервисах; отдельный repository layer для каждого запроса сейчас добавит обёртки без очевидной пользы.
- `AddressProfileService` фиксирует ID активных импортов одним чтением; блоки и display geometry изолированы transaction/savepoint и могут отказать независимо. Не превращать это в один неразделимый расчёт ради сокращения кода.
- `DatasetCoverage`, `AnalysisArea`, OSM enum-предикаты, source reader и route guard имеют понятные обязанности. SQL identifiers приходят из ограниченных enum; routing SQL вынесен рядом с guard и реально читается через `file_get_contents`.
- Страницы, composables, API, типы и чистые presentation utils разделены. Профиль и сравнение используют один API профиля, сравнение не изобретает новые GIS-метрики. DTO адаптеры и отдельная карта поездок оправданы различием взаимодействий.
- Сетевые composables очищают устаревший результат, используют отмену и дополнительные identity/sequence guards. В сравнении проверяется соответствие ID/радиуса; у route matrix — соответствие исходных точек. Сам AbortController не заменяет эти guards.
- Ноль, null, неизвестное покрытие, stale/unknown, ошибка блока и недоступный источник представлены раздельно. Formatter сохраняет малые положительные значения; union площадей/линий не заменён суммой.
- UI не вычисляет GIS или субъективный итоговый рейтинг. `comparisonFacts` проверяет сопоставимость данных перед текстовым выводом; это полезная предметная логика, не лишняя абстракция.
- В построенных графах literal JS imports и PHP `use App` циклов не обнаружено. Ограничение: контейнер DI, динамические имена, SQL functions и косвенные runtime-связи полностью таким графом не покрываются.
- Простая маршрутизация через серверные страницы и literal dynamic imports разумна для четырёх страниц. Замена на router/Pinia не обоснована текущим аудитом.

Размеры ключевых файлов: TripsPage 546 строк, CityMap 488, ComparePage 421, LocalCarRouterProvider 271, RoutingGeometryGuard 239; importers около 183–221. Эти размеры используются только для выбора участков чтения. Routing provider/guard имеют значительный объём оправданных отрицательных проверок; дробить их по произвольному лимиту строк не предлагается. Часть CSS сжата в длинные строки, поэтому число строк также недооценивает объём UI; форматирование вне задания.

## Тесты и инструменты

| Уровень | Что фактически проверяет | Вывод |
|---|---|---|
| PHP unit/feature | Настоящие сервисы/HTTP, валидация, приватность исключений/ответов, синтетический provider через Http fake | Mocks ограничивают сеть/БД; это не доказательство работы настоящего маршрутизатора, но полезная проверка контрактов |
| PostGIS integration | Метры, coverage, геометрия, атомарность импортов, миграции в тестовой схеме, guards и snaps | Общая safety-инфраструктура оправдана; не объединять с SQLite и не запускать против рабочей БД |
| Frontend Node/SFC | Настоящие composables/чистые функции и отрендеренные компоненты, управляемые pending replies | Код бизнес-алгоритма обычно исполняется из исходников, не копируется. Основная проблема — F04; тест старой MetricCard надо перенаправить по F03 |
| Browser smoke | Настоящие Vue/MapLibre/DOM, viewport/клавиатура/фокус/история, синтетические API и offline basemap | Один server/fixtures/support, а не множество равнозначных серверов. Не заменяет Laravel, реальный GIS/OSRM или физический телефон |
| ETL fixtures | Настоящие preparation scripts на маленьких PBF | Полезно, не дублирует runtime integration |
| Nginx privacy | Настоящий отдельный процесс с production config и synthetic canary, без живых журналов | Отдельная граница защиты; F01 |
| Исследовательские acceptance | Реальные provider/графы и исторические controls, ресурсные/геометрические ограничения | Не автоматический CI unit suite. Сохранять источники и запускать отдельно по задаче |

Увиденные `assert.match` часто проверяют **отрендеренный HTML и сообщения**, а не исходный текст компонента. Проверки DOM/ARIA и явного объяснения недостатка данных полезны; не заменять их все snapshots. Зависимость от точного CSS class/markup, количества карточек и compiler output есть в SSR-стендах; при переносе loaders сохранять поведенческое намерение, не механически старую разметку.

Вручную написанные browser fixtures не копируют GIS-алгоритм: они задают контракты/ошибки/задержки. Опасность — принять их за подтверждение реальных источников; docs уже описывают эту границу. Geometry/access/privacy/late-response/history suites сокращать по размеру нельзя.

**Исторический сбой не считается действующим.** `profile-map-workspace-2026-10-23.md` описывает падение собственного loader у transport-coverage. В текущем `tests/frontend/transport-coverage.test.mjs:6–15` уже используется общий loadComponent с PointAddressLabel. Аудит не объявляет этот тест сломанным; сегодняшнее полное прохождение также не заявляется.

Фактически выполнены только неисполняющие приложение проверки:

| Проверка | Результат | Граница |
|---|---|---|
| PHP `php -n -l` | 134 исходных PHP-файла, 0 синтаксических ошибок | Без bootstrap, зависимостей и БД; не проверяет семантику PHP 8.4/Laravel |
| Python `ast.parse` | 25 Python-файлов, 0 синтаксических ошибок | Без import, pycache, ETL и сетевых вызовов |
| Node `--check` | 44 JS/MJS-файла, 0 синтаксических ошибок | Без module execution, Vue/TS typecheck и browser |
| Статические графы и references | 4 frontend-файла вне entry graph: три компонента F03 и cn tooling; literal import cycles не найдены | Не заменяет сборку/динамическое наблюдение |

Перед отказом от запуска изучены scripts. `composer test` и `test:postgis` вызывают `artisan config:clear`; build изменяет assets; Playwright пишет отчёты, несмотря на временную сборку. Эти команды не запускались. Typecheck, frontend tests, PHPUnit, Pint и application/browser smoke в этом аудите не запускались; результатов прежних отчётов недостаточно для утверждения, что сейчас всё зелёное. Установки, dependency audit по сети и исследование CVE не выполнялись.

## Пробелы исследования

1. Рабочая БД не опрашивалась: активные импорты, покрытие и число объектов из docs — исторические сведения, не актуальная инвентаризация БД.
2. Не анализировались содержимое больших reports/archive, живые логи, личные fragment-ссылки, графы и массивы геоданных. Порядок retention и точный список дубликатов внутри них остаются отдельной задачей.
3. Не проверены свежая установка из lock, реальный запуск в контейнерах, точность опубликованного build относительно source и сторонние runtime-consumers. Уверенность удаления зависимостей поэтому ниже уверенности отсутствия их импортов.
4. Базовый статический граф не разрешает произвольные динамические имена, package internals и все Laravel conventions. Неиспользуемость не установлена для всего framework scaffolding.
5. Не проводился полный security audit или доказательство отсутствия утечек/ошибок доступа. Подтверждён только пробел включения существующей Nginx-регрессии в CI.
6. Пользовательская полезность сравнения, новые POI, воздух, аккаунт, входы/доступ и будущие маршруты не оценивались и не добавлялись в план очистки.

## Последовательные небольшие Goals для отдельных заданий

Это предложения, не созданные активные Goals и не разрешение выполнять изменения сейчас. Перед каждым заданием повторять Git-статус и сохранять обратимость относящихся к нему U-файлов; не включать постороннюю незавершённую работу.

### G01. Удалить только бесспорные старые controls и пустой unit example

- **Границы:** два `components/map/*LayerControls.vue` из A01/A02, `tests/Unit/ExampleTest.php`, относящаяся к текущему состоянию строка docs; не трогать MetricCard, карты, данные, зависимости и framework Feature/ExampleTest.

- **Готовность:** действующие страницы используют MapLayersPanel; нет живых ссылок на снятые controls; удалён только assertion, не проверявший приложение.
- **Проверки:** статические imports/строки/loaders, typecheck, frontend tests; слои профиля/сравнения и smoke главной. Риск низкий, объём небольшой.

### G02. Установить навигацию по текущим контрактам и историческим отчётам

- **Границы:** README, frontend-structure, browser-smoke, address-comparison, короткий docs index; существующие инструкции не переписывать без отдельного указания. PROJECT не превращать автоматически в tracked-файл.

Лучше выполнить двумя независимыми подзаданиями:
