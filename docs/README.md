## Как вести документацию

1. Описывать актуальное состояние и ограничения. У каждого правила одно основное место; в остальных документах — ссылка.
2. Текущее поведение — в `features`, устройство — в архитектуре/схеме/frontend, запуск и подготовка — в runbook и `data`. Будущий контракт явно помечать `plan`.
3. В `plans` оставлять предстоящие задачи, зависимости, критерии готовности и открытые вопросы. Завершённые шаги и отменённые сценарии не сохранять внутри активного плана.
4. Не включать в текущие документы хронологию решений, пересказы обсуждений, отчёты о правках документации и логи прогонов. При смене решения переписать действующее правило. Существенное свидетельство воспроизведения хранить отдельно; новый отчёт на каждую задачу не нужен.
5. При изменении поведения обновлять основной контракт и одну строку [changelog](changelog.md) со ссылкой. Переносы, оформление и повторные прогоны в журнал не записывать.
6. Каждый Markdown в `docs` имеет `status`, `updated`, `verified`. Статусы: `current`, `plan`, `hypothesis`, `history`, `superseded`. `updated` — дата правки текста; `verified` — `code`, `run YYYY-MM-DD` или `not verified`, а не дата актуальности данных. Проверка ссылок не подтверждает runtime.
7. Новый документ индексировать в README своего раздела. Имена текущих документов — без дат. Ссылки — относительные; при переносе обновлять входящие ссылки и якоря. Поле `replaces` при необходимости указывает прежнее имя.
8. После правок запускать `scripts/check-docs`: [границы проверки](testing.md#проверка-документации).

## Шаблон следующего задания

Для задания достаточно раздела существующего плана; отдельный файл нужен только при самостоятельном объёме.

```markdown
Результат: наблюдаемое поведение.
Статус: предложено / к исполнению / отложено.
Исполнитель и ревью: один исполнитель, нужный уровень проверки.
Границы: что входит, допустимые эффекты и целевое окружение.
Зависимости: что должно быть готово.
Готово, когда: критерии и необходимые проверки.
Открытые вопросы: только влияющие на результат и разрешённые действия.
```
