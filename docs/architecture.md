# Архитектура PlaceLens

Архитектура работающего приложения. Целевые возможности и границы первого выпуска — в [продукте](product.md).

## Границы системы

Модульный монолит с подготовленными локальными геоданными. Laravel/PHP 8.4 предоставляет REST API, PostGIS хранит и анализирует геометрию, Vue 3/TypeScript 6 отображает результаты. Python ETL подготавливает OSM и спутниковые выпуски офлайн. HTTP читает подготовленные данные; тяжёлая GIS/raster-обработка в нём запрещена.

Текущий экран анализирует адрес/точку в радиусе 200–1000 м через POST place-analysis. Четыре локальных POI-provider независимы. Спутниковые TCI/NDVI реализованы и локально активированы для шести дат; воздух ещё не реализован и возвращает UNAVAILABLE. Состояние локальной активации и запуск — в [runbook](runbook-local.md#локальные-спутники-рабочая-активация). Прежние profile/compare/transport/trips API сохранены, их старые страницы удалены; общий GIS/import/snapshot остаётся серверной инфраструктурой. Работающий спутниковый срез не означает завершение первого ядра или А13; приёмка остаётся в [roadmap](plans/roadmap.md#ближайшая-очередь).

```text
Локальные исходники → офлайн-подготовка → команды импорта → PostGIS
                                                          ↓
Браузер → API/FormRequest → предметные сервисы → SQL → JSON с качеством
    ↓
MapLibre: подложка + геометрии ответа + TCI/NDVI по descriptors API

Спутники: локальные входы → офлайн-выпуски и индекс
                            ├→ блочный runtime → PHP-reader → satellite JSON
                            └→ готовые PNG XYZ → PHP delivery → same-origin тайлы

Поездки: POST → mode dispatch → car provider + OSRM / walking provider + ORS
                              → собственные prepared snapshots/guards
```

Подложка может использовать сеть; она не является источником аналитических показателей. Live Overpass на каждый пользовательский запрос не используется. Новые внешние API сначала проверяются отдельным ограниченным исследованием.

## Backend

| Каталог | Ответственность |
|---|---|
| `app/Http/Controllers/Api/V1` | HTTP-ответ и делегирование предметной операции |
| `app/Http/Requests` | Валидация входа |
| `app/Http/Middleware` | Ограничения тела запроса и формата в соответствующих API |
| `app/Services/Addresses` | Профиль выбранного OSM-объекта и подпись произвольной точки |
| `app/Services/Gis` | Границы, геометрия области анализа, оценка покрытия |
| `app/Services/Osm/Search` | Поиск по подготовленным адресным записям |
| `app/Services/Osm/Analysis` | Показатели окружения и ограниченные display layers |
| `app/Services/Osm/Import`, `Transport/Import` | Readers, проверки источников, атомарные снимки |
| `app/Services/Transport` | Анализ официальных остановок |
| `app/Services/Analysis/SatelliteProvider.php` | Независимый блок спутниковой аналитики и descriptors слоёв |
| `app/Services/Satellite` | Чтение закреплённого runtime, проверка каталогов/блоков и доставка готовых PNG |
| `app/Services/Routing` | Раздельные car/walking providers и снимки, проверка геометрии/доступа и diagnostics; car SQL рядом с guard |
| `app/Console/Commands` | CLI-входы подготовки и импорта; discovery Laravel по convention |

Контроллеры не должны накапливать GIS/SQL, а UI — повторять серверный расчёт. Предметный SQL в небольшом сервисе допустим; отдельный repository layer нужен только при реальной ответственности, а не для обёртки одного вызова.

## Потоки и консистентность

- Импорты сохраняют источник, хеш входа/конфигурации, версии/даты и результат обработки. Readers и правила наборов остаются раздельными; публикация снимка и coverage атомарна.
- Адресный поиск читает подготовленные `osm_address_search_entries`; повторяемые пространственные связи готовятся до HTTP. Исходный населённый пункт не подменяется.
- Профиль фиксирует ID активных снимков одним чтением, затем считает независимые блоки. Ошибка одного блока/слоя изолируется transaction/savepoint; полный отказ БД может прервать профиль целиком.
- Сравнение запрашивает два обычных профиля независимо. Между запросами возможна публикация нового снимка; различия метаданных показываются, ссылка не обещает исторический снимок.
- Картографические слои профиля получаются из тех же выбранных снимков, ограничены радиусом/данными. Ближайший объект за кругом не обязательно присутствует в display layer.
- Спутниковый reader читает готовые NDVI/маски из ограниченных блоков и агрегирует круг; PostGIS выполняет проекцию точки. PNG подготовлены и перепроецированы офлайн; PHP проверяет и отдаёт запрошенные байты, MapLibre отображает их по descriptors API. Python/GDAL, расчёт NDVI и генерация тайлов в HTTP не запускаются. Поток подготовки и доверие — в [satellite](data/satellite.md#серверное-чтение-а101), поля и независимость отказов — в [контракте блока](features/place-analysis.md#6-блок-satellite).
- Запросы поездок проверяют локальную область, привязки, препятствия, доступ и согласованность ответа своего движка. Пеший provider читает ограниченные spatial cells и только объявленные ORS ways; восстанавливает цепочку исходных узлов в PHP. Полный городской контекст и Python не исполняются внутри HTTP. Неуспех не заменяется прямой линией или фиктивным временем.

Схема и единицы — [data-schema](data-schema.md), охват — [coverage](features/coverage.md), семантика зелени — [area-analysis](features/area-analysis.md), маршрутный контракт — [trips](features/trips.md).

## Frontend и состояние

Единственный Vue entry монтирует PlaceAnalysisPage на `/`; старые URL перенаправляются без восстановления query/fragment. Независимые запросы/epochs, карта, слои и выбранное место описаны в [frontend](frontend-structure.md). Старые визуальные оболочки и демо удалены, библиотечные модули/API и browser records сохранены. Хранение нового анализа не подключено.

## Окружение и данные на диске

Базовые сервисы: nginx, php, node, db; точные версии/сети — в Compose/Dockerfile. Nginx 80, Vite 5173, PostGIS 54325 опубликованы на loopback. PHP обращается к `db:5432`; Node-зависимости контейнера находятся в named volume.

Единый `docker-compose.yml` использует явный сохранённый режим frontend-assets: `dev` запускает Vite, `build` использует готовый `public/build`. Nginx ждёт FPM и выбранные assets. Автомобильный `local-router` включается профилем `routing` того же файла. У OSRM нет опубликованного порта; сеть routing внутренняя, snapshot монтируется read-only. Команды для нового и подготовленного окружения, переключение assets и явное подключение read-only спутниковых каталогов — в [локальном runbook](runbook-local.md). Чистый checkout не содержит аналитических наборов; локальная активация не является публичным деплоем.

Пеший `local-walking` включается профилем `walking` того же Compose-файла.
Его неизменяемый снимок монтируется read-only; проверенный граф копируется в
tmpfs для служебного lock GraphHopper. Исходный граф не переписывается. У ORS
нет опубликованных портов/внешней сети, logging отключён. Контракт и выпуск —
[walking-backend](features/walking-backend.md). Режимы, сброс результатов,
проверки ответа и действия UI определяет [контракт поездок](features/trips.md),
а не второй набор правил окружения.

| Путь | Роль и сохранность |
|---|---|
| `data/raw/<dataset>/<version>` | Исходники, границы и PBF для повторения подготовки |
| `data/satellite` | Офлайн-выпуски/индексы, отдельные runtime и PNG delivery; подключаются явно, исходные выпуски сохраняются |
| `data/prepared/local-routing/<version>` | Рабочие graph/guards/manifest и контрольные суммы выпуска |
| `data/reports` | Протоколы и артефакты; часть является входом `prepare-routing-runtime.py` и исторических проверок |
| `experiments` | Изолированные PoC с собственным README; `.runtime` grocery — производный стенд |
| `public/maps` | Локальные runtime-ресурсы карты с происхождением/лицензией |
| `public/build` | Опубликованный Vite manifest/assets; не disposable у работающего пилота |
| `storage`, `bootstrap/cache`, browser outputs | Runtime/cache/диагностика; могут содержать чувствительные материалы |

`data/` ignored. Это не уменьшает ценность входов, выпусков и доказательств; политика удаления требует отдельного задания с реестром зависимостей.

## Защита приватности

Приватность распределена по HTTP-клиенту, форме ссылки, request limits, обработке исключений PHP и Nginx logging/spooling. Эти слои не заменяют друг друга. Личные точки передаются POST, личные ссылки используют fragment; исходный ввод и аргументы исключений не должны попадать в журналы. Проверки — [testing](testing.md); механизм — [privacy fixes](features/trip-privacy.md).
