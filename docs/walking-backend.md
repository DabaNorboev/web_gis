# Локальный пеший backend

Статус: реализован и проверен изолированно 26.10.2026. UI `/trips` и `/compare`
пока остаётся автомобильным; выбор пешего режима в интерфейсе — отдельное задание.

## Контракт API

`POST /api/v1/trips/analyze` принимает `mode: walking`, один старт и 1–3 цели.
Форма координат совпадает с car: `start` и `places[]` содержат `lon`, `lat`,
у цели есть необязательный `label`. Необязательный `road: {lon, lat}` — явно
выбранная уличная точка. Она не подбирается автоматически вместо адреса.

Вызов без `road` трактует сам введённый пункт как выбранную уличную точку.
Точка внутри здания/препятствия, неоднозначность или отсутствие безопасного
кандидата требуют уточнения до запроса ORS. Наличие `road` позволяет сохранить
исходный объект и рассчитать **отдельную дорожную часть** от выбранной улицы.

Пример на публичной контрольной паре сохранённого OSM:

```json
{
  "mode": "walking",
  "start": {
    "lon": 92.85691572194698,
    "lat": 56.012996851312465,
    "road": {"lon": 92.85692831280052, "lat": 56.01289682010654}
  },
  "places": [{
    "lon": 92.8563753,
    "lat": 56.0133717,
    "label": "Публичный контроль",
    "road": {"lon": 92.85624483223121, "lat": 56.01336553074247}
  }]
}
```

У каждого результата:

| Поле | Значение |
|---|---|
| `start`, `target` | Исходные координаты объекта/ввода, не заменённые координатами улицы |
| `street_points` | Явно переданные уличные пункты, либо исходные пункты при отсутствии `road` |
| `route_scope` и `route.scope` | `street_points`: только дорожная часть |
| `metrics.*.scope` | `street_points`; значения относятся только к проверенной дорожной части |
| `address_metrics` | Значения и method всегда null: полный путь между объектами не подтверждён |
| `approaches` | Исходный объект, выбранная улица, геометрическое смещение; расстояние/время подхода null |
| `selection_kind` | `INPUT_STREET_POINTS`, `EXPLICIT_STREET_POINTS` или `DIFFERENT_STREET_POINTS` |
| `route.geometry` | Восстановленная исходная OSM-цепочка, а не непроверенный упрощённый shape |
| `snaps.*.original` | Введённая **уличная** точка; исходный объект остаётся в `start`/`target` |

При явном `road` подход имеет `status: UNKNOWN`; без отдельного объекта —
`NOT_INCLUDED`. Смещение `selection_shift_m` не является рассчитанным подходом.
Если хотя бы одно смещение объекта к явно выбранной улице превышает 20 м,
ставится `DIFFERENT_STREET_POINTS`. Такой выбор не объявляется успешной
автопривязкой исходного объекта. Проверка покрытия относится к выбранным улицам
и маршруту; исходный объект за пределами пилота при явном `road` остаётся лишь
контекстом, с неизвестным подходом.

Статусы `AVAILABLE`, `NEEDS_REFINEMENT`, `UNKNOWN`, `NO_PATH`, `UNAVAILABLE`,
`OUTSIDE_PILOT` относятся к уличной части. **AVAILABLE не означает достижимость
входа или полный путь от дома.** При любом другом статусе `route` и значения
`metrics` null; method null. Отказ одной цели не скрывает остальные результаты.
Автомобильный ответ и `LocalCarRouterProvider` сохранены.

## Подготовленный снимок и проверка

Provider использует только `local-walking:8082/ors/v2` в Docker. Внешний ORS,
API-ключи и перенаправления не используются. Время — статическая модель ORS:
нет полевой проверки скорости, ожидания переходов, входов или актуального доступа.
Высоты отключены, наличие пешего пути не подтверждает доступность для коляски.
Дата наблюдения неизвестна и не заменяется датой подготовки.

Данные находятся в ignored `data/prepared/local-routing/ors-foot-20261026-v1`:
граф, source PBF, 43 664 оригинальных ways, 5 815 spatial cells, manifest/hashes.
Все 12 659 исходных tagged nodes сохранены: retained nodes плюс 37 standalone
barriers из того же закреплённого контекста. Добавление препятствия не создаёт
новой связи графа; проходимость ворот требует общего исходного node ID.

PHP читает только нужные исходные ways и cells, проверяя их hashes. Городской
контекст не сканируется на запросе. Python, тяжёлый GIS и подготовка графа внутри
HTTP не запускаются. Для маршрута восстанавливается однозначная цепочка:
соседство исходных узлов, доступ/условия, препятствия, направление, coverage и
концы. Неоднозначная или частичная атрибуция остаётся неизвестной.

Основные пределы:

- уличная привязка 20 м; точность концов к исходнику 0,25 м;
- отклонение упрощённого shape от исходной цепочки до 1,25 м; этот допуск не
  расширяет проход через препятствия или выбор другого way;
- путь до 10 км; ответ ORS до 2 MB / 10 000 точек, до 3 секунд на запрос пары;
- до 2 000 named ways/cells, до 12 MB прочитанных исходников на операцию,
  до 50 000 guard features; дополнительные лимиты памяти/работы в reader/matcher;
- все прочие ограничения размера тела, числа целей и rate limit общего API
  сохраняются. Нет публичного пакетного matrix/isochrone API.

Здание не разрешается пересечь по одному тегу `bridge`/`tunnel`. Неизвестный
уровень железной дороги не считается доказанным разделением. Ворота/переезд
могут подтвердить точечное пересечение с правильными исходными IDs и доступом,
но не движение вдоль стены/railway. Ошибка проверки данных не выдаётся за
доказанный выход из coverage. Нулевые меры для ненулевого маршрута отклоняются.

## Подготовка и запуск

Нужны уже сохранённые входы прежних исследований; скрипт не скачивает данные,
не импортирует БД и отказывается перезаписывать каталог. Для побайтового повтора
этого выпуска использовать **точно** закреплённый timestamp:

```bash
python3 -B scripts/prepare-walking-runtime.py \
  --output data/prepared/local-routing/ors-foot-20261026-v1 \
  --prepared-at 2026-10-26T06:47:26+00:00
```

Если каталог уже существует, не удалять его ради повтора: выбрать новый каталог
и сверить результат. Новый timestamp/источники означают другой выпуск; нельзя
просто переписать pin для принятия неизвестных данных.

Manifest SHA-256:
`c448c4c1625e4bc514347d03ede7d364ba04d1af536f8a25e91d347b34a6a6a7`.
Он закреплён в `config/routing.php` и `docker/walking/start.sh`. Startup дополнительно
проверяет graph list, все файлы графа, конфигурацию и исходный extract.

```bash
docker compose -f docker-compose.yml -f docker-compose.routing.yml -f docker-compose.walking.yml up -d --no-build --wait --wait-timeout 120 php local-router local-walking
```

Команда запускает подготовленный контур и может поднять обычную db по зависимости
PHP; запуск не является read-only диагностикой. При отсутствии локального образа
Compose может потребовать его получение; автоматической подготовки графа нет.
Существующий default override не менялся: walking включается только явно.

У ORS нет опубликованных портов/внешней сети. Снимок read-only, служебная копия
графа — в tmpfs 128 MiB; ресурсный предел 2 CPU / 3 GiB без swap, heap 2 GiB.
Engine logging выключен конфигурацией и Docker driver `none`, включая ошибочные
запросы. PHP сохраняет прежнюю sanitization ошибок API; сырые ответы и приватные
аргументы не добавлены в журналы. Недоступный ORS не переключается на OSRM или
внешний сервис; автомобильный расчёт от него не зависит.

## Фактически выполненные проверки 26.10

- PHP unit/feature: **100 тестов / 449 assertions**, включая новый пеший API и
  прежний автомобильный/приватный контракт.
- Защищённый PostGIS: **174 теста / 1 911 assertions**, только новая временная
  `web_gis_test` в собственном контейнере/tmpfs; рабочая БД не запускалась.
- Python подготовка: **8 fixtures**, в том числе раздельные standalone barriers,
  одинаковые IDs, повреждённые входы и запрет перезаписи.
- Два настоящих offline-выпуска с одинаковым timestamp: manifest hashes совпали;
  полная сверка выпущенных файлов сохранена в свидетельствах.
- Настоящие Laravel API → ORS: четыре публичные пары задания 1 с явно выбранными
  улицами дали AVAILABLE; те же исходные точки внутри зданий — NEEDS_REFINEMENT.
  Смешанный запрос дал AVAILABLE / NEEDS_REFINEMENT / OUTSIDE_PILOT.
- После остановки только тестового ORS: walking UNAVAILABLE, car AVAILABLE с
  настоящим OSRM. Сервисы и БД были полностью изолированы от рабочего окружения;
  `.env` в PHP-контейнере маскировался пустым тестовым файлом, config cache отключён.

Это локальный backend-прогон, не GitHub Actions, публикация или приёмка UI.
Frontend/build/browser suites не запускались: их код и опубликованные assets
не менялись. Текущие ограничения входов и полевого доступа остаются.

Точные команды, результаты и изоляция сохранены в ignored
`data/reports/walking-backend-2026-10-26/`: `release.json`, `live/`,
`runtime-replay/`, `checks.json`, `preservation.json` и ведомость hashes.
Harness `check-live.py` в этом каталоге создаёт только собственные временные
сервисы, внутреннюю сеть и `web_gis_test`; raw-ответы содержат только публичные
контроли. Он отказывается перезаписывать существующий `live/`.

Задание 2 завершается runtime/API. Следующий отдельный этап — интерфейс явного
выбора улиц и различение дорожной части/подходов; существующий car UI не должен
начать выдавать пешие результаты без этого этапа.
