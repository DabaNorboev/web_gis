# Задача поиска жилья: контракт и состояния

Статус: **принятый целевой контракт**, с уточнениями владельца от 01.11.2026. `status: plan` отличает цель от работающего UI. П1/П2 реализованы частично относительно обновлённой цели; состояние и расхождения — в [плане перехода](search-task-delivery-plan.md). Принятие текста не подтверждает реализацию или проверки приложения.

## 1. Назначение и границы

PlaceLens помогает сузить территорию поиска жилья, сравнить расположение вариантов и подготовиться к просмотру. Объявления остаются на внешних площадках; каталог, парсинг, цены и фотографии не обязательны. Направление для агентств не входит.

Два входа в одну задачу: «Пока не знаю, где искать» — через важные места и территорию; «Уже есть варианты» — сразу через адреса. Условия сохраняются при переходах. Первый законченный путь: **условия → адреса → сравнение → подготовка к просмотру**. Территория добавляется позднее и не блокирует этот путь.

Работающая версия — [product](../product.md) и [контракты функций](../features/README.md); цель — этот документ; переход — [карта](interface-replacement-plan.md) и [поставки](search-task-delivery-plan.md). Прежние G/U/V-планы не являются очередью исполнения.

Основа — сценарий владельца и [девять макетов](search-task-mockups/README.md). Это ориентиры цели; принятый текст имеет приоритет над рисунками.

## 2. Сущности, идентичность и пределы

В первой версии **один поиск**, не более **5 кандидатов** и **3 важных мест**, сравнение пары. «Мой поиск ▾» открывает действия текущего поиска и его сохранения/удаления, **без списка поисков**, переключения между ними и создания нескольких задач. Лимиты действуют и для ссылок. При достижении предела добавление недоступно с объяснением; автоматического вытеснения нет. Расчёт всего списка одним запуском не предлагается.

| Сущность | Данные и ответственность |
|---|---|
| Поиск | Постоянный `searchId`, места, кандидаты, пара, общий радиус окружения, заметки и чек-листы |
| Важное место | Постоянный `placeId`, название, исходный выбор «адрес или точка», свой `mode` (`walking` / `driving`), необязательный личный порог времени |
| Кандидат | Постоянный `candidateId`, явно выбранный адресный объект, заметки и чек-лист; не объявление и не роль А/Б |
| Пара | Ссылки на разных кандидатов в ролях А/Б; может быть неполной. Один кандидат имеет профиль без обязательного сравнения |
| Результат поездки | В памяти: `candidateId`, `placeId`, условия и отпечаток, время расчёта, статус, значения, диагностики, происхождение и допустимая геометрия |
| Результат окружения | В памяти: `candidateId`, радиус, условия и отпечаток, время расчёта, значения, пропуски и происхождение |
| Подготовка к просмотру | Вопросы с основанием, отметки выполнения и собственные заметки, привязанные к кандидату; при связи с местом используется `placeId` |

А/Б — временные роли: перестановка или замена пары не теряет результаты, заметки и чек-листы кандидатов. Индекс результата backend — индекс в конкретном запросе, а не `placeId`. Диспетчер сохраняет соответствие «запрос → кандидат → место → режим» для каждого ответа.

Важное место как **адрес** хранит подтверждённый ID объекта, подпись и исходные координаты; как **точка** — явно выбранные координаты и пользовательскую подпись, без выдуманного адресного ID. Координаты обмена — EPSG:4326, `lon, lat`. Уличный выбор хранится отдельно от исходного объекта, проходит прежние проверки и не подтверждает вход или подход.

Подпись места не подтверждает назначение объекта или закрепление за школой; её правка не запускает расчёт.

## 3. Явный расчёт и независимость

Добавленный кандидат получает состояние **«Не рассчитано»**. Одна кнопка **«Рассчитать»** у кандидата запускает его поездки ко всем заданным местам и окружение. Кнопка пары запускает те же блоки для текущих А/Б. Без мест рассчитывается только окружение; пояснение предлагает добавить места для поездок. Без кандидата запуск недоступен.

Одна команда может потребовать несколько запросов существующих API для разных режимов. Отказы независимы по кандидату и блоку; частичный успех не обозначается как полный.

Добавление адреса, навигация, изменение условий, восстановление поиска/ссылки и Back/Forward **не запускают аналитику**. Поиск и подпись для выбора объекта — отдельные запросы. После выбора уличного кандидата доступно «Рассчитать» без автозапуска; это меняет прежнее поведение.

«Повторить» запускает отказавший блок/поездку; «Уточнить» открывает выбор по коду причины. После выбора проверка запускается явно. Новая команда, изменение/удаление ввода отменяет применение зависимого прежнего ответа; перед принятием проверяются epoch и отпечаток.

## 4. Условия, актуальность и устаревшие значения

**Отпечаток условий** включает ID/ревизии исходного выбора, фактические координаты и уличные hints, режим; для окружения — радиус. Известные версии источника, графа и методики сохраняются для проверки актуальности. Неизвестные версии не выдумываются; время расчёта отдельно от дат источника/наблюдения.

Порог, роли А/Б и радиус окружения не входят в отпечаток поездки. Отпечаток не доказывает свежесть данных: смена источника без доступных сведений автоматически не обнаруживается.

| Изменение | Поездки | Окружение / другие данные |
|---|---|---|
| Личный порог места | Принятый актуальный результат сопоставляется заново, без маршрутизации | Без изменения |
| Радиус 300/500 м | Без изменения | Прежний результат становится устаревшим; расчёт нового радиуса только по кнопке |
| Смена пары или А/Б | Сохраняются у кандидатов | Сохраняются |
| Смена адреса | Создаётся **новый кандидат с новым candidateId**, изначально «Не рассчитано» | Старый кандидат и его записи остаются до явного удаления; обычного переноса заметок нет |
| Явная замена исчезнувшего объекта | Новый кандидат и ID; старые расчёты/уличные выборы не переносятся | Только при подтверждённом missing допускается подтверждённый перенос заметок с пометкой «Относилось к прежнему объекту» и исходным адресом; старые отметки не подтверждают новый объект |
| Положение/режим места или его уличный выбор | Зависимые поездки сбрасываются; остальные сохраняются | Окружение не затрагивается |
| Новое место | Для него «Не рассчитано», прежние независимые ячейки сохраняются | Окружение не затрагивается |
| Удаление места | Его поездки и зависимый кэш удаляются | Заметки кандидата не удаляются; связанный пункт чек-листа не превращается в актуальный факт |
| Обнаруженная смена версии данных/методики без замены исходного выбора | Затронутые результаты помечаются устаревшими | Только затронутые блоки |

Сброшенный результат не участвует в таблице/карте. Устаревшее значение **в памяти** показано приглушённо с исходными условиями, временем и пересчётом, без сравнения с порогом, отметки «в ориентире / сверх» и актуальной маршрутной линии. Независимые ячейки сохраняются.

Предел — **«до 30 мин»** в рамке со значком цели; результат — **«около 24 мин»**. На метке места только предел, на линии маршрута только результат, в таблице колонка «Личный ориентир». Порог необязателен. Нет единого балла и автоматического победителя.

Автомобильное время модельное, без пробок и парковки; пеший результат относится к выбранным уличным точкам. Подходы от дома и входы не подтверждены. Расстояния окружения по прямой не доказывают доступность; неизвестные значения остаются `null` с причиной, не нулём.

## 5. Сохранение и удаление

Формат первой версии имеет `schemaVersion` и `searchId`. Локальное хранение без аккаунта: для первой версии выбран IndexedDB без новой библиотеки; настройки пока отдельно в прежних ключах localStorage. Сохраняются места (выбор, название, режим, порог и явные пользовательские уличные hints), кандидаты, пара, общий радиус, заметки и чек-листы.

**Числа результатов, время расчёта и геометрия в первой версии не сохраняются.** После открытия восстановлены условия, результаты «Не рассчитано». Расширение формата возможно через миграцию `schemaVersion`; неизвестная версия не перезаписывается, показаны причина несовместимости и отмена.

«Сохранено на устройстве» — только после записи текущей ревизии. До неё «Сохранение…», при сбое — «Не сохранено», причина и повтор. Успех старой записи не подтверждает новую ревизию. При ошибке сеанс работает с предупреждением о потере несохранённых изменений.

Удаление требует подтверждения с конкретным перечнем:

| Действие | Что перечисляет подтверждение |
|---|---|
| Удалить кандидата | Этот адрес, его результаты в памяти, заметки и отметки чек-листа; его роли в паре будут очищены. Места и остальные кандидаты сохраняются |
| Удалить место | Место, его режим/порог/уличный выбор, зависимые результаты и кэш территории; связанные основания чек-листа перестанут быть актуальными |
| Удалить поиск | Места, кандидаты, пара, заметки, чек-листы, результаты в памяти и производный кэш; настройки приложения остаются, в хранилище поиска остаётся только случайная отметка поколения |
| Удалить всё | Поиск, его производные кэши и известные настройки PlaceLens, **кроме остающейся случайной отметки поколения**; не данные других сайтов и не внешние/браузерные копии ссылок |

Успех удаления подтверждается завершением операции хранения; ошибка не маскируется. Подтверждение обоих видов удаления явно говорит: **«Останется случайная отметка, чтобы другая вкладка не восстановила удалённый поиск»**. В хранилище поиска после успешного удаления остаётся только маркер; при «Удалить поиск» отдельно сохранённые настройки не удаляются, при «Удалить всё» удаляются известные настройки. Сбой очистки настроек после удаления поиска — частичный результат, не полный успех.

### Поколение и защита от старой вкладки

Маркер — **128 случайных бит**: `crypto.getRandomValues(new Uint8Array(16))`, представление — 32 hex-символа. Он не выводится из адресов, ID, времени или иных данных; Math.random, хеш личных данных и запасной слабый генератор запрещены. При недоступности криптографического генератора запись не начинается. Маркер не является ID пользователя/поиска, не попадает в ссылку, отчёты, логи или сообщения ошибок. Основа генератора — [Web Crypto](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/getRandomValues).

Каждая вкладка запоминает поколение при открытии. **Каждая запись** в одной readwrite-транзакции IndexedDB читает текущий маркер, сверяет поколение вкладки и ревизию поиска, затем пишет. При обоих видах удаления маркер заменяется новым случайным, а запись поиска и производный кэш удаляются в той же транзакции. Удаляющая вкладка получает новое поколение из этой же транзакции и принимает его при complete; затем пишет новое состояние без перезагрузки. Abort не меняет её поколение. «Сохранено»/«Удалено» — только после complete; BroadcastChannel лишь уведомляет, не заменяет сверку. Порядок пересекающихся транзакций — по [IndexedDB](https://www.w3.org/TR/IndexedDB/#transaction-scheduling).

Прежнее поколение либо отсутствие ожидаемого маркера отклоняет запись: **«Данные удалены в другой вкладке»**. Такая вкладка не пересоздаёт хранилище, не инициализирует маркер заново и не автосохраняет оставшийся ввод; доступно только явное открытие актуального состояния либо временная работа без записи. Отсутствие маркера при наличии сохранённого поиска — повреждение, без молчаливого исправления. Пустое хранилище без маркера может инициализировать только новый, ещё не привязанный к поколению сеанс по явному созданию поиска. Сеанс со старым поколением этого права не получает.

**Окно гонки:** между нажатием «Удалить» и complete уже начатая чужая запись может завершиться раньше; следующая транзакция удаления стирает и её. После complete транзакция со старым поколением отклоняется. Между отдельными read и write сверки быть не должно. Старая вкладка может ещё показывать прежний ввод в памяти до уведомления/возврата фокуса; это не право записать его. Удаление IndexedDB внешними средствами браузера может убрать и маркер: активная старая вкладка не открывает БД повторно для записи после утраты соединения. Новый чистый сеанс не отличит полную внешнюю очистку от первого посещения; старые внешние копии и память другой вкладки этим не стираются. Это граница выбранного механизма, не гарантия удаления всех копий.

Обязательные будущие тесты П3: старая вкладка после каждого из двух удалений; отсутствие автопересоздания; в хранилище поиска только новый маркер без searchId/ревизии/времени/личных данных; отсутствие маркера у старого и нового сеанса; маркер без поиска и поиск без маркера; обе очередности гонки; после каждого удаления своя вкладка пишет новый поиск без reload, прежняя отклоняется, abort не принимает новый маркер; сверка ревизии обязательна. Значение маркера не печатается в тестовом отчёте.


## 6. Две ссылки и открытие входящей задачи

Два явных действия:

| Действие | Состав |
|---|---|
| **Поделиться адресами** | Передаваемый адресный выбор: один открытый кандидат либо выбранные А/Б, их подписи/ID, роли и общий радиус. Без личных мест, их порогов и hints |
| **Поделиться вместе с моими местами** | Тот же адресный выбор плюс личные места, подписи, исходные координаты/адресные ID, собственные режимы, пороги и явные пользовательские уличные выборы |

Не передаются весь список кандидатов неявно, заметки, чек-лист, результаты, геометрия, кэш, локальный `searchId` и настройки. Область ссылки явно указана: открытый кандидат либо пара; без выбора действие недоступно. Ссылка не является снимком результатов.

Перед личной ссылкой предупреждение о передаче мест, подписей, координат и условий и сохранении в истории браузера. Fragment не шифруется; личные поля не идут в query, логи и внешнюю аналитику. Версия ссылки отдельна от хранения; сериализацию определить до перехода, старые режимы не импортируются по матрице раздела 10.

До применения проверяются версия, структура, лимиты, координаты и роли. Адреса разрешаются без аналитики; ошибка не повреждает поиск. Импорт получает локальные ID без перезаписи случайно совпавших сущностей.

При уже сохранённом поиске доступны **три действия**:

1. **Открыть временно** — задача в памяти, без изменения постоянной; предупреждение о несохранении. Запись поверх прежней возможна только через явную замену с подтверждением.
2. **Заменить** — подтверждение с перечнем удаляемых мест, кандидатов, пары, заметок, чек-листов и кэша. Новый локальный `searchId`; при сбое записи прежний поиск остаётся доступным.
3. **Отмена** — прежняя задача и хранилище сохраняются, вход не применяется.

Без сохранённого поиска вход открывается без расчёта: успешная запись подтверждается, ошибка оставляет временный сеанс с предупреждением. Серверная загрузка объявления не разрешается ссылкой.

## 7. Исчезновение объекта и подготовка к просмотру

Исчезнувший кандидат до явной замены/удаления сохраняет свой ID, подпись и записи. Показано «Объект недоступен в текущих данных». Замена создаёт новый ID; перенос заметок — только по исключению раздела 4. Прежние результаты не текущие; ближайшее здание или старая координата не подставляются. Сетевой отказ не означает исчезновение.

Каждый пункт чек-листа имеет основание из факта или пробела. «Подход не рассчитан — проверьте выход со двора» не утверждает наличие препятствия. Заметки/отметки не меняют статус backend. Изменённое основание требует пересмотра; новый кандидат не наследует актуальные отметки прежнего объекта.

## 8. Таблица состояний экранов

Разделы: **Условия / Территория / Адреса / Сравнение / Просмотр**. Переход сохраняет контекст задачи. «Просмотр» всегда обозначает выбранного кандидата. Необязательный этап территории не блокирует добавление адреса.

| Состояние | Что видно | Доступное действие / переход |
|---|---|---|
| Пустой поиск | Два входа, отсутствие результатов | Добавить место или найденный адрес |
| Нет важных мест | Кандидаты/окружение доступны, поездок нет | Добавить место; «Рассчитать» проверяет окружение |
| Один кандидат | Его профиль; второй столбец не имитируется | Рассчитать, добавить кандидата, подготовиться к просмотру |
| Достигнуты 5 кандидатов / 3 места | Предел и причина недоступности добавления | Удалить с подтверждением или отредактировать существующее |
| Не рассчитано | Явная подпись без нуля и пустой маршрутной линии | «Рассчитать» у кандидата/пары |
| Расчёт идёт | Загрузка каждого запрошенного блока, независимые результаты доступны | Изменение ввода отменяет применение зависимого ответа; дублирующий запуск блокируется |
| Частичный отказ | Успехи и конкретные причины по ячейкам | Повтор/уточнение только там, где код это разрешает |
| Устарело | Приглушённое значение, исходные условия и время; без сравнения с порогом | Пересчитать |
| Вне покрытия | Причина и область ограничения | Без кнопки повтора; условия можно изменить отдельно |
| Ошибка сервиса/проверки | Структурированная причина без секретов | «Повторить», если реестр разрешает |
| Нужен выбор улицы | Указанный конец, кандидаты только из текущего ответа | «Уточнить», явный выбор и затем расчёт |
| Путь не найден / данных недостаточно | Причина из реестра; отсутствие пути не доказывает физическую непроходимость | Действие по конкретному коду, без универсального выбора улицы |
| Объект исчез | Старый адрес и записи, причина missing из resolver | Явная замена новым кандидатом; перенос заметок только с подтверждением и пометкой прежнего объекта |
| Сохранение / сохранено / ошибка | Статус текущей ревизии, предупреждение при сбое | Повторить запись; продолжить временно |
| Входящая ссылка при сохранённом поиске | Состав входа и последствия замены | Открыть временно / заменить / отмена |
| Ссылка недействительна или несовместима | Причина: формат, версия, лимит или неоднозначный старый вход; прежний поиск не меняется | Отмена / открыть сохранённый поиск; если его нет — начать пустой временный. Сначала явно убрать ошибочный вход из URL, без автопересчёта |
| Данные удалены в другой вкладке | Запись отключена; локальная память не объявляется сохранённой | Открыть актуальное состояние / продолжить временно; не создавать маркер заново |
| Подтверждение удаления | Конкретный перечень удаляемых данных и сохраняемых независимых данных | Подтвердить / отмена; ошибка не маскируется успехом |

На телефоне: три положения шторки, сопоставимые карточки А/Б вместо таблицы, прокрутка чипов. Положения и приоритеты прокрутки определить до реализации. Обязательны клавиатура, возврат фокуса и доступность закрытия/подтверждения на коротком экране. Дорисовать состояния и мобильное «Сравнение»; прочие случаи задаются таблицей.

## 9. Правила реестра кодов

Точные коды, объяснения, действия и состояния backend вынесены в [реестр поиска](../features/search-task-reasons.md). Его машинная основа — каталог backend П2, а не текст reason. [Diagnostics contract](../features/local-routing-diagnostics-contract.md) остаётся основным местом для локализации, target_index и формата issue.

Для каждого точного кода обязательны объяснение и допустимое действие; неизвестность не ноль и не повод угадывать конец. UNKNOWN результата, location unknown, UNKNOWN/CHOOSE выбора улицы и незнакомый runtime-код различаются. Выбор улицы не запускает расчёт. Backend-каталог проверяется независимо от UI-реестра: новая известная причина без объяснения/действия ломает тест; fallback не закрывает покрытие. Ошибки хранения и frontend-фазы отделены от backend-статусов.

## 10. Территория и границы перехода

Методика утверждается отдельным коротким документом до реализации. Предварительно: H3 в зоне local routing; вне подтверждённого покрытия нужного режима — «нет данных». От центра ячейки к каждому месту — в режиме этого места. Привязка только с существующими порогами; неуспех — неизвестность, не увеличение порога. Формулировка: **«по проверенным центрам ячеек»**, не гарантия для любого дома.

Ячейка удовлетворяет условиям, когда все обязательные пары проверены и укладываются в пороги. Неизвестные пары не считаются нулём или подтверждённым несоответствием. Полную таблицу сочетаний превышения и неизвестности, вариант отсутствующего порога, разрешение H3 и бюджет матрицы определить в методике и замере, а не угадывать по рисунку.

Ключ кэша: `(ячейка, placeId, режим, отпечаток выбора и данных)`, владелец — `searchId`. Порог перефильтровывает, изменение места/режима требует явного расчёта. Кэш не обходит запрет постоянного сохранения результатов первой версии. Его устройство задаст методика; обе команды удаления очищают кэш, поздний ответ его не воссоздаёт.

Границы повторного использования и регрессий — в карте замены. Принятие контракта не разрешает удаление UI или установку инструментов; совместимость старых входов определена ниже.

### Прямые страницы и старые ссылки: решение первой версии

**Решение владельца 02.11.2026 (C2), заменяет D11. До П7 поведение не меняется.** После П7 старые страницы не монтируются; прежние входы обслуживает новый UI:

| Старый вход | Поведение после П7 |
|---|---|
| `/address/{id}` с валидным адресным ID | Временный новый поиск с этим кандидатом, без расчёта и записи |
| `/compare` с валидными адресами | Временный новый поиск с указанными кандидатами/парой; только адресные параметры и допустимый радиус, без расчёта и записи |
| `/trips`, личные места/точки, прежние `#places`/`#trip`, корневые старые query, смешанные параметры, дубликаты, неизвестная версия, повреждённый или иной старый вход | «Ссылка несовместима» и кнопка «Новый поиск», без частичного импорта |

Допустимые адресные входы проходят проверку ID/лимитов и resolver без аналитики. Исчезнувший объект не заменяется сохранёнными координатами; отказ resolver не объявляется исчезновением. Неоднозначные/лишние поля и смесь с новым fragment отвергаются целиком; личные места, режимы, hints и результаты не переносятся. Точный allowlist параметров фиксируется в адаптере П6 и его fixtures, не расширяет эту матрицу.

Временный вход не пишет storage **даже при отсутствии сохранённого поиска** и не запускает расчёт при открытии/Back/Forward. Сохранённый поиск остаётся нетронутым; дальнейшая явная замена/сохранение требует отдельного подтверждения по разделам 5–6. Кнопка «Новый поиск» при несовместимости не удаляет и не перезаписывает сохранённое без подтверждения. Старый личный fragment не попадает в новый query, логи или аналитику; уже отправленные серверу прежние query задним числом не скрываются.

Граница повторного использования: API, независимые типы, чистые утилиты и картографические примитивы. Исключение C1 — новое ядро П1/П1а, не импортирующее старые страницы, компоненты, composables и owners прямо или транзитивно, включая типы; импорт-тест П4 проверяет и его. Точный список — [карта замены](interface-replacement-plan.md#список-разрешённых-импортов-для-п4). Новые UI и владельцы представления пишутся с нуля; старые файлы сейчас не меняются/не удаляются.

Дальнейшие задания — [карта замены](interface-replacement-plan.md) и [план поставок](search-task-delivery-plan.md). П1а и хранение с маркером П3 реализованы изолированно; публичный UI и совместимость ещё не подключены. [Модули П3](../frontend-structure.md#хранение-нового-поиска-п3).
