# G4: интеграция обновлённого интерфейса

Статус: G4.1–G4.2 реализованы в рабочей копии 29.10.2026; G4.2a и последующие этапы не начаты, приёмка G4 впереди. Основание — завершённая в описанных границах G3.5 из [общего плана](interface-v2-plan.md) и просьба владельца разбить перенос обновлённого макета на этапы. `verified: code` означает сверку границ с исходниками, не новый прогон приложения или приёмку дизайна владельцем.

Этот документ — основное место порядка интеграции. [UX-план](interface-prototype-ux.md) описывает решения самостоятельного макета; [frontend-structure](../frontend-structure.md) и контракты функций описывают рабочее приложение. Отчёты макета не подтверждают работу приложения.

## Исходники и границы

- Визуальный ориентир — [PlaceLens Visual](../../experiments/placelens-visual/PlaceLens-visual.html), редактируемые [HTML](../../experiments/placelens-visual/index.html), [представление](../../experiments/placelens-visual/visual.js), [действия](../../experiments/placelens-visual/app.js), CSS в том же каталоге. Последние изменения описаны в [QA от 29 октября](../../experiments/placelens-visual/QA-ux-next.md#уточнения-представления-29-октября-2026). Код демонстрационных запросов и чисел в приложение не копировать.
- При подготовке: ветка `feature/walking-street-choices`, HEAD `c2b7d44`. Пять коммитов уточнений макета существуют, но G2–G3, часть исходников и реорганизация документации всё ещё присутствуют в staged/unstaged/untracked. HEAD сам по себе не воспроизводит всю основу интеграции. Перед каждым заданием заново проверять Git; не сбрасывать и не коммитить чужую работу попутно.
- Переносится Новый интерфейс главной. Текущий интерфейс, отдельные `/address/:id`, `/compare`, `/trips`, ссылки и переключение представлений сохраняются. Решение о default и удалении прежнего вида не входит в G4.
- Сохраняются один/два адреса, 300/500 м, до трёх общих целей, общий режим, явный расчёт, отдельный произвольный старт, остановки вокруг точки, уточнение улиц и независимые повторы.
- Backend, GIS, guards, лимиты, форматы ссылок и хранение личных точек не меняются. Все предметные операции выполняют существующие владельцы; другой loader, cache результатов или writer history не создаётся.

| Решение | Интеграция |

| Общие пояснения окружения, ⓘ, подробности своей ячейки | Тексты и происхождение берутся из текущих контрактов/ответов. Демо `envNote` не становится вторым источником методики |
| Обзор / Поездки / Рядом / Данные | Единая навигация результата без вложенных дублирующих вкладок; доступные tablist/tab/tabpanel и клавиатура |
| Сигналы целей и связь карты со строкой | Из имеющихся результатов: готово, нужен расчёт/уточнение, ошибка, неизвестность; после G4.2a также отношение к заданному ориентиру. Сторона и цель определяются стабильными ID |

29.10.2026 владелец явно включил личные ориентиры в эту интеграцию отдельным этапом. G4.2a следует после матрицы и до карты/мобильной доводки; номера остальных этапов не меняются. GIS/маршрутные расчёты остаются прежними; сравнение с заданным значением — новая пользовательская функция. До G4.2a пороговые элементы не показываются как работающие.

G4.1 — выполнен в границах handoff ниже; остальные этапы — **не начаты**. По умолчанию один исполнитель на этап, без субагентов и повторного поиска референсов. ### G4.2a — личные ориентиры и обновление статусов

**Зависимость:** G4.2. Новая функция согласована владельцем; повторное разрешение не требуется.

**Объём:** ориентир модельного времени для каждой цели, отдельно по режиму, общий для А/Б; отдельный ориентир прямого расстояния до ближайшей остановки в адресном сравнении. Самостоятельный старт имеет свои цели/ориентиры. Другие метрики не получают порогов автоматически. Без заданного ориентира остаются числа и состояние расчёта, без статусов соответствия и выдуманного default из демо.

**Владение:** один владелец настроек внутри рабочего пространства вне условий версии/вкладки. Ключи — сценарий, стабильный goal ID и режим, для остановки — metric key. Ответы API не дублируются. Переименование/замена точки сохраняют ориентир той же цели; замена А/Б — общие ориентиры. Удаление цели удаляет её настройки. Другой режим использует свои настройки, не порог предыдущего. Радиус не меняет ориентиры и поездки.

**Первая версия хранения:** память открытой страницы, без БД/localStorage и расширения URL. Переключение версии/вкладок сохраняет настройки, reload сбрасывает. Восстановление чужой ссылки не подставляет ориентиры по совпавшему индексу. При редактировании и перед копированием ссылки явно сообщать: «Ориентиры действуют в этом сеансе и не входят в ссылку». Ordinary/personal форматы прежние; передача ориентиров остаётся отдельным расширением.

**Сравнение:** конечные положительные значения в минутах/метрах; пустое поле снимает ориентир, ошибочный ввод не применяется. Сравнивается исходное известное значение, минуты переводятся в секунды по контракту ответа. Равенство входит в ориентир. Округление не меняет статус; малое превышение не подписывается «0 мин сверх». Неизвестные/непринятые значения и несопоставимые методы не классифицируются по порогу. «В ориентире» относится к данной метрике/модели, не к пригодности жилья или подтверждению подхода.

**Представление:** вход возле цели/строки, нейтральные числа, порог на общей шкале, знак и текст. Для остановки — личный ориентир прямого расстояния, не норматив пешего доступа. Оговорки модели сохраняются. Окно показывает живую сводку А/Б, включая приходящий ответ. Правка применяется сразу; закрытие/Esc завершает редактирование, не обещая отмены уже применённого. Запрос не запускается/не отменяется, геометрия не меняется.

Акцент и одно доступное уведомление запускаются после закрытия окна только для изменившихся статусов, с учётом reduced motion. Долгое редактирование не расходует время акцента, первый результат не объявляется сменой прежнего статуса. Карта G4.3 использует эти же подготовленные статусы.

**Файлы и документы:** отдельные state/presentation по необходимости, редактор/матрица G4.1–G4.2, типы UI. При реализации обновить основные контракты сравнения/поездок, product и changelog по фактическому поведению; сейчас план не заменяет текущие контракты.

**Готово и проверки:** frontend границ, равенства/округления, null, режима/ID/сброса; browser редактирования/снятия ориентира, долгого окна, ввода во время запроса, ошибки/неизвестности, фокуса и переключения версии. Числа, геометрия, sequence и количество POST при изменении только ориентира прежние. Проверить ссылки/reload согласно границе хранения. G4.4 дополнительно проверяет окно на 390×480, возврат к инициатору, акцент после закрытия и отсутствие самовольного переключения экрана при редактировании из настроек.

### G4.3 — одна реальная карта и связь с матрицей

**Зависимость:** G4.2 и G4.2a с устойчивыми ID строк, общими статусами ориентиров и действиями выбора/возврата. Сигналы карты используют сравнение G4.2a без собственной формулы; изменение ориентира не вызывает fit и расчёт.

**Сделать:**

- Подготовить общий набор маркеров А/Б и до трёх целей, состояния из результатов; разделить «Все цели / Одна цель» как управление показом, не новый расчёт.
- Расширить подготовленные map props/overlay для нескольких принятых результатов. У каждой интерактивной сущности сохранить сценарий, сторону, goal ID, endpoint и sequence. Старые дорожные кандидаты не становятся кандидатами другой ячейки.
- Показывать только существующую допустимую геометрию в соответствии с режимом показа. Не рисовать схематичные связи SVG из макета, линии ошибочной поездки и неподтверждённые пешие подходы. Поисковые адресные кандидаты, выбор улицы и точки имеют приоритет своего контекста.
- Выбор строки выделяет соответствующий результат/цель; маркер открывает свои подробности. Возврат имеет явную цель. Увеличение карты и слои не закрывают маркеры и атрибуцию.
- Сохранить один MapLibre и обработчик клика. Camera fit только по явному намерению, включая ожидание ready и отмену. Тема, результат запроса, resize и переключение вкладки не вызывают неожиданный fit; при изменении контейнера вызывается корректный resize.

**Основные файлы:** HomeWorkspaceMap, подготовка map data/useHomeTrips, homeWorkspace types, HomePage, при необходимости tripOverlay/CityMap. Если изменён общий CityMap/overlay, прогнать также старые карты.

**Готово:** две стороны и три длинные цели различимы на реальной карте при разных zoom, отказе подложки и выборе улицы. Компактная карта остаётся пригодна для взаимодействия, раскрытие даёт полноценный выбор; жёсткая высота SVG не переносится без проверки.

**Проверки:** frontend home-workspace-map/trip-overlay, browser выбора кандидатов/ручной улицы, раннего focus, отмены/позднего события, камеры, слоёв/тем и отказа/повтора подложки. Проверять сохранение локальных результатов и количества расчётных POST.

**Сделать:**

- Сохранять позиции каждого мобильного экрана; возврат «К строке» восстанавливает строку/фокус и имеет приоритет над обычной сохранённой прокруткой. Новый расчёт явно показывает начало результата, поздний ответ не вырывает пользователя из начатого редактирования.

**Основные файлы:** HomePage, представление результата/редактора, контроллер UI-навигации при необходимости, scoped styles. UI scroll/focus state не записывается в личную ссылку или БД.

**Готово:** 390×844, 320×740, 390×480 и переход через desktop breakpoint; форма/подробности прокручиваются, кнопки доступны, возврат стабилен даже после длинного чтения и повторного входа. Пустые и восстановленные URL-сценарии различены: корректное восстановление не заменяется обязательным стартом в настройках.

**Проверки:** browser мобильного перехода строка → карта → возврат, вкладок/диалогов, частичной ошибки, независимости сценариев и сохранения при смене версии. Проверить 200% zoom и отсутствие ловушки фокуса вне модального окна. Физический touch/экранную клавиатуру проверять на устройстве при наличии; уменьшение viewport не выдавать за такую проверку.

### G4.5 — итоговая интеграция и регрессии

**Зависимость:** G4.1–G4.4, включая G4.2a. Это стабилизация собранного приложения, не повторная разработка дизайна.

- Пройти полный путь адрес → профиль → А/Б → общие цели → оба режима → уточнение/повтор → замена/удаление; отдельно старт/точка/остановки и возврат.
- Проверить ordinary/personal links, reload, Back/Forward, invalid/conflicting fragments, переключение версии с результатом/черновиком/запросом. Владельцы и writer URL остаются единственными.

### G4.6 — независимая приёмка обновлённого приложения

**Зависимость:** G4.5 и остановка параллельных правок приложения на время приёмки.

Другой чат сравнивает живое приложение с исходным макетом и согласованной таблицей границ, а не только читает отчёт. Проверяет заполненное А/Б, одиночный/пустой экран, частичные ошибки, реальные сценарии взаимодействия и карту. Размеры: 1440×900, 1280×720, 1280×560, 390×844, 320×740, 390×480; фактические viewport подтверждаются, снимки просматриваются.

Приёмщик не расширяет дизайн и не исправляет приложение сам. Записывает воспроизводимые дефекты и возвращает конкретному этапу; после исправления повторяет затронутые сценарии. Неработающие действия, утрата состояния, неверные подписи/выводы, недоступные результаты или перекрытые важные кнопки препятствуют закрытию G4. Мелкие предложения отделяются от дефектов.

**Готово:** явный вердикт с проверенными границами и оставшимися ограничениями, затем оценка владельцем. Агентская приёмка не является usability-тестом с новым человеком. Реальные GIS/OSRM/ORS, свежесть данных и физический телефон не считаются проверенными синтетическими API. Изменение default или удаление Текущего интерфейса остаётся отдельным решением.
