# Крупные дороги и железнодорожные линии на карте

Управление обновлено 23.10.2026: темы подложки, переход от показателя к слою, выделение конкретной линии и свёрнутая легенда фактически показанных данных. Сведения по «О данных» и ручные переключатели сохранены. [Актуальные взаимодействия и проверки](map-visual-interaction-2026-10-23.md). Ниже — методика и исторические проверки слоя 20.10.2026.

Этап от 20.10.2026: на картах профиля и выбранных вариантов сравнения добавлены два независимых слоя, выключенных по умолчанию. Переключатели сравнения общие для обеих карт. Площади и официальные остановки сохраняют отдельное управление и прежние данные. Главная и карты поиска не получают новые аналитические слои.

Крупные дороги обозначены оранжевой сплошной линией с белой обводкой, железнодорожные — фиолетовым пунктиром с белой обводкой. Легенда объясняет источник, ID снимка, дату версии и неизвестную дату наблюдения отдельно для каждого слоя/стороны. Цвета подложки не переключаются вместе с аналитическим слоем. Прямое открытие/refresh начинает с выключенных слоёв; замена вариантов, радиуса и история внутри страницы сохраняют выбор. Состав URL прежний: адреса и радиус.

## Источник и пределы результата

Используются существующие локальные снимки OpenStreetMap: дороги №10 и пути №11. Версия источника 18.10.2026 20:25:06 UTC, `observed_at=null`. Даты и ID берутся из метаданных API, не заданы константами в UI. Атрибуция © OpenStreetMap contributors, ODbL, со ссылкой на страницу copyright сохранена в легенде.

- Крупные дороги: `motorway`, `trunk`, `primary`, `secondary` из существующего `osm_roads`.
- Железная дорога: `rail`, `narrow_gauge` из существующего `osm_railways`; трамваи не добавляются.

Показываются картографические фрагменты, без вывода об эксплуатации, движении, шуме, воздухе или безопасности. Пересечение линий на плоской карте не подтверждает соединение. Разные проезжие части, пути и OSM ID не объединяются, совпадающие линии сохраняются. Число фрагментов и длины не выводятся как новые показатели. Прежние строки длин дорог/путей в сравнении убраны из интерфейса; существующие расчёты и значения API сохранены. Профиль и раньше показывал расстояния до линий без их длины.

Пустой доступный слой означает только отсутствие найденных линий в выбранном снимке и области. Это не доказывает отсутствие объектов на местности. Ошибка/недоступность, загрузка и частичное покрытие имеют отдельные сообщения. При частичном покрытии возвращаются только известные фрагменты. Никаких рейтингов или общего балла.

## API и ограничение области

Существующий `GET /api/v1/addresses/{id}/profile?radius_m=300|500` дополнен `map.linear_layers.{roads,railways}`. Новых эндпоинтов, источников, импортов, миграций, схемы и снимков нет. Показатели/старые map-поля не меняются. Каждый слой — `{status,data,message}`; `data` — FeatureCollection с `coverage`, `radius_m`, `source`, `dataset_import_id`, `observed_at`, `source_updated_at`, `quality`. В properties каждого элемента только исходный ID, имя и тип. Длины в новом map-контракте отсутствуют.

`OsmLinearMapService` получает те же заранее зафиксированные ID снимков и покрытие, что существующий блок профиля. Область — пересечение метрического круга анализа EPSG:32646 (`quad_segs=64`) с `data_geom` соответствующего снимка. Сначала применяется bbox-фильтр по существующему GiST, затем пересечение кандидатов с областью, `ST_CollectionExtract(...,2)`, исключение пустых геометрий и преобразование в EPSG:4326 lon/lat (GeoJSON, 9 знаков). Сохраняются LineString/MultiLineString и разрывы частей; нет union, слияния по имени/близости или построения графа. Полные исходные длинные линии и весь город браузеру не передаются. При UNKNOWN/OUTSIDE_SERVICE_AREA или отсутствующем источнике — пустой недоступный слой.

Два ограниченных набора передаются в обычном ответе профиля даже при выключенных слоях. Переключение меняет только MapLibre layout visibility и не запрашивает новые данные/не сбрасывает геометрию. Перемещение карты также не расширяет область: фрагменты остаются ограничены анализом выбранного адреса. Для новых GeoJSON-источников задано `tolerance: 0`, чтобы MapLibre не отбрасывал короткие фрагменты при упрощении. Другие источники/слои не менялись. Ошибка геометрии слоя изолируется savepoint: показатели, площади и второй линейный слой остаются доступны. Исходные теги/геометрии в БД не переписываются.

## Проверки

- **48 frontend-тестов**: все прежние проверки и два новых компонентных теста. Проверены 4 комбинации линий × 8 комбинаций площадей, независимость остановок/адреса/радиуса, точное сохранение исходных фрагментов/ID, отсутствие setData при изменении только видимости, очистка и ошибка отдельного слоя, источник/даты, empty/partial/missing/loading. SSR-тест сравнения проверяет отсутствие строки длины при сохранении остальных карточек.
- Typecheck, production build и Pint трёх PHP-файлов проходят. Сборка без сети, проект/зависимости read-only, результат сначала во временном каталоге. Предупреждения о MapLibre-бандле >500 кБ и необязательном fontaine прежние; новые зависимости не ставились.
- **3 GIS-теста / 119 assertions**: только новая изолированная БД `placelens_linear_layers_test_20261020` с копией структуры без данных, транзакции с откатом, без миграций/импортов. Проверены 300/500 м, большие/далёкие линии, отдельные ID дублей и параллельных/пересекающихся линий, MultiLineString с двумя разорванными фрагментами, покрытие/частичная обрезка, empty/missing/UNKNOWN/OUTSIDE и изоляция SQL-ошибки одного слоя с сохранением старых показателей/площадей/второго слоя.
- **20 реальных наборов** (5 адресов × 2 радиуса × 2 категории), **208 фрагментов**: независимый пространственный запрос сверяет ID исходных элементов. Максимальное расстояние до каждой геометрии не превышает радиус +0,002 м после округления GeoJSON; остаток линии вне data_geom ≤0,002 м. Самый большой сериализованный набор features в этой выборке — 16 830 байт. Это наблюдение по выборке, не максимальный размер или производительность по городу.

## Сохранность и воспроизведение

Браузер и проверки рабочих данных использовали отдельный временный PHP-стенд: проект/сборка read-only, временный storage, array-сессии/кэш, отдельная cookie, PostgreSQL `PGOPTIONS=-c default_transaction_read_only=on`. Только отдельный процесс GIS-тестов отключал read-only с принудительной конфигурацией новой изолированной БД и охранной проверкой имени. Миграции/импорты в рабочей или тестовой БД не запускались; тестовой БД скопирована лишь структура. Все синтетические строки откатились, временная БД и PHP-стенд после проверки удалены.

Полные контрольные суммы строк 11 рабочих таблиц до/после совпали: снимки/покрытие, остановки/маршруты/связи, адреса, здания, дороги, пути, зелень, вода. Все прежние поля десяти профилей (включая показатели длины в API, качество, площади и остановки карты) совпали после исключения времени расчёта и нового `map.linear_layers`.

Сборка установлена в локальный `public/build` после браузерной проверки. Перезаписан только сгенерированный manifest с резервной копией, добавлены новые assets; прежние assets не удалялись. Существующие пользовательские изменения сохранены. Исходные данные, `.env`, миграции, схемы, формулы существующих расчётов и прежние компоненты площадных/официального слоёв не редактировались. Сверены 755 существовавших файлов, включая 65 файлов data/raw и .env: удалений и неожиданных изменений кода/данных нет. `git diff --check` пройден. Служебный `.idea/workspace.xml` изменился во время работы; этим заданием он не редактировался, причина изменения не устанавливалась, файл не сбрасывался.

Артефакты: `data/reports/linear-map-layers-2026-10-20/` (игнорируется Git): before/after/final сверки, bounds.php/json, браузерный сценарий/результаты/скриншоты, логи frontend/GIS/build/typecheck и отчёт сохранности файлов. Предыдущие отчёты сохранены.

Повторение безопасных frontend-проверок: `docker compose exec -T node npm test` и `docker compose exec -T node npm run typecheck`. Новый `tests/Integration/OsmLinearMapTest.php` требует изолированной разрешённой тестовой БД с текущей схемой. Браузерный сценарий рассчитан на отдельный read-only стенд; перехват MapLibre-конструктора существует только в тестовом браузере, продуктовые hooks не добавлены. Этап не начинает следующий слой или импорт.
