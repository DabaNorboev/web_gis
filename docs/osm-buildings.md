# Локальный импорт зданий OSM

Реализован отдельный подэтап Stage 4: `osm_buildings`, команда `osm:import-buildings`, атомарные снимки. HTTP API окружения, показатели и слой зданий пока не добавлялись.

## Снимок и аудит — 19.10.2026

## Схема и правила импорта

`osm_buildings`: FK `dataset_import_id`, `osm_type` (way/relation), `osm_id`, версия/время правки, `feature_kind` (building/part), исходная `geom` (Polygon/MultiPolygon, EPSG:4326), `crosses_boundary`, `parent_relations`, `count_exclusion`, `raw_data`. Уникальность — `(dataset_import_id, osm_type, osm_id)`; адрес и название не являются ключами. Есть GiST по `geom` и индексы идентификатора/вида в снимке. Ограничения проверяют непустую валидную 2D-геометрию, координаты и согласованность вида с исходными тегами.

- Импорт не требует адреса. `building:part` имеет приоритет, даже когда указан `building`; оба тега сохраняются с предупреждением.
- Отбор по `ST_Intersects` с сохранённой границей, а не по прямоугольнику или центроиду. Пересекающие границу контуры не обрезаются и получают флаг/предупреждение. Полигон границы и его SHA-256 записываются в конфигурацию; буфер за границей не загружается. Это ограничение нужно учитывать в будущих показателях граничных адресов.
- Дедупликация подсчёта ограничена явным outer-членством way в валидном родительском relation вида building и проверкой `ST_Covers(parent,member)`. Way сохраняется с `count_exclusion={reason:covered_outer_member,parent_osm_ids:[...]}`. Один лишь одинаковый адрес, пересечение или близость исключения не создаёт. Родитель-часть, невалидный, отсутствующий или не покрывающий member родитель не исключает way. Исходные ссылки сохраняются в `parent_relations` для разбора.
- Для будущего числа зданий использовать `feature_kind='building' AND count_exclusion IS NULL` и активный снимок. Это число OSM-объектов по правилам импорта, а не подтверждённое число физических жилых домов. Для доли площади нельзя складывать пересекающиеся площади: методика и API относятся к Stage 6.
- Журнал: `source=OpenStreetMap`, `dataset_key=buildings`. Дата OSM — версия исходника, `observed_at=null`. Файл и стабильная конфигурация (граница/правила/source URL) хешируются отдельно. `--expected-sha256` дополнительно проверяет нужный файл перед созданием попытки.
- Проверка документа/границы предшествует записи попытки. Ответ с `remark`, дубли OSM ID и неверная контрольная сумма отклоняются. Геометрии не ремонтируются; причины пропусков/предупреждений сохраняются в отчёте и журнале.
- Строки сначала подготавливаются во временной таблице. Публикация и смена активного снимка — в одной транзакции, конкурентный импорт блокируется advisory lock. Сбой оставляет предыдущий снимок активным, попытка получает `failed`. Пустой или состоящий только из частей набор не публикуется.
- Защита снижения более 20% проверяет и общее число строк, и отдельно число самостоятельных объектов зданий: рост числа частей не маскирует исчезновение зданий. После проверки dry-run допускается `--allow-large-drop`.
- Точный повтор успешного входа возвращает `skipped`. Исторический повтор не реактивирует старый снимок; исчезнувшие из новой загрузки объекты остаются только в истории. Адреса и остановки не переключаются.

## Запуск

Все операции офлайн, PHP/Composer — в контейнере `php`. `--source-url` только записывает происхождение, сетевых обращений команда не выполняет. Снимок около 68 МиБ целиком разбирается в памяти: используйте CLI-лимит 1024 МиБ; это не меняет PHP-FPM или Docker. Это JSON-импортер, не потоковый читатель произвольного PBF.

```bash
docker compose exec php php artisan migrate

docker compose exec php php -d memory_limit=1024M artisan osm:import-buildings \
  data/raw/osm_buildings/2026-10-19-vk/buildings.json \
  --boundary=data/raw/boundaries/krasnoyarsk/2026-10-07/boundary.geojson \
  --source-url=https://maps.mail.ru/osm/tools/overpass/api/interpreter \
  --expected-sha256=1655e58d07cdea16d07447400f8f9e776c973bde6c0fa9328f24b52c9f141b4f \
  --dry-run --report=data/reports/osm_buildings_import/2026-10-19/dry-run.json
```

Для публикации повторить без `--dry-run`, с `--report=.../import.json`. Dry-run не меняет строки зданий и журнал. Успешный отчёт также хранится в `dataset_imports.result`; при ошибке публикации причины и промежуточный отчёт остаются в неактивной попытке журнала. Сырые JSON и отчёты не коммитятся.

## Проверки

`docker compose exec php composer test:postgis`: отдельная база `web_gis_test`, ограничения/индексы и обратимость только в изолированной тестовой схеме. Проверяются адресонезависимый импорт, отверстия, части, явное outer-членство с покрытием, ошибочные родители, граница с отверстиями, сохранение полного пересекающего контура, dry-run, повторы/история, падение числа зданий, откат публикации, контрольная сумма, `remark`, конкурирующая блокировка и независимость наборов. Общая проверка идентификаторов/дат Overpass вынесена в `OsmSnapshotReader` и используется адресным импортером без изменения его правил отбора.

## Опубликованный снимок — 19.10.2026
