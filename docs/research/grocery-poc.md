# Изолированный PoC продуктовых магазинов OSM

Дата: **20.10.2026**. Это техническая проверка отдельного эксперимента, не исследование пользовательского спроса и не интеграция в основной PlaceLens.

## Результат

Создан отдельный [PoC](../../experiments/grocery-poc/README.md): выбор двух конкретных адресных OSM-элементов, общий радиус **300/500 м**, два списка и две карты, выделение объекта и ссылки на OSM ID/версию. Категория строго `shop=supermarket|convenience|grocery`. Объединения по сети, имени, адресу или близости нет. Числа подписаны как найденные **элементы OSM**, без рейтинга и вывода о лучшем адресе.

Локальный адрес для просмотра: [http://127.0.0.1:8765](http://127.0.0.1:8765). После проверки оставлен только read-only сервер эксперимента. Команда отдельного запуска из корня проекта:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 experiments/grocery-poc/server.py
```

Если этот экземпляр уже работает, повторный сервер на том же порту запускать не нужно. В самостоятельном терминале остановка — `Ctrl+C`; для другого свободного порта есть `--port`.

Прежние страницы, маршруты, схема БД и исходные наборы не редактировались. Исследовательские отчёты также не менялись. Внешние API, аккаунты, ключи и новые источники данных не используются.

## Основания и изоляция

Перед работой проверено рабочее дерево, прочитаны README, локальная спецификация и оба отчёта: [аудит критериев](criteria-research-audit.md), [аудит POI](poi-coverage-audit.md). В дереве уже были многочисленные изменения пользователя. Сбросов, коммитов и форматирования существующих файлов не было.

Все новые исполняемые файлы находятся в `experiments/grocery-poc/`. Основной Laravel/Vue, Composer/npm-конфигурация и Docker Compose не менялись. Отдельный Python HTTP-сервер использует стандартную библиотеку и слушает только `127.0.0.1`; это временный стенд, не предложение менять архитектуру продукта. GIS-расчёты выполняются на стороне Python, браузер только отображает результат через уже установленный MapLibre.

Подготовка выполнялась существующим образом `web-gis-osm-etl:local`, ID `sha256:0049b1139641ad01a8e3f43802773641f0b926b6a6a6c84d4d9160443b1d286a`. Контейнер одноразовый: `--network=none --read-only --memory=1800m --cpus=2`, raw и код смонтированы только для чтения, единственный writable mount — новый `.runtime` эксперимента. БД и volumes приложения не подключались. MapLibre 6.12.0 скопирован из существующего node-контейнера вместе с BSD-лицензией; установки и сборки зависимостей не выполнялись.

Производные JSON, библиотека карты, скриншоты и протоколы находятся в `.runtime/`, игнорируемом новым `.gitignore` **внутри эксперимента**. Корневой `.gitignore` не менялся. Подготовка требует отсутствующего выходного каталога и отказывается его перезаписывать. HTTP-сервер не запускает подготовку автоматически и не предоставляет операций записи.

## Источник и метод

Использован только ранее сохранённый OSM PBF:

| Параметр | Значение |
|---|---|
| Файл | `data/raw/osm_pbf/2026-10-19-geofabrik/siberian-fed-district-261018.osm.pbf` |
| SHA-256 | `25c716a36131aab2e99802feca29d44495b80303d37e1d46eddc2a36f211863e` |
| Версия базы из заголовка | `2026-10-18T20:25:06Z` |
| Дата наблюдения | Неизвестна; `observed_at=null`, `freshness=UNKNOWN` |
| Сервисная граница | Прежний `boundary.geojson`, SHA-256 `0a631518e68855b2eba44a72429b9a11fa95e0de075c013f523eafa4b84ef5f8` |
| Область отбора | Bbox сервисной геометрии с запасом 0,03° долготы / 0,02° широты: `[92.0863489,55.8918405,93.2817693,56.1803241]` |

Граница используется как существующее ограничение территории, а не источник названий населённых пунктов. Магазины, адреса и уличные линии извлечены заново из PBF в отдельный PoC-файл; адресные/строительные JSON и рабочая БД не были источниками PoC. Нового скачивания PBF, Overpass-запросов и геокодирования не было.

Два прохода: сначала метаданные продуктовых relations и их member IDs, затем восстановление всех необходимых координат через дисковый `sparse_file_array`. Способ соответствует уже используемому в проекте принципу полного дискового индекса. Ways восстанавливаются **до** географического отбора, включая вершины вне города и окон аудита. Проверяется bbox целой геометрии, объекты не обрезаются. Временный индекс удалён после подготовки.

Выход содержит **708 продуктовых элементов** в области отбора: 546 node и 162 way; это не число магазинов Красноярска. Типы геометрии — 546 Point и 162 Polygon. Во всём PBF найдено 19 relations с этими продуктовыми тегами; они собраны без зарегистрированных ошибок, в область отбора не попали. Это не гарантия пригодности произвольных будущих relations.

Для карты подготовлено 9 913 уличных линий выбранных типов. Внешних тайлов, геокодеров, шрифтов и декоративных POI на карте нет. Это упрощённая карта для проверки объектов; отсутствуют фон зданий, вода и названия улиц. Ориентация и оценка пешего доступа по ней ограничены.

В отдельном каталоге **37 094 адресных элемента** с улицей/местом и номером дома, чья служебная точка находится в сервисной геометрии. Для node это исходная точка; для контура — центроид внутри полигона, иначе граничная вершина. Это не вход. Повторяющиеся подписи сохраняются с разными OSM ID, выбор явный. Отсутствующий исходный город не дописывается. Экспериментальный поиск не заменяет поиск основного PlaceLens и не удостоверяет жилое назначение объекта: например, выбранный для проверки `node/2332693473` одновременно является продуктовым POI с адресом Борисевича, 22.

Расстояние считается до точки либо ближайшей части полной геометрии в локальной сферической азимутальной равнопромежуточной проекции **AEQD**, центр — выбранная адресная точка, радиус сферы **6 371 008,8 м**. Между спроецированными вершинами — отрезки; внутри полигона расстояние нулевое. Радиус фильтруется до округления. Это метрическая модель PoC, а не эллипсоидальный расчёт PostGIS geography, маршрут или расстояние до входа. Пограничная точность относительно эллипсоида не измерена; перенос формулы в основной продукт не утверждён.

Для **всех 37 094 выбираемых адресов** проверено, что консервативный bbox круга 500 м помещается в область отбора. Это проверка пространственного запаса, не полноты OSM. Для семи контрольных адресов предварительный bbox-фильтр также сверен с расчётом по всем 708 геометриям: пропущенных подходящих элементов нет. Дистанции выбранных Point независимо сопоставлены с формулой haversine той же сферической модели, расхождение менее `0,00001 м`; это проверка реализации модели, не её геодезической точности.

### Возможный дубль и ошибки интерпретации

На Свердловской, 61Г [node/1817554654](https://www.openstreetmap.org/node/1817554654) без имени (`shop=convenience`, изменение 06.08.2012) расположен внутри [way/170583063](https://www.openstreetmap.org/way/170583063), «25 часов» (`shop=convenience`, изменение 14.05.2019). Оба элемента входят в результаты **обоих** радиусов и сохраняют отдельные строки и геометрии. Это **кандидат на дубль**, не подтверждённое соответствие одной торговой точке: слияния нет, работа на текущую дату не удостоверена.

Дополнительная неоднозначность исходных тегов: `way/468616492` имеет имя «Теле2», но отобран по `shop=convenience`. Несоответствие ожидаемому смыслу имени — повод ручной проверки; по одному имени нельзя автоматически объявить ошибку или заменить категорию. Фильтр PoC не меняет заранее согласованные правила после просмотра результата.

На Молокова, 28 в 500 м найдены несколько «Пятёрочек» и «Фасолей» с разными ID. Их принадлежность одной сети не является основанием объединения. У многих элементов нет адреса или имени; ближайший дом не присваивается автоматически. Время изменения даже в 2026 году не принимается за дату проверки текущей работы.

## Проверки и доказательства

Выполнены только проверки нового эксперимента:

- **10 Python-тестов — успешно.** Независимый аналитический пример AEQD, оба круга в Красноярске, полигоны с отверстиями, геометрия, содержащая окно без вершин внутри, край полигона при внешнем центроиде, фильтрация до округления, отсутствие слияния разных ID, пустое состояние, реальные адреса и восстановление 11 ways.
- `verify_snapshot.py` — **7 реальных адресных случаев × 2 радиуса**, повтор прежних окон, проверка запаса области для всех адресов, сравнение предварительного отбора с полным перебором и независимая формула Point-дистанций.
- **Браузер: 16 состояний сравнения**, существующий Chrome/Playwright с временным профилем. Явный выбор двух адресов клавиатурой; 7 пар на 300/500 м; прямой URL; мобильный режим. Во всех состояниях сравнивались ID ответа, строки DOM, GeoJSON-источника карты и **реально отрисованных features**. Наборы совпали.
- При изменении текста адреса старые список и карта очищаются; до нового явного выбора расчёт недоступен. Проверены пустая поисковая выдача, пустые продуктовые результаты, выделение строки/объекта и наличие ссылок для каждого ID. Неверные адресные ID и радиус 400 м дают HTTP 400.
- В браузерной проверке **0 внешних запросов, 0 ошибок браузера**. Ссылки OSM проверены как ссылки, их страницы автоматически не открывались. Основные API PlaceLens не вызывались.
- Визуально просмотрены desktop **1380×1050** и mobile **390×844**; горизонтального переполнения на мобильном нет. Это не полный аудит доступности.
- Синтаксис `app.js` проверен существующим Node-контейнером. `git diff --check` пройден; новые текстовые файлы дополнительно проверены отдельно. Миграции, импорты в БД и тесты основного приложения не запускались.

Подготовка заняла **323,80 с**, peak RSS **1 803 776 КиБ**; временный индекс удалён. Это локальный замер одной подготовки, не оценка производительности будущего продукта.

## Ограничения и решение после PoC

Подтверждена техническая возможность показать одинаковые локальные результаты на карте и в списке. **Не подтверждены** реальная полнота продуктовой сети, работа на текущую дату, ассортимент, цены, часы, доступный вход, возможность пройти через ограждения и полезность для людей, выбирающих жильё. Натурных проверок, звонков и интервью не было. Ноль не означает отсутствие магазинов.

Кольца relations соединяются по общим node refs; неподдерживаемые роли/типы и неоднозначная сборка дают явный отказ/запись об исключении. Это не универсальная проверка валидности полигонов и не исправление исходных геометрий. Случай успешной сборки 19 relations не снимает необходимость проверки будущих данных. Поиск, геометрический метод, модель площадки, правила подтверждения дублей и публичная методология требуют отдельного решения перед возможной интеграцией.

## Сохранность рабочего дерева и остановка

До работы сохранены хеши/размеры **682 существовавших файлов**, включая код, документы и raw; исключены `.git`, `vendor`, `node_modules`, `storage`. В окончательной сверке **681 файл побайтно неизменен**; изменился только игнорируемый служебный `.idea/workspace.xml`. PoC его не редактировал и не восстанавливал, источник изменения не устанавливался. Сравнение статусов Git сохраняет все прежние изменения пользователя; добавлены только каталог эксперимента и этот отчёт. Коммитов нет.

Доступа к основной БД, SQL, миграций или импорта со стороны PoC не было. Утверждение относится к действиям этого задания, а не к отсутствию возможной внешней активности работающих сервисов. Все исходные наборы сохранены по хешам.

**Работа завершена на PoC и отчёте.** К основному продукту ничего не подключено. Дальнейшая проверка с пользователями, ручная верификация торговых точек и интеграция требуют следующего отдельного решения.
