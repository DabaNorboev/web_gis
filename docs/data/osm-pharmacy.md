# Розничные аптеки OSM: срез А8

Отдельный подготовленный `pharmacy`-снимок для [анализа места](../features/place-analysis.md#5-блок-poi). Подключён в локальном рабочем окружении проекта: **pharmacy snapshot 15**, 158 записей; grocery snapshot 14 и остальные наборы сохранены. Публичного деплоя нет. Официальные остановки, парки, спутники и воздух не подключаются.

## Категория

Входной положительный признак — точный `amenity=pharmacy`: розничная аптека. `healthcare=pharmacy` без него, `shop=chemist`, `shop=medical_supply`, косметика, медицинские учреждения и торговые автоматы не включаются. Название/бренд не заменяют тег. `dispensing=no` не исключает розничную аптеку: отсутствие отпуска рецептурных лекарств не означает отсутствие аптечного ассортимента. Значение сохраняется в исходных тегах; API не обещает наличие рецептурного отпуска или конкретных лекарств.

Исключены явные `access=private|no` (непубличные/внутренние объекты), lifecycle-флаги `disused|abandoned|demolished|razed|construction|proposed|removed|closed` и соответствующие `*:amenity`, `*:healthcare`, `*:shop`, кроме значений `no|false|0`. `access=customers` допустим; неизвестный доступ остаётся null. Отсутствие флага закрытия не доказывает работу аптеки. Теги OSM не подтверждают лицензию, ассортимент, режим работы, вход или пешеходную доступность.

## Общие механизмы и независимость

Переиспользуются [строгий grocery pipeline v2](osm-grocery.md#метаданные-входа-и-запрет-неполной-публикации), восстановление полной геометрии, `DatasetCoverage`, структурные aliases, диагностика relations и атомарная транзакция публикации. Grocery-параметры и совместимость его сохранённого v2-входа не изменены. Аптечные параметры заданы отдельными reader/preparation/importer и provider; таблица `osm_pharmacy`, ключ набора `pharmacy`, advisory lock и активный снимок независимы от grocery.

- Геометрия: полные Point/Polygon/MultiPolygon4326 без clipping/repair; точное пересечение с сервисной границей при импорте. Отбор 200–1000 м и `distance_m` — по полной геометрии через geography; граница включена, окончательная проверка `ST_Distance <= radius`. Точка метки `ST_PointOnSurface` не является входом и не ограничивает отбор.
- Scope: `schema_version=2`, `dataset_key=pharmacy`, `categories=[pharmacy]`, точные `rules={pharmacy:{amenity:[pharmacy]}}`, все `node|way|relation`. Обязательны SHA PBF/границы/producer/общих помощников; дополнительный `retail_script_sha256` фиксирует общий скрипт grocery. `ST_Equals` проверяет геометрию bbox-фильтра, `ST_Covers` — всю объявленную область данных. Узкая область, неизвестный метод/метаданные или неправильная категория отклоняются, COVERED и ложный ноль им не присваиваются.
- Каждый выбранный relation получает emitted, доказанно outside или rejected. Node-only/nested-only, отсутствующий member, неподдержанная геометрия с неизвестным положением блокируют публикацию: диагностика не разрешает пропуск. Только полный envelope way-членов, доказанно вне extraction, допускает безопасное внешнее исключение.
- Identity — `osm:type:id`, независимо от версии/названия. Равная полная геометрия, равные теги кроме type и явное outer-членство позволяют структурный alias way → relation. Разные ID только по близости/имени не объединяются; возможные node/area-дубли сохраняются отдельно с `identity_note`. Счётчик — число найденных записей набора, не гарантированное число уникальных действующих аптек.
- Если один OSM ID присутствует в обоих доступных снимках, в объединённом ответе остаётся один объект с категорией pharmacy (приоритет явного аптечного тега); счётчики пересчитываются по возвращённым записям. Это не объединение разных ID и не изменение сохранённых снимков.
- Категории читаются в отдельных транзакциях. Отсутствующий/упавший pharmacy не скрывает grocery и наоборот: `availability_by_category` различает READY, UNAVAILABLE и ERROR; неизвестное покрытие и count=null не превращаются в ноль. Если нет ни одного результата и есть ошибка — блок ERROR; если все источники недоступны — UNAVAILABLE. Карта/список используют реальные геометрии/ID, фильтр аптек, связанный выбор и отдельные сообщения состояния; fallback на demo/прежний профиль отсутствует.

## Воспроизведение и подключение

Входы те же локальные, что у grocery: сохранённый PBF Geofabrik `siberian-fed-district-261018.osm.pbf`, SHA `25c716a36131aab2e99802feca29d44495b80303d37e1d46eddc2a36f211863e`, и сервисная граница городского округа Красноярск OSM relation 1157393, SHA `0a631518e68855b2eba44a72429b9a11fa95e0de075c013f523eafa4b84ef5f8`. Внешнего буфера нет: возле края круга честный PARTIAL, список неполный, полный count=null.

Запуск из корня, output каждый раз **новый**; существующие входы/выходы не перезаписываются:

```bash
docker run --rm --network=none --read-only --memory=1800m --cpus=2 \
  --user "$(id -u):$(id -g)" -e PYTHONDONTWRITEBYTECODE=1 \
  -v "$PWD/data/raw:/input:ro" -v "$PWD/scripts:/scripts:ro" \
  -v "$PWD/data/prepared/pharmacy:/output:rw" -w /scripts \
  web-gis-osm-etl:local python /scripts/prepare-osm-pharmacy.py \
  /input/osm_pbf/2026-10-19-geofabrik/siberian-fed-district-261018.osm.pbf \
  /input/boundaries/krasnoyarsk/2026-10-07/boundary.geojson /output/NEW_DIRECTORY \
  --expected-pbf-sha256 25c716a36131aab2e99802feca29d44495b80303d37e1d46eddc2a36f211863e \
  --source-url https://download.geofabrik.de/russia/siberian-fed-district-261018.osm.pbf
```

Успешный output: `pharmacy.json`, `manifest.json`, `diagnostics.json`; версия OSM **18.10.2026 20:25:06 UTC**, observed_at=null, OpenStreetMap/ODbL-1.0. Дата подготовки не является наблюдением. Команды подключения — миграция `2026_11_05_000001_create_osm_pharmacy_table` и `osm:import-pharmacy FILE --boundary=BOUNDARY --expected-sha256=SHA`; 05.11.2026 они выполнены по явному разрешению владельца в локальной БД `db` сервиса Compose `db`. Публикация атомарная; отказ, включая позднюю ошибку активации, сохраняет прежние снимки и coverage. Повтор checksum+configuration идемпотентен. Актуальная сборка подключена после сохранения прежней в резервной копии.

## Локальная рабочая активация

05.11.2026 по явному разрешению владельца применена только аптечная миграция и атомарно активирован **снимок 15**, checksum `1b10efaf10a0546a9f36a44756b1a4b9f65184c07e44f51fe4050d016fbad583`. Принято 158 записей, 5 кандидатов вне сервисной границы, возможных/структурных дублей нет. Рабочий grocery №14 остаётся активным с 663 записями; контрольные суммы его строк, configuration/result и всех остальных активных наборов совпали до/после подключения. Старые inputs/outputs не перезаписывались.

До изменений подтверждено окружение Laravel `local`, БД `db`; аптечной таблицы и прежних pharmacy imports не было. Сверены SHA-256 подготовленного JSON, PBF, границы и трёх скриптов. В `data/backups/a8-pharmacy-activation-20261105-01/` сохранены dump затрагиваемых таблиц и grocery (`affected-tables.dump`, каталог прочитан `pg_restore -l`), прежняя сборка, исходная незакоммиченная работа, конфиги, контрольные суммы и точечная инструкция возврата (`RETURN.md`, `rollback.sql`). Возврат не применялся, поскольку подключение прошло успешно; restore БД не проверялся восстановлением поверх рабочей БД. Reset/fresh, удаление прежних наборов, commit/push и публичный деплой не выполнялись.

Frontend сначала собран в отдельный каталог, затем заменён `public/build`; прежний каталог сохранён как `replaced-public-build` и отдельная копия `public-build`. Конфиг Nginx совпал с подключённым bind mount репозитория; `nginx -t` прошёл. Конфиг не изменялся, reload не потребовался: применение защиты рабочими процессами подтверждено специфичным JSON Nginx 413 на синтетическое тело больше 8 KiB, а не только `nginx -T`.

Рабочий HTTP (`http://localhost`, Nginx/PHP) вернул для публичного OSM node/708811103 на Киренского, 21 три аптечные записи на 200 м и четыре на 1000 м; grocery-объекты и их поля совпали с ответами, сохранёнными перед активацией. Для публичной «Фармакопейки» node/12096761683 подтверждены COVERED на 200 м и PARTIAL на 1000 м с реальной аптечной записью, count=null. Остановки/парки остаются UNAVAILABLE с null, спутник/воздух — UNAVAILABLE; demo-ID и подстановок нет. Некорректный синтетический JSON дал безопасный 422, в ответах no-store/no-referrer; синтетический маркер отсутствует в журналах Laravel/Nginx.

Отказ чтения проверен через тот же рабочий HTTP краткой транзакционной `ACCESS EXCLUSIVE`-блокировкой только `osm_pharmacy`, без изменения строк. Сработал установленный lock_timeout provider: pharmacy получила ERROR/UNKNOWN/count=null, grocery №14 сохранил READY и свои записи. Блокировка освобождена ROLLBACK, повторный HTTP подтвердил READY аптек. Это контролируемый probe отказа; падения сервиса и изменения рабочих геоданных не было.

В Chromium на опубликованной странице без API-fixtures проверены поиск и выбор «Киренского 21», реальные аптеки/продукты, радиусы 200/1000 м с обновлением круга, выбор список → карта и карта → список, переключение категорий без повторных запросов/потери результатов, очистка меток для неподключённых остановок. Аптечные объекты связаны со снимком 15, grocery — с 14; ошибок страницы нет. Контейнерный браузер использовал временный HTTP pass-through к рабочему Nginx/PHP для доступа к localhost, без подмены ответов. Ответы, сводки и снимок экрана сохранены рядом с резервной копией.

Ручная проверка: `http://localhost/analysis` → поиск «Киренского 21» → «Объекты» → «Аптеки». Официальные остановки и парки остаются неподключёнными; весь А8 не закрыт. Полнота OSM, фактическая работа аптек и ассортимент не подтверждены; внешнего буфера нет, у края PARTIAL. Хранение/обмен/восстановление после reload этим подключением не добавлены.
