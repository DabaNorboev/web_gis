# Офлайн-выпуски спутниковых слоёв А9

Реализована офлайн-подготовка однотайловых окон schema 2 и городского выпуска schema 3; HTTP-provider А10.2 подключается только явной конфигурацией; UI и рабочая активация отдельны. Команда [prepare-satellite.py](../../scripts/prepare-satellite.py) не использует сеть, HTTP приложения или БД. [Закреплённый рецепт](../../config/satellite/2024-08-15-tatyshev.json) содержит относительные локальные пути, размеры, SHA-256 и источники всех входов: COG B04/B08/SCL/TCI (полные или явно закреплённые native-вырезки), исходные B04/B08 JP2, XML продукта/гранулы, STAC selection и свидетельство радиометрии. Они находятся в ignored `data/reports`, не поставляются чистым checkout; отсутствующий/изменённый вход останавливает подготовку до создания выпуска. [Версии зависимостей](../../config/satellite/requirements.txt) соответствуют переиспользованному изолированному runtime, автоматической установки нет.

Из корня проекта, с сохранёнными входами; для повтора выбрать **новое** имя каталога:

```bash
PYTHONPATH=data/reports/source-feasibility/2026-11-03-radiometry-01/python-libs \
python3 -B scripts/prepare-satellite.py \
  --config config/satellite/2024-08-15-tatyshev.json \
  --output data/satellite/releases/2024-08-15-tatyshev-replay-01
```

`--input-root` задаёт корень перенесённых входов (по умолчанию текущий каталог). Только локальные относительные пути внутри него. Существующий output не перезаписывается; manifest создаётся последним. Каталог без manifest — незавершённый выпуск, непригодный для подключения. Выпуск не активируется автоматически.

Ограниченное окно Татышева — 630 × 748 native-пикселей, 6,30 × 7,48 км, EPSG:32646; не весь город. Идентичности и точные времена исходной гранулы — в manifest закреплённого рецепта. Дата наблюдения не заменяется временем подготовки; облачность tile не описывает круг места.

Метод `placelens-s2-date-v1`, маска `scl456-dn-v1`:

- B04/B08 читаются как uint16 DN в native-сетке 10 м без resampling; входы обязаны совпадать по CRS, extent, transform и reader scale=1/offset=0. TCI — исходное трёхканальное отображение B04/B03/B02 поставщика, без новой растяжки и без использования в расчёте NDVI. Это цветное изображение, не количественное отражение.
- Радиометрия: на закреплённых входах подтверждено `COG=max(JP2−1000,1)` с сохранением нуля; применяются scale=0.0001/offset=0 один раз. XML продукта/гранулы, identity и JP2 проверяются для каждого нового выпуска; оконное доказательство не становится полным автоматически. Saturated без подтверждённой кодировки блокирует выпуск, DN1 неизвестен. Независимый NDVI по JP2: `(JP2_B08−JP2_B04)/(JP2_B08+JP2_B04−2000)`, допуск float32 6e−8.
- NDVI `(rho_B08−rho_B04)/(rho_B08+rho_B04)` безразмерен, диапазон −1…1; непригодное — float32 nodata −9999, никогда не нулевой отклик. Исходные DN 0 — nodata, 65535 — saturated, COG DN=1 неоднозначен после clipping и исключён, даже если JP2 позволяет уточнение.
- SCL переносится с 20 на точную сетку 10 м только nearest. Пригодны SCL 4/5/6, включая воду, при обычных B04/B08 и допустимой арифметике. Нет буфера облаков и подбора порогов. Взаимоисключающий приоритет: nodata → DN1 → saturated → SCL3 → SCL8/9/10 → SCL7 → SCL2 → SCL11 → SCL1 → неизвестный SCL → численный отказ; коды/имена записаны в manifest. Ноль в reason-raster означает **пригодно**, nodata этому слою не назначается. Маргинальный DN1 сохраняется отдельно от приоритетных причин.
- Географическая маска — ненулевые B04, B08 и SCL; пригодная — reason=0. Маски uint8 0/1, ноль является известным отсутствием покрытия/пригодности. Их EPSG:4326 GeoJSON — полигоны объединённых пикселей, без упрощения; координаты `lon, lat`. В schema 2 `coverage.scope=prepared_window`, `geographic_fraction` — доля ненулевых исходных данных внутри **полного окна выпуска**, не доля футпринта сцены и не круга места; А10 отдельно вычисляет покрытие круга, не экстраполируя пригодную часть. TCI nodata=0 остаётся независимым от NDVI.
- Общая легенда `ndvi-fixed-v2`: числовые интервалы `[−1,−.2,0,.2,.4,.6,.8,1]`, нижние границы включены, верхние исключены, последнее 1 включено; границы сравниваются в точности хранимого float32 NDVI (включая −0,2), цвета закреплены в `legend.json`. Неизвестное прозрачно в RGBA; это не низкий NDVI. Легенда не классифицирует процент растительности или здоровье деревьев.

Формат офлайн-выпуска для последующего чтения А10: tiled/DEFLATE GeoTIFF на единой EPSG:32646 сетке, без overviews: `true-color.tif` (uint8 RGB), `ndvi.tif` (float32), `ndvi-rgba.tif`, `scl.tif`, `exclusion-reason.tif`, `geographic-mask.tif`, `usable-mask.tif`. Дополнительно `geographic-coverage.geojson`, `usable-coverage.geojson`, `scene.json`, `recipe.json`, `legend.json`. `manifest.json` schema_version=2/status=`prepared_offline` связывает scene/product/date, grid/resampling, радиометрию, маску, легенду, входы и assets с SHA-256/размером/nodata/типом, версии ПО и hash скрипта, hash сохранённого `recipe.json` (`recipe_sha256`) и исходного файла рецепта (`source_recipe_sha256` в новых выпусках), независимую численную проверку, время подготовки и сумму размеров файлов **без самого manifest**. Финальный размер каталога измеряется отдельно. Численные значения и геометрия воспроизводимы; created_at/время/пути нового выпуска не обещают побайтового совпадения manifest. URL и формат доставки определяет А10.

Ограничения: смешанные пиксели 10 м, качество SCL независимо не оценено, неизвестная часть не означает отсутствие растительности. Нет процентов растительности, ежегодных композиций, разностей лет, порогового кандидата или полевых обещаний. У прежней однотайловой команды сохраняется предел 4 млн пикселей окна; городской путь ниже обрабатывает отдельные блоки и не повышает этот предел. Ограниченный набор А9.3 пригоден для последующего чтения А10, но не подтверждает готовность целевого городского набора. Согласованное расширение выполняется отдельными шагами [А9.4–А9.6](../plans/roadmap.md#городские-спутниковые-выпуски-а94а96); городские выпуски 06.06 и 09.09.2026 описаны ниже. Работающий сервер этим этапом не проверяется.


При чтении legacy schema 1 поле `coverage.scene_fraction` следует понимать только как нынешнее `geographic_fraction` внутри окна: это прежнее неоднозначное имя, не покрытие исходной сценой. Исходный футпринт сцены сохранён в `scene.json.geometry`, extent подготовки — в `grid`/`native_bounds`; за ним нет подготовленного NDVI, даже когда сцена там есть. Для круга знаменатель — все его native-пиксели, включая неприготовленную часть; outside-prepared, nodata внутри и исключения маски учитываются отдельно. Недоступное численное значение — null, не ноль. Будущий reader А10 не должен переносить оконные доли на круг.

Ограниченный [review-satellite.py](../../scripts/review-satellite.py) читает выпуск и закреплённые входы без изменения, создаёт только новый каталог свидетельств: проверку происхождения/hashes/сеток/численного утверждения JP2, восемь кругов 200/1000 м и PNG совмещённых контрольных окон с легендой. Круги используют центры пикселей и документированную EPSG:32646 для радиуса, футпринт сцены — из STAC; это не проверка качества данных во всей сцене. Диагностическая SCL-палитра не является независимым эталоном, NDVI-слой накладывается на шахматный фон только для просмотра прозрачности. Нужен уже доступный Pillow; пакеты не устанавливаются. Из корня проекта:

```bash
PYTHONPATH=data/reports/source-feasibility/2026-11-03-radiometry-01/python-libs \
python3 -B scripts/review-satellite.py \
  --release data/satellite/releases/2024-08-15-tatyshev-a9-2-v2 \
  --output data/satellite/reviews/a9-2-replay-01
```

Старая легенда v1 в сохранённых выпусках использовала float64 границы при float32 значениях: ровно −0,2 мог отображаться предыдущим цветом. v2 исправляет представление границ без изменения порогов, численного NDVI, масок или радиометрического метода. Прежние выпуски остаются неизменными; для дальнейшего предметного чтения используется исправленный release `2024-08-15-tatyshev-a9-2-v2`, не рабочая активация.

## Ограниченный набор дат А9.3

Три даты на **одном прежнем окне** 630 × 748 пикселей EPSG:32646, без расширения территории. Рецепты: [28.06.2024](../../config/satellite/2024-06-28-tatyshev.json), [26.07.2024](../../config/satellite/2024-07-26-tatyshev.json), [15.08.2024](../../config/satellite/2024-08-15-tatyshev.json). Это отдельные наблюдения, без композиции или анализа изменений. Метод, маска и легенда v2 общие; маски/пригодность конкретных дат сохраняются разными.

`input_layout=native_window` допускает только pinned вырезки на исходной JP2-сетке и собственное оконное доказательство; не разрешает обработку остальной сцены. DN=0 неизвестен даже при nodata=None. Полная исходная SCL переносится nearest; подготовленная исследовательская маска не подменяет вход. `full_tile` требует полного доказательства. Метод/маска от layout не меняются.

Минимальный локальный индекс `data/satellite/tatyshev-2024-summer-v1.json` — явный список трёх выпусков для будущего А10, не активация приложения. Индекс schema 1/status=`validated_offline_set` хранит общие grid/версии/scope, а для каждой даты — scene_id, release_id, относительный путь к manifest, SHA-256 и версии метода/маски/легенды. Пути отсчитываются от каталога индекса, поэтому весь `data/satellite` можно перенести вместе. Большие входы и выпуски ignored; наличие JSON-рецептов в Git не делает набор доступным в чистом checkout.

[index-satellite.py](../../scripts/index-satellite.py) проверяет явно перечисленные manifest, обязательные assets, sizes/hashes, identity, grid/types/nodata, версии и покрытие; затем пишет только новый индекс. Дубликат даты, несовместимость и пустое пригодное покрытие блокируют готовность.

Офлайн-повтор двух новых дат и индекса из корня проекта; output-имена должны быть новыми. Исправленный августовский выпуск переиспользуется:

```bash
export PYTHONPATH=data/reports/source-feasibility/2026-11-03-radiometry-01/python-libs
for observation_date in 2024-06-28 2024-07-26; do
  python3 -B scripts/prepare-satellite.py \
    --config "config/satellite/${observation_date}-tatyshev.json" \
    --output "data/satellite/releases/${observation_date}-tatyshev-replay-01"
done
python3 -B scripts/index-satellite.py \
  --manifest data/satellite/releases/2024-06-28-tatyshev-replay-01/manifest.json \
  --manifest data/satellite/releases/2024-07-26-tatyshev-replay-01/manifest.json \
  --manifest data/satellite/releases/2024-08-15-tatyshev-a9-2-v2/manifest.json \
  --output data/satellite/tatyshev-2024-summer-replay-01.json
```

Офлайн-замеры отделяют загрузку, подготовку после импорта библиотек и полный процесс `/usr/bin/time -v`; это не бюджет HTTP и не воспроизведение на другой машине.

## Первый городской выпуск А9.5: schema 3

[prepare-satellite-city.py](../../scripts/prepare-satellite-city.py) и [satellite_city.py](../../scripts/satellite_city.py) добавляют отдельный блочный путь. Однотайловые recipes/releases schema 2, их маски и прежний индекс не переписываются. [Июньский рецепт](../../config/satellite/2026-06-06-city.json) закрепляет hash нового `inputs-manifest.json`; тот связывает точные продукты, оба времени гранул/каталога, source URL, размеры и SHA-256 всех реально использованных COG/JP2/XML/SCL, а также manifest подбора А9.4, target и исходную границу.

На дату используются два продукта 46VDH/46VEH одного datatake; полные identity и времена гранул закреплены manifest, не заменяются временем подготовки. Acquisition принимает только даты pinned selection: пару 2026 и сезонные окна 2024–2025; произвольная дата/подмена продуктов запрещены.

Target побайтово сохраняет А9.4: OSM relation 1157393 v72, снимок 07.10.2026, буфер 1000 м в EPSG:32646; hash target `2c1c7cbafd784e9b737ff3f3e32d9864e62d898e452e33c15f140f3aab365158`, исходной границы `0a631518e68855b2eba44a72429b9a11fa95e0de075c013f523eafa4b84ef5f8`. Это OSM-граница городского округа, не юридическая кадастровая. Подготовленная прямоугольная сетка: EPSG:32646, transform `[10,0,443890,0,-10,6224970]`, 7281 × 2970 пикселей; геометрия target занимает только часть прямоугольника.

Чтение, вычисления, проверка и запись выполняются блоками не более 512 × 512 пикселей. Окно источника обрезается до его extent перед чтением; массивы полного города/JP2 не создаются. GDAL cache — 32 MiB, один поток GDAL/OpenJPEG. Геометрии — только небольшой target, граница, прямоугольник и два футпринта; полная векторизация пригодной маски не выполняется. Рецепт задаёт бюджет пика памяти (768 MiB у июня), проверяемый по Linux `ru_maxrss` после каждого блока; превышение препятствует публикации manifest. Это контроль реального пика процесса, включая библиотеки/кодеки, а не обещание об их внутреннем устройстве.

Тайлы сортируются по scene_id. На каждом native-центре пикселя выбирается **первый покрывающий футпринт**, независимо от SCL/NDVI и наличия более ясного соседнего тайла. Red, NIR, TCI, SCL и исходные JP2 берутся из одного назначенного продукта. Никакого усреднения, максимума NDVI или fallback на другой тайл при nodata. B04/B08/TCI читаются без resampling, SCL 20→10 м — nearest на точную сетку каждого блока. `source-tile.tif` фиксирует индекс; overlap подсчитывается отдельно, выбранный пиксель входит в итог один раз.

Радиометрическое правило выше проверяется для **каждого продукта на всех назначенных target-пикселях**, включая исключённые SCL. XML проверяет product/baseline/спутник/datatake/tile/время, quantification=10000, offsets B04/B08=−1000. Доказательство не распространяется на неназначенный overlap или остальную сцену.

Метод NDVI остаётся `placelens-s2-date-v1`, легенда — `ndvi-fixed-v2`, версия маски города — `scl456-dn-city-v1`, обработка — `city-block-v1`. Коды исключения 0–11 сохраняют смысл; 12 = вне target внутри прямоугольной сетки, 13 = target вне футпринтов. NDVI вне пригодной части — −9999, RGBA alpha=0. Цветное TCI исходное, вне подготовленного target обнулено; его отдельная маска доступности не приравнивается к пригодности NDVI.

Schema 3/status=`prepared_offline_city` хранит `scenes[]` вместо фиктивного общего scene_id, точные времена/идентичности и mapping source-индексов, радиометрическое доказательство по каждому продукту/каналу, версии, параметры сетки, hashes/размеры всех assets и входов, время/пик памяти. `manifest.json` пишется последним; существующий output запрещён. Неполный каталог не является готовым выпуском.

Выходы — tiled/DEFLATE GeoTIFF без overviews, на одной сетке: прежние `true-color.tif`, `ndvi.tif`, `ndvi-rgba.tif`, `scl.tif`, `exclusion-reason.tif`, `geographic-mask.tif`, `usable-mask.tif` и новые `target-mask.tif`, `footprint-mask.tif`, `source-tile.tif`, `tci-valid-mask.tif`. Дополнительно сохраняются `recipe.json`, `inputs-manifest.json`, `legend.json`, `target.geojson`, `boundary.geojson`, `source-footprints.geojson`, `prepared-grid.geojson`. Большого `usable-coverage.geojson` нет: для точного чтения используется растровая маска.

`coverage.scope=target_polygon_pixel_centers`: знаменатель — все native-центры 10 м внутри target, не bbox. Source/prepared/geographic/usable независимы по смыслу; поля круга описаны в [контракте](../features/place-analysis.md#6-блок-satellite), городские доли в него не подставляются. Target сохраняет приближение дуг буфера А9.4 до 0,076 м: у западной границы один из 31 410 центров теоретического круга 1000 м на 0,0182 м вне pinned target и остаётся неизвестным. Epsilon-допуск/расширение target запрещены; консервативный буфер требует нового согласованного release.

`index-satellite.py` понимает оба формата: прежний однотайловый индекс остаётся schema 1; городской индекс schema 2 использует `scene_ids[]` и городской scope, закрепляет SHA-256 manifest. Совместимость включает hash target, общую сетку, метод/маску/легенду и правило назначения источников. Разные охваты/схемы не объединяются молча. Городской индекс допускает до шести явно перечисленных выпусков; прежний однотайловый набор остаётся ограничен тремя. Июньский локальный индекс — `data/satellite/krasnoyarsk-2026-june-city-v1.json` — сохранён. Новый индекс двух дат — `data/satellite/krasnoyarsk-2026-city-v1.json`; он не активирует приложение.

Офлайн-повтор по сохранённым входам, из корня проекта (новый output обязателен):

```bash
OPJ_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
PYTHONPATH=data/reports/satellite-city/2026-11-05-a9-4-01/python-libs:data/reports/source-feasibility/2026-11-03-radiometry-01/python-libs \
python3 -B scripts/prepare-satellite-city.py --stage prepare \
  --config config/satellite/2026-06-06-city.json \
  --output data/satellite/releases/2026-06-06-krasnoyarsk-replay-01
```

Зависимости — Python 3.10, NumPy/Rasterio/GDAL, изолированный Shapely 2.1.2 из А9.4, Pillow для review/доставки; автоматической установки нет. Входы июня: `data/satellite/inputs/2026-06-06-city-a9-5-01/`; `config.json` закрепляет acquisition, `requests.jsonl` — размеры/hashes и ресурсы. Время загрузки измеряется отдельно от офлайн-подготовки; `/usr/bin/time -v` включает импорты, RSS указывается в Linux KiB.

Независимый полный контроль записанных растров — та же команда со `--stage review --release <release> --output <новый-каталог>`; он потоково проверяет все маски, alpha/легенду, исходные каналы, JP2-арифметику, target и назначение стыка, затем считает круги 200/1000 м внутри/на краю/вне/на стыке и создаёт ограниченные обзорные/контрольные PNG. ## Серверное чтение А10.1

[SatelliteCatalogReader](../../app/Services/Satellite/SatelliteCatalogReader.php) — PHP-модуль независимого satellite-provider. `forPoint(lon,lat,radius)` проецирует северную зону UTM46 через PostGIS (один SELECT, local statement timeout 500 ms); `forProjectedPoint(x,y,radius)` читает native-круг EPSG:32646, 200–1000 м. Это проекционный круг по центрам пикселей, не точное совпадение с geography-контуром карты. [Предметные поля](../features/place-analysis.md#6-блок-satellite) имеют одно основное место.

[prepare-satellite-runtime.py](../../scripts/prepare-satellite-runtime.py) офлайн проверяет индекс/manifest/assets и совместимость, не повторяя ETL/радиометрию, и копирует готовые NDVI/маски в новый runtime. Блок ≤256², запись 8 байт: little-endian float32 NDVI и uint8 reason/source/target/geographic. Значения/неизвестность сохраняются точно. Каталог содержит все сцены, проектированные футпринты, hashes блоков, исходного индекса и [отдельных предупреждений](../../config/satellite/catalog-metadata.json), привязанных к manifest. Исходные releases/индекс неизменны. TCI и доставка изображений в этот runtime не входят.

Доверенный SHA-256 `catalog.json` передаётся конструктору **из доверенной конфигурации оператора**, не берётся автоматически из соседнего изменяемого файла. На каждый вызов проверяется небольшой каталог; каждый затронутый блок читается один раз и хэшируется в памяти до использования. Проверки по size/mtime вместо hash нет; cache между запросами не добавлен. Неизменённый hash каталога не оправдывает изменённые байты блока. Непрочитанная порча обнаруживается при обращении к блоку либо офлайн `--verify <runtime> --sha256 <pin>`, проверяющем весь набор. Runtime следует монтировать read-only; смена метода, исходного набора или предупреждений требует нового каталога и нового доверенного pin. Это самостоятельный проверенный снимок: изменения исходных TIFF после копирования не перечитываются при запросе и не меняют уже закреплённые байты runtime.

Бюджет чтения всех шести дат: ≤16 MiB, четыре блока на дату при 1000 м, прирост PHP-памяти ≤32 MiB, проверяемое время ≤2 с. Дедлайн кооперативный между чтениями/строками, не прерывает зависший системный IO; проекция имеет отдельный бюджет. Нет сети, расчёта NDVI, полного хэширования GeoTIFF или Python/GDAL в запросе. Ошибка затронутого блока исключает дату из пригодных, возвращает null; доступные остальные даты сохраняются.

Runtime: `data/satellite/runtime/krasnoyarsk-2024-2026-a10-1-v1/`; pin `14c4c26cd9c057cd9e17cdc9182b9f2ae15a5a5881d4bd0e951b6760d750cd6b`. Подготовка: `python3 -B scripts/prepare-satellite-runtime.py --index data/satellite/krasnoyarsk-2024-2026-city-v1.json --metadata config/satellite/catalog-metadata.json --output <новый-каталог>` в описанных Python-зависимостях. Команды fixture/реальных проверок reader — [testing](../testing.md). Свидетельства А10.1: [verification.json](../../data/satellite/reviews/2026-11-06-a10-1-01/verification.json); не подтверждают HTTP/UI/рабочую активацию.
## Доставка и активация А10.2

[prepare-satellite-delivery.py](../../scripts/prepare-satellite-delivery.py) создаёт **новый** каталог PNG XYZ EPSG:3857, 256², z10–13: существующий MapLibre принимает обычный raster source без нового сервиса. Перепроекция nearest выполняется офлайн с tolerance 1e−9 native-пикселя; цвета легенды не интерполируются. Alpha TCI берётся из tci-valid-mask, NDVI — из подготовленного RGBA; маски независимы. Источники/NDVI в HTTP не рассчитываются. Увеличение масштаба выше z13 — overzoom, не дополнительная детализация. Исходные releases и runtime неизменны.

```bash
# Те же PYTHONPATH и зависимости, что у городской подготовки выше.
python3 -B scripts/prepare-satellite-delivery.py \
  --runtime data/satellite/runtime/krasnoyarsk-2024-2026-a10-1-v1 \
  --sha256 14c4c26cd9c057cd9e17cdc9182b9f2ae15a5a5881d4bd0e951b6760d750cd6b \
  --index data/satellite/krasnoyarsk-2024-2026-city-v1.json \
  --output <новый-каталог>
```

Бюджет satellite data ≤256 KiB; reader ≤16 MiB, кооперативные 2 с/прирост памяти 32 MiB, проекция 500 ms. Дедлайн не прерывает OS IO и не является жёстким timeout.

Каталог доставки связывает hash reader, manifest каждой даты, общую легенду, bounds и hash/size каждого PNG; `catalog.json` пишется последним. Приложение читает каталог ≤2 MiB и только запрошенный PNG ≤300000 байт; наружу не выдаются каталоги, TIFF, cells или пути. Hash проверяется по прочитанным байтам. Ошибка asset даёт безопасный 404/no-store; успешный PNG — image/png, nosniff, no-referrer и immutable cache. URL содержит pin/дату/слой/z/x/y, параметры места отсутствуют. Каталог/слои выбираются только из доверенной конфигурации, не из запроса.

Для явной активации: перенести reader и доставку целиком; независимо сверить SHA-256 обоих catalog.json и legend; смонтировать каталоги read-only для PHP; явно задать `SATELLITE_RUNTIME`, `SATELLITE_RUNTIME_SHA256`, `SATELLITE_DELIVERY`, `SATELLITE_DELIVERY_SHA256`. Pins передаются из доверенной конфигурации оператора; файл рядом с runtime не является источником доверия. Затем применить конфигурацию штатным способом, проверить POST/PNG в целевом FPM/Nginx и его privacy-логи/заголовки. Для выключения убрать конфигурацию, сохраняя данные. Исследовательского fallback нет; UI подключается актуальной сборкой. Тестовый HTTP-процесс не проверяет рабочий Nginx/FPM.

Fixtures, реальная доставка и HTTP проверяются раздельно: [команды testing](../testing.md#спутниковый-http-и-доставка-а102), [свидетельства А10.2](../../data/satellite/reviews/2026-11-06-a10-2-01/). Полный ETL/review А9 и набор А10.1 для изменения HTTP не повторяются.
