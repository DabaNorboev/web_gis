# Воздух: офлайн-вход и файловый снимок

Офлайн-вход А11.1 и независимый файловый importer А11.2, без подключения приложения, БД, активации или миграций. Семантика локального API А12 — [air-контракт](../features/place-analysis.md#7-блок-air); ближайшая очередь — [roadmap](../plans/roadmap.md#ближайшая-очередь). Полный паспорт датчика не является условием ограниченного показа наблюдений станции: неизвестные QC, история оборудования и координат остаются явными ограничениями.

## Минимальный вход v1

- `manifest.json`: `schema: placelens.air-input.v1`, назначение, `prepared_at`, исходное окно, timezone/offset null, inventory с относительными путями, размерами, SHA-256. `prepared_at` — время подготовки пакета; `origins[].retrieved_at` и `access/requests.jsonl` — время HTTP-получения, `server_date`/`date` — HTTP Date. Ни одно из них не становится временем наблюдения.
- `stations.json`: namespace `air.krasn.ru/project/9` + строковый ID источника, имя, исходные координаты и ссылка на raw/ID, неизвестные CRS/даты/статус/истории с причинами. Не создавать идентичность по имени и не объединять разные ID по близости.
- `observations.jsonl`: одна строка на возвращённое наблюдение PM2.5; `station_id`, `observed_at_raw` точно из API, `indicator: pm2_5`, `source_field: pm25`, `aggregation: hourly`, `value`, `unit: µg/m³`, `row_present`, `missing_reason`, `qc`, `qc_raw`, `qc_reason`, ссылка `raw_file` + нулевой `raw_index`. `timezone`, `utc_offset`, `observed_at_utc` — null с `SOURCE_TIMEZONE_UNCONFIRMED`.
- `raw/`: исходные ответы справочника и недели, сохранённый help оператора и точная вырезка публичного JS, связывающая `pm25` с PM2.5 и мкг/м³. `client-excerpt.json` содержит byte offset/length и hash/размер полного старого JS; полный JS остаётся в прежнем запуске. `origins.json` — исходные параметры/происхождение; `checks.json` — проверенные свойства именно этого набора.

В v1 отсутствующие строки не материализуются как измерения. При построении сетки importer/reader различает отсутствие строки (`SOURCE_ROW_MISSING`) и исходное отсутствующее/null значение (`SOURCE_VALUE_NULL_OR_ABSENT`); оба дают null, не 0. `row_present: false` допустим только для явно производной сетки, без выдуманной ссылки на исходную строку. Числовой 0 сохраняется как доступное значение. Нечисловое/нефинитное значение не приводится к числу молча.

`hourly` означает запрошенный `time_interval=hour`, без обещания алгоритма усреднения/границ аппаратного интервала. Наивная строка времени сохраняется буквально; нет добавления `Z`, UTC+7 или timezone по расположению станции. Без подтверждённого timezone нельзя обещать возраст значения относительно текущего UTC, freshness остаётся UNKNOWN.

Единицы подтверждены сохранённым `help.html` и mapping публичного клиента; справочник project 9 сам не содержит соответствующего индикатора PM2.5. Соседние `pm10`, `pm25_mcp`, AQI и температура не импортируются как PM2.5 и не становятся QC. В raw недели поля `time, site, t, h, p, aqi, iaqi, pm25, pm10, pm25_mcp`; QC-флагов нет: `qc_raw: null`, `qc: UNKNOWN`, причина `SOURCE_QC_NOT_PROVIDED`. 336 сопутствующих температур равны −42,5 °C: это ограничение доверия к источнику, не основание автоматически исправить/обнулить PM2.5 или объявить его VALID/SUSPECT.

## Импортер А11.2 и снимок v1

Команда [import-snapshot.py](../../scripts/air/import-snapshot.py) использует только стандартную библиотеку Python 3, без сети, БД и внешних библиотек. Для нового снимка:

```sh
python3 -B scripts/air/import-snapshot.py \
  --input tests/Fixtures/air/a11-1-v1 \
  --output data/air/snapshots/new-snapshot
```

Адаптер v1 ограничен namespace `air.krasn.ru/project/9`, PM2.5/`pm25`, единицей `µg/m³` и исходными часовыми строками. Namespace и строковый ID не переименовываются. Он проверяет schema и обязательные файлы manifest, уникальность inventory, размеры/SHA-256, отсутствие неперечисленных файлов, абсолютных путей, `..`, неканонических путей и symlinks. Вход и output должны быть отдельными деревьями. JSON с повторяющимися ключами, NaN/Infinity, ошибочный API envelope даже при HTTP 200, несогласованные origin hash/размер/период отклоняются. `checks.json` копируется как свидетельство подготовки, его числам importer не доверяет.

Каждая станция сверяется со своим raw-справочником, каждое наблюдение — с `raw_file`/нулевым `raw_index`: ID, буквальная строка времени, `pm25`, null, признаки неизвестности и остальные поля нормализованной строки. Для всех raw-строк часовых серий требуется нормализованная ссылка; неизвестная станция, пропущенная при нормализации raw-строка, выход за окно, нечисловое/нефинитное значение приводят к отказу. Отсутствие строки в самом raw не является такой ошибкой: это пропуск источника. Соседние индикаторы не подставляются вместо PM2.5.

### Ключ, дубли и повтор

Ключ наблюдения зафиксирован до записи: `(source, station_id, observed_at_raw, indicator, aggregation)`. Все поля наблюдения кроме raw-ссылки составляют его семантическое содержимое. Совпадающие дубли сворачиваются в одну запись с объединением уникальных `raw_references`; конфликт по тому же ключу отклоняет весь вход, независимо от порядка строк. Повтор той же raw-ссылки также не размножает наблюдение. Числа `12` и `12.0` равнозначны и получают каноническое представление; boolean числом не считается. Повторяющийся ID станции в справочнике нормализованных станций отклоняется.

Станции, наблюдения и raw-ссылки сортируются. `logical_sha256` вычисляется из канонических станций, содержимого наблюдений без raw-ссылок и coverage: перестановка нормализованных или raw-строк не меняет логическое содержимое. При перестановке raw сохраняются новые корректные индексы; побайтовые hashes входа и raw-ссылки могут отличаться. При добавлении нового совпадающего raw-дубля сохраняется дополнительная ссылка, а логический ряд остаётся тем же.

Повтор входа в **новый** output создаёт самостоятельный эквивалентный снимок с тем же логическим hash, без добавления строк в прежние результаты; `created_at` является временем импорта. Любой существующий output, включая пустой каталог или незавершённый импорт, даёт отказ без изменения его файлов. Перезапись и автоматическое возобновление отсутствуют.

### Состав и готовность

Формат `placelens.air-snapshot.v1`:

- `manifest.json`: единственный маркер `state: ready`, `activated: false`; версия, время импорта, hash входного manifest, ключ/политика дублей, счётчики, исходное окно, неизвестность timezone, ограничения и inventory всех остальных файлов с размерами/hashes.
- `input/`: полная побайтовая копия проверенного входа, включая его manifest, origins, raw, checks и сохранённую проверку доступа. Старый ignored запуск для чтения снимка не требуется.
- `stations.json`: станции с исходными ID, координатами, source begin/end и неизвестными CRS, статусом, датами координат, историей оборудования и переносов. Наличие наблюдений не назначает ACTIVE. Source begin/end не становятся границами подтверждённой истории.
- `observations.jsonl`: по одной записи на ключ; вместо `raw_file`/`raw_index` — массив `raw_references` с этими полями и `value_field_present`. Все raw-ссылки, включая `coordinate_source` станции, разрешаются относительно `raw_reference_root: input` из manifest.
- `coverage.json`: по каждой станции фактические `first_observed_at_raw`/`last_observed_at_raw`, число строк, null, нулей и отсутствующих часовых интервалов в заявленном окне. У станции без строк обе фактические границы null с `SOURCE_ROW_MISSING`. Это границы данного входа, без обещания непрерывного архива.

Null представлен существующей строкой с `row_present: true` и `SOURCE_VALUE_NULL_OR_ABSENT`. Отсутствующая строка не материализуется, учитывается в coverage с `SOURCE_ROW_MISSING`. `value_field_present` вместе с сохранённым raw различает отсутствующее поле `pm25` и явный null внутри существующей строки. Числовой 0 доступен, не считается пропуском. Исходные часы не получают UTC/timezone; время подготовки, HTTP и импорта их не заменяет.

Все проверки входа и конфликтов завершаются до создания output. Каталог создаётся эксклюзивно; после записи importer повторно сверяет размеры/hashes всех файлов. Manifest сначала полностью записывается как `manifest.pending`, затем переименовывается в `manifest.json` последним шагом. При позднем отказе каталог диагностики может остаться, но без готового manifest; читатель должен игнорировать такой каталог. Прежние результаты не затрагиваются. Команда при отказе возвращает ненулевой код, без тела raw и сетевых исключений. Это локальная файловая готовность, без активации приложения.

## Обновление и хранение А12

`php artisan air:refresh [--end="YYYY-MM-DD HH:00:00"]` запускает publisher через Python 3. Ручной запуск может передать исключительную верхнюю границу в исходном времени. При её отсутствии команда использует начало текущего часа в настроенной зоне расчёта окна. Для получения данных запрашивается одно окно для заданных станций. Станции, ответ и результаты проверяет импортер А11 с закреплённым свидетельством единицы PM2.5 из fixtures А11. Допустимы пропуски отдельных часов и станций. Полностью пустой ответ отклоняется, чтобы не заменить историю при возможном сбое источника.

Под lock обновления publisher проверяет активный выпуск по хешу manifest и inventory. Если запрошенная исключительная верхняя граница раньше `window_raw.end_exclusive` проверенного выпуска, Python возвращает `older_window`, а Artisan сообщает о пропуске с кодом 0. Такой запуск записывает время попытки и завершается до запроса к источнику, переключения версии, записи `last_success_at` и уборки выпусков. Окно с той же или более поздней верхней границей проходит обычную проверку и публикацию.

| Параметр | Значение |
|---|---|
| `AIR_SNAPSHOT_ROOT` | Выделенный абсолютный путь на локальной файловой системе с общим `flock` и атомарным rename. Publisher и PHP читают одно дерево. Запись нужна только publisher. |
| `AIR_STATION_IDS`, `AIR_WINDOW_HOURS` | От 1 до 20 уникальных ID через запятую и окно от 1 до 168 часов. |
| `AIR_WINDOW_TIMEZONE` | Зона IANA для вычисления границы при запуске без `--end`. Исходные метки остаются без установленного пояса, смещения и UTC. |
| `AIR_RETENTION_DAYS` | От 1 до 3650 дней хранения каталогов предыдущих выпусков по времени создания. Уборка после успешного обновления сохраняет активный выпуск независимо от возраста. |
| `AIR_SCHEDULE_ENABLED`, `AIR_SCHEDULE_CRON` | Явное включение и cron-выражение Laravel в UTC. По умолчанию задача отключена. |

В принятом локальном c-ares образе PHP отсутствует `python3`. Для этого развёртывания Artisan запускается из checkout на хосте с PHP CLI, зависимостями Laravel и Python 3. Если выбран каталог `data/air/runtime` внутри общего checkout, хостовый `AIR_SNAPSHOT_ROOT` указывает на его абсолютный путь на хосте, а контейнерный — на `/var/www/html/data/air/runtime`. Это один каталог через существующий bind mount. Publisher должен иметь право записи, PHP — доступ для чтения выпусков и файлов блокировки.

Для рабочей активации нужен один штатный вызов Laravel `schedule:run` каждую минуту в окружении publisher. И ручной запуск, и Laravel вызывают `air:refresh`. Файловый lock исключает их пересечение. Пропущенный или занятый запуск не повторяется автоматически. Перед включением проверить настройки обоих окружений, доступ к общему каталогу и HTTPS-доступ publisher к источнику, согласовать рабочую частоту, окно, ID, зону и срок хранения. [Изолированные проверки](../testing.md#плановое-обновление-и-локальная-история-воздуха-а12).

Ограничения получения: до двух HTTPS GET на фиксированные endpoint проекта и часовых данных, без редиректов и повторов, до 2 МиБ на ответ, общий сетевой бюджет 15 секунд и 45 секунд на работу дочернего процесса. Полный inventory проверяется до публикации. В HTTP из локального снимка читаются manifest и три хешированных продукта: до 64 КиБ на JSON-файл и 8 МиБ для JSONL. Каждый запрос читает одну зафиксированную версию.

`attempt.json` хранит `last_attempt_at` для запуска, получившего lock. `active.json` меняется атомарно и хранит `snapshot_version`, `last_success_at` и `last_observed_at_raw`. Совпадение окна, списка ID и обоих сырых ответов сохраняет проверенную версию без дублирования строк или выпуска. Исправленный ответ публикует новую версию со своим raw. При ошибке проверки или до переключения прежний указатель и ряд сохраняются. История HTTP ограничена окном активного выпуска. Срок хранения каталогов служит для локальной диагностики и восстановления, без автоматической догрузки и объединения окон.

### Пробный выпуск А12

22.11.2026 вручную проверен один архивный выпуск за `[2026-08-09 00:00:00, 2026-08-16 00:00:00)`. Все восемь станций, включая три из А11, вернули по 168 числовых значений. Часовой пояс, свежесть и QC неизвестны. Всего три HTTPS GET с HTTP 200 и кодом источника 1: справочник, первые шесть часов для 20 кандидатов, полное окно для выбранных восьми. Справочник побайтно совпал с закреплённым А11. ## Воспроизведение и границы

Офлайн-подготовка требует Python 3, без БД и сети. Скрипт сверяет четыре исходных hash и журнал перед созданием **нового** каталога, существующий output не перезаписывает:

```sh
python3 -B scripts/air/prepare-input.py \
  --source data/reports/source-feasibility/2026-11-03-a2-01 \
  --access data/air/access/2026-11-13-a11-1-02 \
  --output /tmp/air-input-new
```

На другой машине закреплённый набор читается непосредственно: старый ignored запуск нужен только для повторной подготовки, не для разработки importer. При повторе `prepared_at` и manifest hash будут новыми; содержимое нормализованных данных должно совпасть.

Опциональная адресная проверка доступа требует Python `requests`; запускать только в рамках разрешённой офлайн-подготовки, с новым output:

```sh
python3 -B scripts/air/probe-access.py --output data/air/access/new-check
```

Скрипт выполняет ровно два запроса, без retries/redirects, connect/read timeout 5/15 с, предел 256 KiB тела на запрос. Ошибка сохраняется типом без текста исключения; код завершения сам по себе не означает доступность: проверять журнал, HTTP/API status и data. Предел read timeout не является общим wall-clock deadline. Это не загрузчик архива и не runtime-provider.

Точность/калибровка, история оборудования/переносов, datum/CRS, timezone и условия сопоставимости не подтверждены. Для пространственного использования будущих выпусков А12 нужна отдельная проверка CRS и актуальности положения. Импортер сохраняет исходные координаты и наблюдения с неизвестностью. Полный паспорт станции, ветер и многолетняя история не блокируют этот ограниченный вход. Ни нынешний справочник, ни старые точечные пробы других лет не доказывают непрерывность многолетнего архива или самую раннюю дату.
