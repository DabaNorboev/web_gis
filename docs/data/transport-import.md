# Импорт остановок

Офлайн-команда `transport:import-stops` делегирует работу `OfficialStopsImporter`, `OfficialStopsCsvReader`, `GeoJsonBoundary` и `OfficialRouteNormalizer`. Таблицы и GIS-соглашения — в [схеме данных](../data-schema.md). API анализа описан ниже.

## Файлы и запуск

[Паспорт набора](https://www.24bpd.ru/opendata/2466231215-stoppingpoints/) · [CSV версии 20250531T1612](https://24bpd.ru/files/opendata/2466231215-stoppingpoints/data-20250531T1612-structure-20240630T1152.csv). Сохранить CSV без преобразований по пути ниже. SHA-256 проверенного файла: `7ef6db18c365078c9db8e8b5fdeffb7e654e9249012d8aa35d6d6e2900a12e2c`.

Исходники — `data/raw/<dataset>/<version>/`, отчёты — `data/reports/`; весь `data/` игнорируется Git. Команда ничего не скачивает. CSV: UTF-8, запятая, колонки `id,name,type_transport,num_route,address,the_geom_lon,the_geom_lat`.

Граница: [OSM relation 1157393](https://www.openstreetmap.org/relation/1157393), версия 72 от 2026-04-07, снимок от 2026-10-07. Это городской округ, включая западные территории; кадастровая точность не подтверждена. Метаданные/хеш — в `manifest.json` рядом с GeoJSON. Исходный ответ и запрос: `data/raw/osm_stops/2026-10-07/boundary.json` и `boundary.overpassql`. Для подготовки собрать outer/inner rings member ways/nodes в Polygon/MultiPolygon; для точного повтора сохранить готовые файлы и хеши, поскольку OSM меняется.

```bash
docker compose exec php php artisan transport:import-stops \
  data/raw/transport_stops/2025-05-31/stops.csv \
  --boundary=data/raw/boundaries/krasnoyarsk/2026-10-07/boundary.geojson \
  --source-version=20250531T1612 \
  --source-updated-at=2025-05-31 \
  --dry-run
```

Для записи убрать `--dry-run`. Справка: `docker compose exec php php artisan help transport:import-stops`. `--source-updated-at` — публикация; `--observed-at` указывать только при известном наблюдении (сейчас `null`). Формат: `YYYY-MM-DD` либо ISO 8601 со временем и часовым поясом.

## Правила загрузки

- GeoJSON: geometry, Feature или FeatureCollection с одним валидным 2D Polygon/MultiPolygon, EPSG:4326, без custom CRS. `ST_Covers` включает точки на границе. Автоматического объединения с остановками OSM нет.
- Структура CSV и непустые уникальные ID проверяются во всём файле; нарушение останавливает импорт. Неверные координаты пропускаются с сохранением ID в отчёте, внешние точки считаются отдельно. Исходные поля сохраняются.
- Снимок публикуется атомарно, история остаётся. Advisory lock запрещает параллельный импорт этого источника/набора. Повтор успешного входа возвращает `skipped`, включая исторический вход без его реактивации.
- Идентичность учитывает хеш CSV, байтовый хеш границы (включая форматирование), версию импортера, метаданные и хеш справочника. Читаются и хешируются одни и те же байты. Отсутствующие файлы/неверные параметры отклоняются до регистрации попытки.
- Пустой снимок запрещён. Уменьшение остановок более чем на 20% требует проверки и `--allow-large-drop`. `--dry-run` ничего не записывает; статистика/предупреждения реального импорта — `dataset_imports.result`, ошибка — `error_message`, время обработки — часы PostgreSQL.

## Маршруты и ограничения

`config/transport_routes.php` — небольшой справочник по четырём скриншотам, зафиксированным 2026-10-10. URL и дата актуальности неизвестны. Сопоставление с CSV 2025 года не подтверждает текущую или историческую работу маршрута на остановке; связь остановка–маршрут берётся из CSV.

Ключ — `mode:ref`, повторные связи удаляются, буквенные суффиксы сохраняются. Справочник включает автобусы, троллейбусы 4/5/6/13/15, трамваи 2/4/5/6/7, электробус 1 (`bus` с `vehicle_type: electric_bus`). «Заказной» и «СФУ» не становятся номерными маршрутами.

Однозначный номер или согласованный со справочником суффикс `т`/`тр` определяет вид. Несколько кандидатов уточняются только однозначным совместимым типом из CSV, иначе `unknown`. Отсутствующий в справочнике маршрут сохраняет прежний однозначный тип/согласованный суффикс с предупреждением, иначе остаётся неопределённым. Конфликты типа и нераспознанные токены отмечаются; отсутствие в списке не доказывает отмену.

`raw_data.resolutions` хранит токен, исходный тип в нижнем регистре, способ сопоставления (`catalog_unique`, `catalog_suffix`, `catalog_with_source_type`, `source_type`, `source_suffix`, `unresolved`) и уточнение электробуса. Это способы нормализации, не `quality.method` API. Хеш/метаданные справочника входят в конфигурацию импорта; версия импортера — 2.

Текущий снимок: 3 791 исходная запись, 1 176 остановок, 2 613 вне границы, две без координат (2219/2220), 77 ключей маршрутов (12 `unknown`), 5 048 связей; предупреждения у 484 остановок. Старый снимок с 130 ключами (55 `unknown`) сохранён. Число ключей не является точным числом действующих маршрутов; API отмечает неполное покрытие и считает маршрут один раз во всём радиусе.

Проверки: `sh scripts/init-test-db.sh`, `docker compose exec php composer test:postgis`, `docker compose exec php composer test`. GIS-тесты в `web_gis_test` проверяют отбор, координаты, ограничения, нормализацию, dry-run, повторы/изменение конфигурации, исчезновение объектов и откат при сбое записи.

## API анализа

С 20.10.2026 активен буферный снимок №9: тот же CSV/1 176 остановок, отдельная сервисная граница и отбор с буфером 1000 м. Импортер версии 3 принимает `--buffer-m=0..5000` (по умолчанию 0); для рабочих радиусов применяется 1000. [Подготовка, формулы, статусы и проверки](../features/coverage.md). Географическое покрытие не подтверждает полноту действующей сети.

`GET /api/v1/transport/analysis?lon=92.87&lat=56.01` — публичный запрос с обязательными числовыми `lon` (±180) и `lat` (±90), ошибка параметров — JSON/422. Параметр `radius_m`: 300 или 500 м; по умолчанию 500 м. FormRequest проверяет параметры, контроллер делегирует расчёт `TransportAnalysisService`. Внешних запросов нет.

Ответ: `point`, `radius_m`, `analysis_area` (GeoJSON Polygon), `analysis_bounds` ([west, south, east, north], EPSG:4326), `scope: imported_stops`, `coverage`, `nearest_stop`, `stops_in_radius`, `route_details`, `metrics`. `stops_in_radius` содержит ID, исходный ID, имя, координаты и `distance_m` (метры по прямой) найденных точек радиуса, отсортированных по расстоянию, затем ID, из того же активного снимка. Показатели: `nearest_stop_distance`, `stops_count`, `unique_routes_count`, `identified_routes_count`. Каждый содержит источник, ID импорта, наблюдение, расчёт и независимые свойства качества. Для всех SQL-запросов фиксируется один активный снимок. Радиус считается `ST_DWithin` по geography; ближайшая выбирается по точному `ST_Distance` и может быть за выбранным радиусом, если её расстояние помещается в подтверждённый охват. При `PARTIAL` три счётчика равны null/INSUFFICIENT_DATA, найденный список явно неполный; за пределами сервиса или без метаданных покрытия показатели null/UNAVAILABLE, списки пустые. Подробнее — [контракт покрытия](../features/coverage.md).

Маршруты дедуплицируются по ключам на всех остановках радиуса. `identified_routes_count` — число ключей с определённым типом, включая частичный результат. При `unknown`, пропущенных/нераспознанных перечнях или конфликте типа `unique_routes_count` равен `null` с `INSUFFICIENT_DATA`; проблемные ключи/остановки и метаданные справочника — в `route_details`. При отсутствии активного набора все значения `null`/`UNAVAILABLE`. Ноль означает отсутствие точек/маршрутов в радиусе именно в импортированном наборе, не подтверждённое отсутствие транспорта на территории.

`quality.method` — `DERIVED` для результата, `null` без него. Актуальность — `UNKNOWN`: дата наблюдения текущего набора неизвестна; отдельные пороги актуальности ещё не определены, одна известная дата сама по себе не даёт `CURRENT`. Пространственное покрытие проверяется независимо от реальной полноты/работы сети; последние не подтверждены. Пешие расстояния не рассчитываются. Проверено HTTP через Nginx и интеграционными тестами в `web_gis_test`.

Для карты `analysis_area` формируется в PostGIS через `ST_Buffer(point::geography, radius_m)` и возвращается в EPSG:4326. Границы `analysis_bounds` вычисляются в PostGIS по тому же полигону и используются для масштаба карты. Это приближённый полигон для отображения; подсчёты по-прежнему используют точный `ST_DWithin`. Полигон возвращается и при отсутствии активного набора.

`stops_count` считает отдельные записи/точки, без группировки по названию. В активном наборе 1 176 разных координат и 656 разных названий; например, исходные ID 3965/3966 имеют имя «площадь Революции (пр. Мира)», но разные координаты. В CSV нет поля направления или идентификатора остановочной зоны. Количество названий не равно количеству зон; автоматическое объединение пока не выполняется.


## Режим «Остановки рядом»

Выбор точки и радиуса 300 / 500 м показывает окружность, остановки и список по возрастанию расстояния по прямой. Выбор записи списка или точки остановки выделяет её на карте; исходная пользовательская точка остаётся неизменной. Смена радиуса отменяет устаревший запрос и очищает прежнее выделение.

Пешая маршрутизация не используется: время, проходы, препятствия и достижимость не рассчитываются. Все данные остановок берутся из локального активного снимка; внешних запросов для анализа нет. Подложка карты загружается отдельно. Сведения о маршрутах сохраняются в исходном наборе и прежнем API, но не показываются в этом режиме.

В интерфейсе одинаковые названия собраны в раскрываемые карточки (без изменения API, координат и исходных записей). Счётчик по-прежнему показывает число точек, отдельно указано число названий в списке. Карточки и точки внутри упорядочены по расстоянию по прямой. Направления и принадлежность остановочной зоне не выводятся из названия или близости. Выбор точки на карте раскрывает её карточку; кнопка отдельной точки выделяет её на карте.


## Остановки в анализе места (А8)

`OfficialStopPoiProvider` адаптирует **существующие** `transport_stops`, активный `24bpd / transport_stops:krasnoyarsk` snapshot и `DatasetCoverage` к категории `official_stop` нового [POST анализа места](../features/place-analysis.md#5-блок-poi). Новый импортёр/набор/таблица не создавались; OSM-остановки не используются. Прежний transport API с радиусами 300/500 м и сведениями о маршрутах сохраняет своё поведение.

Для раздельной активации используется `config/place_analysis.php`: `PLACE_ANALYSIS_OFFICIAL_STOPS_ENABLED=false` по умолчанию. В локальном окружении 05.11.2026 по разрешению владельца включён флаг true и подключена актуальная сборка; используется прежний snapshot №9 **без переимпорта и изменения данных**. При выключенном флаге новый POST сообщает `OFFICIAL_STOP_NOT_ENABLED`; старый API от флага не зависит. В PHPUnit флаг принудительно выключен независимо от локальной .env, предметные тесты включают его явно.

Отбор 200–1000 м идёт по geography до исходной точки, без округления; `ST_DWithin(radius+0.001)` только консервативный индексный фильтр, окончательно `ST_Distance <= radius`. Граничная точка входит; расположенная на 0,001 м дальше исключается. Геометрия/метка — исходный Point4326, `distance_m` в метрах. SQL не группирует имена/координаты, сортирует distance/id. `official-stop:<source_id>` не зависит от внутреннего PK импорта; одинаковые названия с разными исходными ID остаются отдельными точками. Стабильность source_id между версиями не доказана, имя/близость не устанавливают направление или остановочную зону.

Категория читается в отдельной транзакции (statement_timeout 2 s, lock_timeout 500 ms), фиксирует один активный snapshot. `coverage` берётся по ID этого снимка: PARTIAL даёт неполный список/count=null; вне сервиса — пустой список/count=null; без coverage — `OFFICIAL_STOP_COVERAGE_UNAVAILABLE`, без источника — `OFFICIAL_STOP_SNAPSHOT_UNAVAILABLE`. Ошибка — `availability_by_category.official_stop: ERROR`, UNKNOWN/count=null, без SQL/координат в клиентской ошибке; grocery/аптеки сохраняются. Парк не подключён. Отказ не даёт пустой подтверждённый ноль.

Полнота сети и актуальность неизвестны. Если отчёт импортёра содержит `invalid_coordinates`, эти исходные записи могли бы относиться к кругу, но их положение нельзя подтвердить: completeness категории **PARTIAL**, counts_by_category.official_stop=null даже при COVERED. Найденные точки доступны. Это не меняет spatial coverage и не превращает неизвестность в ноль. На корректном полном fixture-входе без таких пропусков COVERED/0 означает «в используемом наборе найдено 0»; реальная сеть не объявляется полной.

Каждый элемент отдаёт `source=official-stops`, dataset_import_id, source_version, source_updated_at и observed_at из снимка, HTTPS source_url паспорта и limitations. UI показывает источник 24bpd, версию CSV, паспорт и ограничения в подробностях; ограничения полноты видны и без выбранного объекта. Число найденных записей с координатами отделено от неизвестного полного итога: `data.official_stop_summary={found_count,source_without_coordinates}`. `found_count` — точное число точек активного снимка, прошедших фильтр круга; считается SQL `COUNT(*) OVER()` по всему отбору до возможного ограничения списка, а не длиной отображённой страницы. Сейчас список полный, без пагинации. При ошибке/недоступности/вне сервиса found_count=null, не 0; source_without_coordinates — число исходных записей без корректных координат, не число пропущенных точек конкретного круга. Полные count/counts_by_category сохраняют прежнюю nullable-семантику. Наличие остановки не означает удобный подход, нужные маршруты, текущую работу или расписание. Новый POI-provider не читает/не обещает маршруты, время ожидания, вход или пешеходную доступность.

### Пригодность существующего набора и выполненные проверки

Сверен локальный CSV `data/raw/transport_stops/2025-05-31/stops.csv` с SHA `7ef6db18c365078c9db8e8b5fdeffb7e654e9249012d8aa35d6d6e2900a12e2c`; версия `20250531T1612`, публикация 31.05.2025, наблюдение неизвестно. Рабочий snapshot №9 имеет importer_version=3 и существующий буфер 1000 м, связанную service/data geometry. По состоянию сохранённого файла набор пригоден для отображения официальных точек с указанными ограничениями, а не как актуальная полная действующая сеть.

Повторный импорт **только в web_gis_test с откатом** подтвердил 3 791 исходную запись, 1 176 принятых точек, 2 613 внешних и две без координат (2219/2220). Текст адресов этих двух указывает другие населённые пункты, но строка адреса не является доказательством географического исключения; этим срезом они не отнесены за границу по догадке. Поэтому новый POI-результат честно отмечает неполноту. Сопоставление name/address/координат пяти записей прошло без изменения исходной геометрии: 3965/3966 «площадь Революции (пр. Мира)», 3970 «Поворот (ул. Елены Стасовой)», 3971/3972 «Подстанция». Это сверка источника, не проверка на местности.

Тестовый POST у публичной точки 3965 дал 3 остановочные точки на 200 м и 27 на 1000 м; spatial coverage COVERED, completeness PARTIAL, полный счёт null. Совместный тест импортировал проверенные grocery/pharmacy fixtures и подтвердил прежние 663/158 записей, равенство их API-объектов до/после добавления остановок и при отказе этой категории. Неподключённые парки не выдаются за пустые.

[Целевые тесты](../testing.md#официальные-остановки-а8): точная граница 200/1000 и ближайшие внешние точки, одноимённые разные ID, смена active snapshot, отсутствие OSM-fallback, отключение/нет источника/нет coverage, ноль/PARTIAL/outside/ошибка и приватность; сохранены регрессии существующего импортёра/transport API. Реальные ответы проходят TS runtime, неверная metadata отвергается. QA находятся в новом `data/reports/a8-official-stops-20261105-01/`, старые входы/отчёты не перезаписывались. Сборка направлена отдельно от public/build.

### Подпись найденного количества

Для остановок единая подпись над фильтрами использует `official_stop_summary.found_count`: «Найдено N остановочных точек», при N=0 — «Найдено 0 точек с координатами». Ошибка не заменяется нулём; ограниченный список не подменяет found_count своей длиной. Для «Все» складываются известные counts_by_category и found_count; неизвестный компонент позволяет подписывать только число показанных строк.

`source_without_coordinates` сохраняет число негеокодированных записей всего источника. Необязательное `excluded_outside_scope` — число явно исключённых из городского анализа; целое ≥0 и не больше source_without_coordinates. UI предупреждает только об остатке, который потенциально относится к области анализа.

По решению владельца 05.11.2026 ID 2219 (д. Кара-Беллык, ул. Ольшевского) и 2220 (с. Беллык, ул. Ленина), указанные в CSV как Краснотуранский район, исключены из неопределённости анализа Красноярска. Это согласованное исключение по адресам источника, не результат геокодирования или вычисленного положения остановок. Правило действует только при совпадении SHA-256 исходного CSV выше, source_version=20250531T1612 и хеша сохранённой городской границы. Новая версия, другой файл/граница или иные негеокодированные IDs не наследуют исключение. Импортёр/снимок №9, исходные строки и прежний transport API не изменяются; точки не добавляются на карту. При COVERED эти две записи не заставляют городской count быть null; PARTIAL у границы, неизвестные записи и ошибки сохраняют прежнюю семантику. Полнота действующей сети остаётся UNKNOWN.
