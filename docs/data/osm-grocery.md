# Первый grocery-срез А8

Общие механизмы строгой подготовки, geometry/import и category-provider также используются [аптечным срезом](osm-pharmacy.md) с отдельными параметрами и снимком; grocery v2 и его рабочие данные сохраняются.

Подготовка, импорт и provider категории `grocery` для [анализа места](../features/place-analysis.md#5-блок-poi). Это ограниченный OSM-срез, не проверенный каталог действующих магазинов. Остальные категории, спутники и воздух этим pipeline не подключаются. Первое рабочее подключение выполнено в локальном окружении проекта; публичного деплоя нет.

## Категория и identity

- Только точные `shop=supermarket|convenience`: супермаркеты и небольшие магазины общего продуктового ассортимента. `shop=grocery` исключён: его неоднозначное употребление не подтверждает общий ассортимент; в PoC он включался. Основание границ — [supermarket](https://wiki.openstreetmap.org/wiki/Tag:shop%3Dsupermarket), [convenience](https://wiki.openstreetmap.org/wiki/Tag:shop%3Dconvenience), [grocery](https://wiki.openstreetmap.org/wiki/Tag:shop%3Dgrocery). Пекарни, алкоголь, мясо, овощи, киоски, универсальные непродовольственные магазины и другие значения не добавляются по имени/бренду.
- Исключены ненулевые lifecycle-флаги `disused`, `abandoned`, `demolished`, `razed`, `construction`, `proposed`, `removed`, `closed` и соответствующие `*:shop`. Значения `no|false|0` не означают закрытие. Отсутствие флага не доказывает работу магазина.
- Identity — `osm:<node|way|relation>:<id>`. Повтор идентичности в файле отклоняет весь снимок; версия объекта не создаёт вторую запись. Одинаковые названия/адреса/бренды и близость не объединяют магазины.
- Структурное повторное представление outer-way в relation устраняется только при явном членстве, равенстве всей геометрии и всех тегов кроме `type`: canonical ID relation, alias way сохраняется в `raw_data.aliases` и отчёте импорта.
- Совпадающие точки и node внутри площадного магазина без доказательства общей identity — кандидаты на дубли, не подтверждённые дубли. Пары сохраняются в `possible_duplicates`, объекты не сливаются; API `identity_note` и подробности UI показывают неопределённость. Числа означают найденные записи набора, не подтверждённое число физических магазинов. Общая полнота OSM — `UNKNOWN`.

## Геометрия и покрытие

Используются исходные Point, замкнутые Polygon и поддержанные полные multipolygon relations с отверстиями. Полные координаты восстанавливаются до bbox-отбора. Импорт проверяет пересечение с точной геометрией отбора, сохраняет весь объект без обрезки и repair. Неполный/невалидный выбранный объект останавливает импорт: его нельзя потерять и опубликовать ложный ноль.

`DatasetCoverage` сохраняет сервисную геометрию и область отбора отдельно. SHA-256 выбранной границы обязателен, но недостаточен: importer дополнительно проверяет правила и геометрию фактического отбора по контракту v2 ниже. Первый срез использует сохранённую сервисную границу без внешнего буфера: у края круга возможен `PARTIAL`; это не покрытие всего радиуса 1000 м по всему городу. Для буфера требуется отдельная подготовленная точная граница, её нельзя приписать прежнему файлу.

Окончательный отбор — `ST_Distance(geom::geography, point::geography) <= radius_m` для 200–1000 м, включая границу, без округления для отображения. Индексный `ST_DWithin` использует только консервативный запас 0,001 м для кандидатов: обратный geodesic-расчёт на самой границе может численно расходиться. Запас не расширяет итоговый радиус; расстояние по сфероиду до исходной геометрии и число API проверяются одним `ST_Distance`. Полигон учитывается при пересечении с кругом, даже если его `ST_PointOnSurface` снаружи; внутри расстояние 0. Служебная точка не является входом. Карта рисует исходные контуры и метки, не пересчитывает GIS и не фильтрует реальные результаты по метке. Выбор контура/метки связан со списком.

## Метаданные входа и запрет неполной публикации

`OsmGroceryPreparation` принимает только известный контракт `preparation.schema_version=2`, `dataset_key=grocery`, `categories=[grocery]`, `method=complete_source_members_bbox_v2`. Нужны оба точных тега `shop=supermarket|convenience` и объявленный проход по `node|way|relation`; порядок множеств несущественен, пропуски/дубли/другие правила недопустимы. Объекты файла должны соответствовать категории. Обязательны SHA-256 PBF, границы и скриптов, `emitted_counts` по типам и полный `relation_audit`. Неизвестный формат, отсутствие метаданных и прежний v1 отклоняются до журнала/активации, без приписывания им COVERED.

`extraction_geometry` — реальная прямоугольная область, которую использует offline-preparer для отбора кандидатов из полного PBF; `bbox` описывает тот же фильтр. Importer валидирует геометрию через существующий `GeoJsonBoundary`, затем PostGIS проверяет `ST_Equals` с геометрией фильтра и `ST_Covers(extraction_geometry,data_geometry)` для всей объявленной области данных, включая внешний буфер. Это не сравнение строк bbox и не вывод области по расположению найденных магазинов. Перестановка вершин той же геометрии допустима; узкая область или геометрия с тем же bbox, но отверстием, не покрывающая данные, отклоняется. Ограниченный вход сейчас **отклоняется**, а не получает выдуманное полное покрытие. Проверка метаданных согласует свидетельство offline-сканирования с coverage; полноту исходного OSM относительно реального мира она не подтверждает.

Для **каждого** relation выбранных тегов во всём PBF записывается один исход в `relation_audit.outcomes`:

- `emitted` — полные координаты way-членов переданы importer; ID и число обязаны совпадать с relations в файле. Importer отдельно проверяет сборку и валидность геометрии.
- `outside_extraction / complete_members_bbox_disjoint` — все члены являются ways, все координаты восстановлены и их полный envelope заведомо вне области отбора. Importer подтверждает `ST_Disjoint` геометрий; только такое пространственное исключение безопасно для публикации полного набора в выбранной области.
- `rejected` — нет членов, неизвестна геометрия node-only/nested-only, отсутствует way-член, либо внутри области неподдержанный тип/роли. Это **блокирует** успешную подготовку: остаётся `diagnostics.json`, но нет `grocery.json` и успешного manifest. Само наличие диагностической строки не оправдывает пропуск. Неопределимую географию нельзя объявить внешней.

`selected_count` сверяется с полным списком уникальных исходов, `emitted_counts` — с фактическими элементами. Успешная подготовка сохраняет тот же учёт в JSON/manifest и `diagnostics.json`; importer запрещает rejected/неизвестные исходы, неполный учёт и ложные внешние исключения. Исходные объекты не обрезаются. Любая ошибка до или во время активации оставляет прежний снимок; поздний отказ проверяется после записи новых объектов/coverage и деактивации старого внутри откатываемой транзакции.

## Подготовка и импорт

`scripts/prepare-osm-grocery.py` использует существующие disk-backed osmium/SQLite-механизмы. Входы только локальные; output обязан отсутствовать. Нужен существующий `web-gis-osm-etl:local`; сеть/БД не нужны. Пример из корня проекта (следующий запуск — в **другой новый** каталог):

```bash
docker run --rm --network=none --read-only --memory=1800m --cpus=2 \
  --user "$(id -u):$(id -g)" -e PYTHONDONTWRITEBYTECODE=1 \
  -v "$PWD/data/raw:/input:ro" -v "$PWD/scripts:/scripts:ro" \
  -v "$PWD/data/prepared/grocery:/output:rw" -w /scripts \
  web-gis-osm-etl:local python /scripts/prepare-osm-grocery.py \
  /input/osm_pbf/2026-10-19-geofabrik/siberian-fed-district-261018.osm.pbf \
  /input/boundaries/krasnoyarsk/2026-10-07/boundary.geojson /output/NEW_DIRECTORY \
  --expected-pbf-sha256 25c716a36131aab2e99802feca29d44495b80303d37e1d46eddc2a36f211863e \
  --source-url https://download.geofabrik.de/russia/siberian-fed-district-261018.osm.pbf
```

Успешный выход `grocery.json`, manifest и `diagnostics.json`: SHA-256 PBF/границы/скриптов/выхода, правила, версия OSM, counts и инструмент подготовки. Дата подготовки не дата наблюдения: `observed_at=null`. Лицензия ODbL-1.0, источник OpenStreetMap; происхождение PBF — сохранённый Geofabrik snapshot. PoC-файлы и рабочие наборы не используются как runtime-каталог и не перезаписываются.

Новая миграция создаёт только `osm_grocery` (FK на `dataset_imports`, ключ снимок/identity, GiST geometry и geography). В явно выбранном целевом окружении после миграции команда `osm:import-grocery FILE --boundary=BOUNDARY --expected-sha256=SHA256` активирует отдельный OpenStreetMap/grocery snapshot. Рабочий импорт требует явного разрешения владельца и установленного целевого окружения; GIS-тесты по-прежнему выполняются только в защищённой `web_gis_test`. Импорт — advisory lock, временная staging-таблица, атомарная публикация объектов/coverage/active-ID. Прежние снимки не удаляются. Повтор checksum+configuration — `skipped`, без реактивации старого снимка; пустой или упавший более чем на 20% снимок не публикуется без проверки. `--allow-large-drop` означает уже выполненную явную проверку падения.

Без таблицы или активного снимка новый API возвращает `UNAVAILABLE / GROCERY_SNAPSHOT_UNAVAILABLE`. Отказ SQL/расчёта — безопасный `ERROR`, не ноль. При активном снимке POI — `READY`, `coverage/completeness.by_category` независимы. `grocery` count известен только при `COVERED`; 0 означает «в используемом наборе найдено 0». Другие категории пока `UNKNOWN` с точной причиной отсутствия provider, их counts и общий count — `null`.

## Проверки и допуск

[Целевые проверки](../testing.md): offline XML → полный JSON, `GroceryPoiTest` в `web_gis_test`, runtime/epochs и browser fixtures карты/списка. Тест реального подготовленного файла запускается только с явным `A8_GROCERY_FILE`; `A8_LEGACY_GROCERY_FILE` отдельно проверяет отказ прежнего формата, `A8_GROCERY_QA_DIR` допускает запись новых QA только в отдельный каталог; импорт и активный снимок откатываются тестовой транзакцией. Это не активация и не smoke рабочего HTTP-сервера. Проверка записей по исходным тегам не подтверждает фактическую работу магазина, актуальность ассортимента, вход или пешую доступность.

## Доступный подготовленный срез

`data/prepared/grocery/a8-scope-v2-20261104-01`: PBF Geofabrik SHA-256 `25c716a36131aab2e99802feca29d44495b80303d37e1d46eddc2a36f211863e`, версия базы **18.10.2026 20:25:06 UTC**, исходная сервисная граница OSM relation 1157393 (городской округ Красноярск), без внешнего буфера. В bbox отобрано 697 кандидатов (537 node / 160 way / 0 relation); точный импорт принял **663 OSM-записи**, 34 исключены границей. Это не число уникальных действующих магазинов города. Выходной SHA-256 v2 `0605fe882cf5f86414cb874c629d0b306e91ec8b0409af4e3b6e5fc1dfb3a748`. Все 19 relations выбранных тегов в PBF учтены и доказанно находятся вне области отбора; неразрешённых исключений нет.

В новом каталоге сохранены manifest, диагностика всех relations, отчёт и реальные ответы API из откатанной тестовой транзакции. Все 697 кандидатов и их исходные поля/геометрии совпали с сохранённым первым срезом; повторный импорт подтвердил прежние 663 записи и четыре пары возможных дублей. Старый `a8-first-20261104-01` сохранён без изменений, но **не допускается как вход нового importer**: у него отсутствуют обязательные свидетельства v2. Данные подтверждены повторной подготовкой, допуск формата относится только к новому файлу. Первый проверенный публичный объект имеет COVERED/1 запись на 200 м и PARTIAL/1 найденную запись (count=null) на 1000 м. Это примеры покрытия среза, не репрезентативная оценка города. Реальные JSON приняты TS runtime-проверкой; первоначальные проверки UI/выбора использовали синтетические browser fixtures. Первое рабочее HTTP-подключение проверено отдельно ниже.

Сохранённая ручная сверка пяти исходных записей подтвердила сохранение собственных тегов/неизвестных полей: «Красный Яр» node/687000425, «Пятачок» node/766259375, безымянный node/1817554654, «25 часов» way/170583063, «Теле2» way/468616492. У последнего имя противоречит ожидаемому продуктовому смыслу `shop=convenience`; автоматической переклассификации по имени нет. Выявлены четыре пары возможных node/way-дублей; они помечены, не объявлены отдельными подтверждёнными магазинами. Проверка работы/ассортимента на местности не проводилась.

Для первого подключения владелец принял четыре возможные пары дублей отдельными записями с пометками; счётчик означает найденные записи набора, а не гарантированное число уникальных магазинов. Внешний буфер пока не добавляется: у края сохраняются PARTIAL и неизвестный полный счёт. Фактическая работа магазинов и полнота OSM не подтверждены.

## Первое локальное рабочее подключение

05.11.2026 по явному разрешению владельца применена только миграция `2026_11_04_000001_create_osm_grocery_table` и атомарно активирован **snapshot 14** в Laravel `local`, БД `db` сервиса Compose `db`. Вход — только проверенный v2-файл выше, checksum `0605fe882cf5f86414cb874c629d0b306e91ec8b0409af4e3b6e5fc1dfb3a748`: 663 записи, 34 кандидата вне точной границы, четыре возможные пары дублей. Остальные активные наборы не изменились. Старый v1 не допускается; прежние inputs/outputs сохранены.

Перед изменениями сверены SHA-256 подготовленного JSON, PBF, границы и скрипта; сохранены dump затрагиваемых таблиц (`dataset_imports`, `dataset_coverages`, `migrations`), прежняя сборка, `public/hot`, конфигурация Nginx и исходная незакоммиченная работа. Резервная копия и точечный транзакционный сценарий возврата находятся в `data/backups/a8-local-activation-20261105-01/` (`RETURN.md`, `rollback.sql`, `affected-tables.dump`). До подключения grocery-таблицы и grocery-снимков в этой БД не было. Dump проверен чтением каталога `pg_restore`; восстановление рабочей БД не выполнялось. Прежние наборы и outputs не удалялись, reset/fresh не использовались.

Frontend сначала собран отдельно, затем новая сборка подключена через `public/build`; старые assets и hot-файл сохранены для возврата. Nginx использует bind-mounted конфиг репозитория, `nginx -t` прошёл перед reload. Применение правила рабочими процессами дополнительно подтверждено специфичным JSON-ответом Nginx 413 на синтетическое тело больше 8 KiB — это проверка рабочего сервера, а не только `nginx -T` или изолированный probe.

Через рабочий `http://localhost` проверены: публичная точка OSM node/10046666077 с COVERED/1 на 200 м и PARTIAL/одной найденной записью, count=null на 1000 м; обе записи возможной пары node/1817554654 и way/170583063 с `identity_note`; неподключённые категории с null вместо нуля, спутник/воздух UNAVAILABLE. Проверки POST синтетическими данными дали 413/415/422/405 и 404 для отсутствующего адреса, безопасные JSON и `no-store`/`no-referrer`; маркер запроса отсутствует в журналах Laravel/Nginx, временных файлов тел Nginx не найдено.

В Chromium на опубликованной странице `/analysis`, с реальными Nginx/PHP/API и без fixtures, проверены отсутствие начальной выбранной точки, выбор публичного адреса «Свердловская улица, 61Г», радиусы 200/1000 м с обновлением круга, выбор список → карта и карта → список, пометка возможного дубля и удаление меток при выборе неподключённой категории. Все grocery-объекты ответов связаны со snapshot 14 и имеют OSM ID; demo-подстановок нет. Браузер в контейнере использовал временный HTTP pass-through к рабочему Nginx, без подмены ответов; опубликованные assets также получены через него. Артефакты smoke сохранены рядом с резервной копией. Для ручной проверки: `http://localhost/analysis`, поиск «Свердловская 61Г».

Это первое локальное подключение только grocery. Другие категории, спутники/воздух, полнота каталога и проверка действующих магазинов остаются вне поставки; внешний буфер не добавлен, у края честный PARTIAL. Хранение/обмен/восстановление после reload не реализованы, весь А8 и А7 автоматически не закрываются.
