# Импорт остановок

Офлайн-команда `transport:import-stops` делегирует работу `OfficialStopsImporter`, `OfficialStopsCsvReader`, `GeoJsonBoundary` и `OfficialRouteNormalizer`. Таблицы и GIS-соглашения — в [схеме данных](data-schema.md). API анализа описан ниже.

## Файлы и запуск

[Паспорт набора](https://www.24bpd.ru/opendata/2466231215-stoppingpoints/) · [CSV версии 20250531T1612](https://24bpd.ru/files/opendata/2466231215-stoppingpoints/data-20250531T1612-structure-20240630T1152.csv). Сохранить CSV без преобразований по пути ниже. SHA-256 проверенного файла: `7ef6db18c365078c9db8e8b5fdeffb7e654e9249012d8aa35d6d6e2900a12e2c`.

Исходники — `data/raw/<dataset>/<version>/`, отчёты — `data/reports/`; весь `data/` игнорируется Git. Команда ничего не скачивает. CSV: UTF-8, запятая, колонки `id,name,type_transport,num_route,address,the_geom_lon,the_geom_lat`.

Граница: [OSM relation 1157393](https://www.openstreetmap.org/relation/1157393), версия 72 от 2026-04-07, снимок от 2026-10-07. Это городской округ, включая западные территории; кадастровая точность не подтверждена. Метаданные/хеш — в `manifest.json` рядом с GeoJSON. Исходный ответ и запрос: `data/raw/osm_stops/2026-10-07/boundary.json` и `boundary.overpassql`. Для подготовки собрать outer/inner rings member ways/nodes в Polygon/MultiPolygon; для точного повтора сохранить готовые файлы и хеши, поскольку OSM меняется.

```bash
docker compose exec php php artisan transport:import-stops \
  data/raw/transport_stops/2025-05-31/stops.csv \
  --boundary=data/raw/boundaries/krasnoyarsk/2026-10-07/boundary.geojson \
  --source-version=20250531T1612 \
  --source-updated-at=2025-05-31 \
  --dry-run
```

Для записи убрать `--dry-run`. Справка: `docker compose exec php php artisan help transport:import-stops`. `--source-updated-at` — публикация; `--observed-at` указывать только при известном наблюдении (сейчас `null`). Формат: `YYYY-MM-DD` либо ISO 8601 со временем и часовым поясом.

## Правила загрузки

- GeoJSON: geometry, Feature или FeatureCollection с одним валидным 2D Polygon/MultiPolygon, EPSG:4326, без custom CRS. `ST_Covers` включает точки на границе. Автоматического объединения с остановками OSM нет.
- Структура CSV и непустые уникальные ID проверяются во всём файле; нарушение останавливает импорт. Неверные координаты пропускаются с сохранением ID в отчёте, внешние точки считаются отдельно. Исходные поля сохраняются.
- Снимок публикуется атомарно, история остаётся. Advisory lock запрещает параллельный импорт этого источника/набора. Повтор успешного входа возвращает `skipped`, включая исторический вход без его реактивации.
- Идентичность учитывает хеш CSV, байтовый хеш границы (включая форматирование), версию импортера, метаданные и хеш справочника. Читаются и хешируются одни и те же байты. Отсутствующие файлы/неверные параметры отклоняются до регистрации попытки.
- Пустой снимок запрещён. Уменьшение остановок более чем на 20% требует проверки и `--allow-large-drop`. `--dry-run` ничего не записывает; статистика/предупреждения реального импорта — `dataset_imports.result`, ошибка — `error_message`, время обработки — часы PostgreSQL.

## Маршруты и ограничения

`config/transport_routes.php` — небольшой справочник по четырём скриншотам, зафиксированным 2026-10-10. URL и дата актуальности неизвестны. Сопоставление с CSV 2025 года не подтверждает текущую или историческую работу маршрута на остановке; связь остановка–маршрут берётся из CSV.

Ключ — `mode:ref`, повторные связи удаляются, буквенные суффиксы сохраняются. Справочник включает автобусы, троллейбусы 4/5/6/13/15, трамваи 2/4/5/6/7, электробус 1 (`bus` с `vehicle_type: electric_bus`). «Заказной» и «СФУ» не становятся номерными маршрутами.

Однозначный номер или согласованный со справочником суффикс `т`/`тр` определяет вид. Несколько кандидатов уточняются только однозначным совместимым типом из CSV, иначе `unknown`. Отсутствующий в справочнике маршрут сохраняет прежний однозначный тип/согласованный суффикс с предупреждением, иначе остаётся неопределённым. Конфликты типа и нераспознанные токены отмечаются; отсутствие в списке не доказывает отмену.

`raw_data.resolutions` хранит токен, исходный тип в нижнем регистре, способ сопоставления (`catalog_unique`, `catalog_suffix`, `catalog_with_source_type`, `source_type`, `source_suffix`, `unresolved`) и уточнение электробуса. Это способы нормализации, не `quality.method` API. Хеш/метаданные справочника входят в конфигурацию импорта; версия импортера — 2.

Текущий снимок: 3 791 исходная запись, 1 176 остановок, 2 613 вне границы, две без координат (2219/2220), 77 ключей маршрутов (12 `unknown`), 5 048 связей; предупреждения у 484 остановок. Старый снимок с 130 ключами (55 `unknown`) сохранён. Число ключей не является точным числом действующих маршрутов; API отмечает неполное покрытие и считает маршрут один раз во всём радиусе.

Проверки: `sh scripts/init-test-db.sh`, `docker compose exec php composer test:postgis`, `docker compose exec php composer test`. GIS-тесты в `web_gis_test` проверяют отбор, координаты, ограничения, нормализацию, dry-run, повторы/изменение конфигурации, исчезновение объектов и откат при сбое записи.

## API анализа

`GET /api/v1/transport/analysis?lon=92.87&lat=56.01` — публичный запрос с обязательными числовыми `lon` (±180) и `lat` (±90), ошибка параметров — JSON/422. Радиус фиксирован: 500 м. FormRequest проверяет параметры, контроллер делегирует расчёт `TransportAnalysisService`. Внешних запросов нет.

Ответ: `point`, `radius_m`, `analysis_area` (GeoJSON Polygon), `scope: imported_stops`, `nearest_stop`, `route_details`, `metrics`. Показатели: `nearest_stop_distance` (метры по прямой, ближайшая во всём снимке), `stops_count`, `unique_routes_count`, `identified_routes_count`. Каждый содержит источник, ID импорта, наблюдение, расчёт и независимые свойства качества. Для всех SQL-запросов фиксируется один активный снимок. Радиус считается `ST_DWithin` по geography; ближайшая выбирается по точному `ST_Distance`, без ограничения 500 м.

Маршруты дедуплицируются по ключам на всех остановках радиуса. `identified_routes_count` — число ключей с определённым типом, включая частичный результат. При `unknown`, пропущенных/нераспознанных перечнях или конфликте типа `unique_routes_count` равен `null` с `INSUFFICIENT_DATA`; проблемные ключи/остановки и метаданные справочника — в `route_details`. При отсутствии активного набора все значения `null`/`UNAVAILABLE`. Ноль означает отсутствие точек/маршрутов в радиусе именно в импортированном наборе, не подтверждённое отсутствие транспорта на территории.

`quality.method` — `DERIVED` для результата, `null` без него. Актуальность — `UNKNOWN`: дата наблюдения текущего набора неизвестна; отдельные пороги актуальности ещё не определены, одна известная дата сама по себе не даёт `CURRENT`. Покрытие за границей импорта и реальная полнота/работа сети не проверяются. Пешие расстояния не рассчитываются. Проверено HTTP через Nginx и интеграционными тестами в `web_gis_test`.

Для карты `analysis_area` формируется в PostGIS через `ST_Buffer(point::geography, 500)` и возвращается в EPSG:4326. Это приближённый полигон для отображения; подсчёты по-прежнему используют точный `ST_DWithin`. Полигон возвращается и при отсутствии активного набора.
