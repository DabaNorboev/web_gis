# Импорт остановок

Импорт выполняется офлайн из официального UTF-8 CSV. Artisan-команда `transport:import-stops` принимает параметры и выводит результат; `OfficialStopsImporter` управляет снимком и транзакцией, `OfficialStopsCsvReader` читает и проверяет CSV, `GeoJsonBoundary` отбирает точки через PostGIS, `OfficialRouteNormalizer` разбирает обозначения маршрутов.

## Исходные файлы

[Паспорт официального набора](https://www.24bpd.ru/opendata/2466231215-stoppingpoints/) и [CSV версии 20250531T1612](https://24bpd.ru/files/opendata/2466231215-stoppingpoints/data-20250531T1612-structure-20240630T1152.csv).

Скачать файл без преобразования в `data/raw/transport_stops/2025-05-31/stops.csv`. SHA-256 проверенного файла: `7ef6db18c365078c9db8e8b5fdeffb7e654e9249012d8aa35d6d6e2900a12e2c`. Исходники и отчёты в `data/` игнорируются Git. Команда ничего не скачивает и не использует внешние API.

Для отбора города используется локальный `data/raw/boundaries/krasnoyarsk/2026-10-07/boundary.geojson`: геометрия [OSM relation 1157393](https://www.openstreetmap.org/relation/1157393), версия 72 от 2026-04-07, снимок OSM от 2026-10-07. Метаданные и SHA-256 сохранены рядом в `manifest.json`. Геометрия подготовлена из сохранённого ответа `data/raw/osm_stops/2026-10-07/boundary.json`; исходный запрос — `boundary.overpassql` в той же директории. Это граница городского округа в OSM, включая западные территории; она не является подтверждённой кадастровой границей.

Чтобы воспроизвести отбор при другой загрузке OSM, получить relation и её member ways/nodes тем же запросом, собрать замкнутые outer/inner rings в EPSG:4326 и сохранить Polygon/MultiPolygon. Проверка валидности выполняется импортером. Для точного повторения текущего снимка сохранить уже подготовленные файлы и их контрольные суммы: актуальная версия OSM может измениться.

Допустимы GeoJSON geometry, Feature либо FeatureCollection с одним Polygon/MultiPolygon. Координаты — долгота, широта; нестандартный CRS не принимается. Используется `ST_Covers`: точки на границе включаются. Остановки OSM не добавляются к официальным автоматически.

## Запуск

Из корня проекта сначала проверить результат:

```bash
docker compose exec php php artisan transport:import-stops \
  data/raw/transport_stops/2025-05-31/stops.csv \
  --boundary=data/raw/boundaries/krasnoyarsk/2026-10-07/boundary.geojson \
  --source-version=20250531T1612 \
  --source-updated-at=2025-05-31 \
  --dry-run
```

Для записи выполнить ту же команду без `--dry-run`. Справка: `docker compose exec php php artisan help transport:import-stops`.

`--source-updated-at` — дата публикации исходника. `--observed-at` указывать только при известной дате наблюдения; сейчас она неизвестна и сохраняется как `null`. Формат дат: `YYYY-MM-DD` либо ISO 8601 со временем и часовым поясом. Дата импорта не подменяет дату данных.

## Публикация и ошибки

- Проверяются UTF-8, точный набор колонок и уникальность непустых ID во всём исходном CSV. Нарушение структуры останавливает импорт.
- Записи без корректных координат пропускаются с сохранением ID в отчёте; точки вне границы считаются отдельно. Исходные поля выбранных остановок сохраняются в `raw_data` без замены на нормализованные значения.
- Новый снимок записывается одной транзакцией вместе с маршрутами и связями. После полной записи переключается `is_active`. Ошибка откатывает строки нового снимка, сохраняет старый активный набор и фиксирует попытку как `failed`.
- Одновременные импорты этого источника блокируются PostgreSQL advisory lock. Второй процесс получает ошибку и может быть запущен позже.
- Повтор одинакового успешного ввода возвращает `skipped`. Идентичность учитывает SHA-256 CSV, SHA-256 файла границы, версию парсера и переданные метаданные. Даже изменение форматирования GeoJSON даёт новую контрольную сумму. Повтор старого успешного файла не реактивирует исторический снимок.
- Исчезнувшие остановки отсутствуют в новом активном снимке; старые строки остаются в истории.
- Пустой набор не публикуется. Снижение числа остановок более чем на 20% относительно активного набора требует проверки `--dry-run` и явного флага `--allow-large-drop`.
- `--dry-run` выполняет разбор и выдаёт статистику без создания записи импорта. Подробные предупреждения реального запуска хранятся в `dataset_imports.result`; фатальная причина — в `error_message`. Время начала/завершения определяется часами PostgreSQL.

Файлы прочитываются один раз, контрольные суммы вычисляются по тем же байтам, которые обрабатываются. Отсутствующий файл или некорректные параметры отклоняются до создания попытки.

## Маршруты и качество

В CSV нет отдельного справочника или стабильных ID маршрутов. Ключ маршрута формируется как `mode:ref`; номера разделяются запятой/точкой с запятой, повторы внутри остановки удаляются.

Однозначный тип транспорта берётся из `type_transport`. Суффиксы `т` и `тр` означают троллейбус и трамвай только при согласованности с типом в исходнике. Номер без уточнения в записи со смешанным/неизвестным типом сохраняется как `unknown`. Конфликтный суффикс остаётся в обозначении `unknown`, нераспознанный токен отражается в предупреждении. Оригинальная строка остаётся у остановки, исходные токены — у маршрута.

Неверные, но формально однозначные сведения самого источника автоматически не исправляются. `unknown:12` и `bus:12` пока разные ключи; число ключей нельзя выдавать за достоверное число уникальных маршрутов сети. Правило для будущего транспортного показателя требует отдельного решения и проверки качества.

Первый импорт: 3 791 исходная запись, 1 176 остановок в границе, 2 613 вне границы, две без координат (ID 2219 и 2220). Записаны 130 ключей маршрутов, из них 55 `unknown`, и 5 048 связей. У 275 остановок есть предупреждения о маршрутах. Дата наблюдения неизвестна.

## Проверки

```bash
sh scripts/init-test-db.sh
docker compose exec php composer test:postgis
docker compose exec php composer test
```

Интеграционные тесты работают только в `web_gis_test`: проверяют координаты и исходные поля, отбор границы, неоднозначность маршрутов, dry-run, повторную загрузку, смену границы, потерю объектов, откат при реальной ошибке записи и сохранение активного снимка. Транспортный HTTP API реализуется отдельной задачей.
