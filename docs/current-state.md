# PlaceLens: текущее состояние и выводы анализа

Статус: **датированный снимок для планирования на 26.10.2026**, подготовленный из анализа исходников/документации и актуализированный по согласованным вводным, Git и отчётам завершённых заданий. Это не постоянно дублируемый контракт продукта. Приложение, рабочая БД и OSRM при этой актуализации не запускались; пользовательские сессии не проводились. Прежние результаты проверок указаны как свидетельства отчётов, не как новый прогон.

## Главный вывод

Обновление после этого планового снимка: 26.10 реализован и изолированно проверен
[пеший backend/API](walking-backend.md) между выбранными уличными точками;
заданием 3 подключён [пеший UI](trips.md) в `/trips` и `/compare`. Подходы от
объектов неизвестны; пользовательская ценность остаётся гипотезой владельца,
сессии E1 отложены по его решению. Ниже сохранено основание первоначального анализа.

PlaceLens уже имеет техническую основу для сравнения мест, но ещё не подтверждённую пользу при выборе жилья. Предложение из другого чата — перейти от сравнения окружения пары адресов к проверке вариантов жилья по личным местам — использует эту основу, однако добавляет самостоятельные подсистемы: объявления, ограничения по времени, расчёт нескольких стартов и, при успешных исследованиях, область поиска. Реализованный пеший пилот между улицами не подтверждает подходы от объектов или пригодность времени для проверки личного порога.

Первая аудитория — покупатели жилья; оба режима, пеший и автомобильный, обязательны для целевого прототипа. Порядок работ и текущие статусы этапов определяются [roadmap](roadmap.md); этот снимок не задаёт отдельную очередь. Область и дополнительные данные условны. Основное место вводных о сроке, деплое и развитии после защиты — [видение](project-vision.md), бюджета — roadmap. Технические рефакторинги и новые показатели не заменяют проверку пользы.

## Состояние Git и подготовленные исправления

Основание этого документационного снимка — кодовая база `8f58ef8ca441824fa30c83a2228ad386d5a75680` на ветке `feature/project-baseline`: семь подготовленных коммитов и отдельное npm-исправление. Само обновление плана фиксируется следующим документационным коммитом; его hash определяется из Git. Перед переносом документов дерево на `3d117db…` было чистым, а npm затем включён fast-forward без изменения документационных правок. Прежний накопленный WIP уже организован в историю.

- Организация истории, независимая проверка и локальная интеграция завершены: шесть содержательных коммитов и отдельное исправление B1. Все 424 файла/индекс при интеграции соответствовали принятому TIP; старые ветки и refs сохранены.
- B1: локальный `withoutVite()` в профильном GIS-тесте. По отчёту исполнителя 41 PHP и 174 PostGIS теста прошли без frontend assets. Это локальное воспроизведение backend-последовательности, не удалённый GitHub Actions запуск.
- Файловая страховка создана и проверена вне checkout. Реальные env, БД и volumes в неё не входят; это не полное восстановление окружения после переустановки.
- Npm-исправление `8f58ef8ca441824fa30c83a2228ad386d5a75680` проверено отдельно и включено в `feature/project-baseline`. Самостоятельная статическая сверка подтвердила изменение только шести dev-записей lock, сохранение package.json и 120 узлов runtime-графа. По отчёту исполнителя прошли чистая установка, 180 frontend-тестов, typecheck/build и synthetic CLI; audit сократился с 11 до 2 уникальных GHSA. Остаточные Zod и старая source-map-цепочка не исправлены. В задаче организации Git тесты повторно не запускались.
- До фиксации нового плана GitHub уже содержал baseline `3d117db…` и npm-ветку `8f58ef8…`. Публикация нового документационного коммита и его удалённый CI подтверждаются отдельно по результатам исполнения, не самим наличием этого текста.

Итоговые отчёты и evidence организации, страховки, B1, интеграции и npm сохранены отдельно от продуктового дерева. Старый HEAD `7e8a39a…` в исходном анализе описывал прежнюю историю до интеграции, а не нынешний объём сохранённого кода. Контракты функций остаются в их основных документах.

## Реализовано по исходникам

| Подсистема | Что есть | Граница готовности / основная опора |
|---|---|---|
| Окружение | Laravel/PHP, PostGIS, Vue/TypeScript, MapLibre; четыре базовых Compose-сервиса | Конфигурация есть; свежий запуск и рабочие снимки здесь не проверены. [Архитектура](architecture.md), [README](../README.md) |
| Локальные данные | Импорты официальных остановок, OSM-адресов, зданий, дорог, путей, зелени и воды; журнал снимков и coverage | Наличие кода не подтверждает количество, полноту и свежесть данных в текущей БД. [Схема](data-schema.md) |
| Поиск места | Подготовленный адресный поиск, явный выбор OSM-объекта, подпись произвольной точки | Точка не получает фиктивный адресный ID; совпадение текста не выбирает корпус автоматически. [Поиск](address-search.md) |
| Профиль | Независимые блоки остановок, парков, растительности, воды, дорог и путей, радиус 300/500 м | Ошибка дополнительного блока не должна скрывать остальные. [Профиль](address-profile.md) |
| Сравнение | Пара А/Б, общий радиус, различия, независимая замена, ссылки, темы интересов | Нет списка объявлений и автоматического победителя. [Сравнение](address-comparison.md) |
| Карта | Подложка, официальные остановки, пять OSM-категорий, темы, выделение и управление слоями | Слой и рассчитанный показатель — разные представления; отображение не доказывает доступ |
| Личные поездки | `/trips` и общие цели А/Б, до трёх мест, только `driving`; отказы, уточнение дороги, повторы | Ограниченный car pilot, статическое время и snap 35 м. [Поездки](trips.md) |
| Качество и приватность | Происхождение/снимки, независимые method/availability/freshness; POST и fragment для личных точек; ограничения запросов и logging | Есть код и регрессии, но полного нового security audit здесь нет |
| Проверки | PHP unit/feature, защищённый PostGIS, frontend, browser, ETL и отдельный Nginx privacy test | Наличие тестов не означает, что сегодня они прошли. [Testing](testing.md) |

Поездки подключены через `POST /api/v1/trips/analyze`; `TripAnalysisRequest` допускает один старт, 1–3 цели и только автомобильный режим. `LocalCarRouterProvider` выполняет маршрутные запросы по парам с guards. Комментарий «1×N matrix» в сервисе описывает форму результата; готового пакетного N×M API для объявлений в нём нет.

В `osm_buildings` сохраняются геометрии и `raw_data.tags`. Нормализованных характеристик жилищного реестра и пользовательского блока состояния дома нет. Отдельная этажность в контексте адресного объекта уже может браться из OSM; это не проверенная карточка дома из ГИС ЖКХ. Высоты и их полнота в рабочем наборе не измерялись.

## Чего пока нет

- Объявлений с ценой, площадью, этажом, источником и датой ввода; постоянного хранилища таких вариантов.
- Индивидуальных режимов и временных порогов, итогового статуса варианта по всем условиям, матрицы нескольких стартов.
- Пешеходного охвата территории, H3-области и передачи области в поиск площадки. Подготовленный граф ограниченного уличного пилота описан в [walking-backend](walking-backend.md); он не подтверждает доступ от объектов.
- Характеристик дома из официального реестра, школьного закрепления, высотного профиля, показателя солнца.
- Подтверждения полезности с людьми. Существующий план — подготовка исследования, а не его результаты.
- Аккаунтов, сохранённых вариантов/истории, автоматического сбора объявлений и публичного размещения как готового сценария.

## Сопоставление с обсуждением и исправления предположений

| Тезис в материалах | Вывод для плана |
|---|---|
| «Текущие показатели слабые» | Это оценка из обсуждения, не результат пользовательского исследования. Окружение сохранить как проверяемый контекст; главную пользу личных ограничений проверить |
| Сначала точная матрица объявлений, затем принадлежность ячейке | Для конкретного варианта нужен расчёт от его выбранного объекта; центр ячейки даёт только приближение области. Оболочка подходящих объявлений также не доказывает достижимость территории между ними |
| Точки задаёт пользователь, значит неполнота OSM не мешает | Снижается зависимость от каталога POI, но остаются пробелы адресов, дорог, проходов и доступа |
| Достаточно включить `foot` | Автомобильный OSRM runtime остаётся отдельным от подготовленного пешего ORS. Выбор режима направляет запрос в свой provider; имя режима в URL не меняет подготовленный граф. Контракты — [trips](trips.md) и [walking-backend](walking-backend.md) |
| Матрица OSRM быстро даст итог «проходит» | Нынешние guards проверяют геометрию каждой пары. Ответ `table` не заменяет эту проверку; выигрыш производительности требуется измерить вместе с ней |
| Если пешая точность низкая, достаточно подписи «ориентировочно» | Подпись не исправляет невозможный/опасный путь. При провале критерия пригодности режим не участвует в решении по порогу |
| «Дом» уже имеет готовый источник | В обсуждении нет воспроизводимой проверки покрытия/условий/сопоставления для Красноярска. Пока это кандидат на аудит источника |
| Солнце одновременно исключено и включено как условная работа | Убрано из обязательного ядра; допускается отдельное исследование после приёмки ядра и при наличии времени |
| «Ручной ввод без юридического риска», «расширение подходит для диплома» | Безусловные формулировки не принимаются. Условия использования данных и публичного показа нужно проверять отдельно; расширение исключено из базового объёма |
| Слои промзон/домов/школ уже доступны | Готовых источников и продуктовых слоёв этих категорий не выявлено. Дороги и пути не подменяют промзоны |

## Сопровождение и технический долг

Первоначальный аудит предлагал перенос loaders, состояния поездок, личной ссылки и overlay. По исходникам и последующему независимому аудиту R1–R4 эти переносы уже выполнены. Повторять их как будущие обязательные этапы не нужно. Исторический аудит от 25.10 сообщает о 180 frontend и 172 browser checks; это его результат и его окружение, не сегодняшний прогон.

Отдельными кандидатами остаются Nginx privacy в CI, защита фиксированных output paths диагностических скриптов, перенос регрессий старых карточек на действующий UI и избирательная очистка. CI уже описывает PHP/GIS, frontend/browser и ETL; Nginx privacy в workflow не подключён. Приоритет исправления определяется изменяемой границей. Массовый рефакторинг, чистка данных и удаление отчётов для нового сценария не требуются.

## Что остаётся неизвестным

Точная дата защиты и промежуточные требования вуза; фактическое состояние runtime; пользовательская ценность для покупателей; пригодность walking; производительность с guards; качество внешних реестров; условия публикации объявлений и сравнений; необходимость области, хранения и дополнительных показателей. Владелец уже подтвердил горизонт 5–6 месяцев, обязательный работающий прототип с обоими режимами, желательность деплоя и возможность развития после защиты; это больше не открытые вопросы.

Полный порядок решений, статусы этапов и критерии завершения — в [поэтапном плане](roadmap.md). Выбирать следующую работу по нему и текущему заданию владельца; новый функциональный этап уточнением этого снимка не начат.
