# Парки, растительные территории и вода на карте

Действующий контракт слоя профиля. Источники и геометрия ниже — основное место правила; компоновка главной — [home-workspace-map](home-workspace-map.md), отдельного профиля — [address-profile](address-profile.md), `/compare` — [address-comparison](address-comparison.md). Исторические проверки — [сохранённые фрагменты](../history/ui-contract-notes-2026-11-01.md).

На картах профиля и выбранных вариантов сравнения доступны три независимых слоя, выключенных по умолчанию. Официальные остановки и остальные существующие слои сохранены. Переключатели сравнения общие для обеих карт. При замене варианта, смене радиуса и навигации назад/вперёд внутри страницы выбор сохраняется; при полном открытии/обновлении страницы начинается с выключенных слоёв. URL по прежним правилам хранит адреса и радиус, состояния слоёв в него не добавлены. Карты поисковых вариантов не получают аналитические слои. Главная использует слой при показе адресного профиля; режимы обзора поездок определяет контракт карты. Цвета и подписи базовой подложки остаются независимыми от этих переключателей: выключается только добавленный контурный слой в радиусе.

## Источник и границы утверждений

Используются локальные снимки зелени и воды, зафиксированные профилем. ID и даты конкретного выпуска не являются константами контракта. Даты берутся из метаданных снимка, не задаются в интерфейсе константами и не заменяются временем импорта/запроса. Легенда содержит цвет/тип линии, ссылку © OpenStreetMap contributors / ODbL, ID снимка и обе даты. Полнота и актуальность картографического набора не гарантируются.

- Парки: `is_park`, то есть `leisure=park`.
- Растительность: независимый `is_vegetation`, то есть существующие natural/landuse-теги из [методики](area-analysis.md).
- Вода: существующий набор `osm_water`, без новой классификации.

Парк не превращается в растительную территорию автоматически. Объект с обоими признаками передаётся в обеих категориях с одинаковым исходным ID. Разные OSM-объекты, наложения и отверстия сохраняются; слияния/удаления дублей в слое нет. Не следует складывать категории. Картографические контуры не подтверждают доступ и вход, растительность двора, качество района, возможность купания или риск подтопления. Самих таких выводов интерфейс не делает.

Пустой доступный слой означает, что в выбранном снимке/области не найдены площадные контуры этой категории. Это не доказательство отсутствия объектов на местности. Недоступная геометрия, ошибка блока, загрузка и частичное покрытие имеют отдельные подписи. При частичном покрытии показывается только известная часть, а не выдуманные нули.

## Контракт и ограничение объёма

Нового источника/эндпоинта нет. Существующий `GET /api/v1/addresses/{id}/profile?radius_m=300|500` дополнен `map.area_layers.{parks,vegetation,water}`. Каждый элемент — `{status,data,message}`; `data` — FeatureCollection с покрытием, радиусом, source, dataset_import_id, observed_at, source_updated_at и качеством. Ошибка геометрии изолируется savepoint и не меняет блоки показателей. Если прежний блок не рассчитан, соответствующий слой также недоступен.

`OsmAreaMapService` получает те же зафиксированные ID снимков и оценку покрытия, что расчёты этого профиля; повторного выбора активного снимка нет. Передаются только фрагменты, имеющие площадное пересечение с областью:

`scope = ST_Intersection(ST_Buffer(point_32646, radius, 'quad_segs=64'), data_geom_32646)`.

Сначала выполняется bbox-фильтр по существующему GiST и ID снимка/признаку, затем пересечение каждого кандидата со scope, извлечение площадных частей и исключение пустых геометрий. Ответ преобразуется в EPSG:4326 lon/lat, GeoJSON с девятью знаками. Исходный полный контур большого парка или реки и полный городской слой в браузер не отправляются. Геометрия за пределами data_geom не передаётся. UNKNOWN/OUTSIDE_SERVICE_AREA или отсутствие набора дают пустой **недоступный** слой.

Три ограниченных набора входят в обычный ответ профиля даже при выключенных флажках; переключение меняет только видимость fill/line и не делает сетевых запросов. Новых показателей, радиусов, схемы, состава/активности снимков и исходных данных нет. Формулы существующих показателей не изменены. Отображение контура обрезки использует метрический круг расчёта площадей EPSG:32646; существующий круг радиуса карты из транспортного API сохранён.
