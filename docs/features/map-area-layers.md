# Парки, растительные территории и вода на карте

Управление обновлено 23.10.2026: темы подложки, переход от показателя к слою, выделение конкретного объекта и свёрнутая легенда фактически показанных данных. Сведения по «О данных» и ручные переключатели сохранены. [Актуальные взаимодействия и проверки](../history/map-visual-interaction-2026-10-23.md). Ниже — методика и исторические проверки слоя 20.10.2026.

Завершённый этап 20.10.2026. На картах профиля и выбранных вариантов сравнения доступны три независимых слоя, выключенных по умолчанию. Официальные остановки и остальные существующие слои сохранены. Переключатели сравнения общие для обеих карт. При замене варианта, смене радиуса и навигации назад/вперёд внутри страницы выбор сохраняется; при полном открытии/обновлении страницы начинается с выключенных слоёв. URL по прежним правилам хранит адреса и радиус, состояния слоёв в него не добавлены. Поиск адреса и главная не получают новые аналитические слои. Цвета и подписи базовой подложки остаются независимыми от этих переключателей: выключается только добавленный контурный слой в радиусе.

## Источник и границы утверждений

Используются только существующие локальные OSM-снимки: зелень №12, вода №13. Версия источника — 18.10.2026 20:25:06 UTC; дата наблюдения неизвестна. Даты берутся из метаданных снимка, не задаются в интерфейсе константами и не заменяются временем импорта/запроса. Легенда содержит цвет/тип линии, ссылку © OpenStreetMap contributors / ODbL, ID снимка и обе даты. Полнота и актуальность картографического набора не гарантируются.

- Парки: `is_park`, то есть `leisure=park`.
- Растительность: независимый `is_vegetation`, то есть существующие natural/landuse-теги из [методики](area-analysis.md).
- Вода: существующий набор `osm_water`, без новой классификации.

Парк не превращается в растительную территорию автоматически. Объект с обоими признаками передаётся в обеих категориях с одинаковым исходным ID. Разные OSM-объекты, наложения и отверстия сохраняются; слияния/удаления дублей в слое нет. Не следует складывать категории. Картографические контуры не подтверждают доступ и вход, растительность двора, качество района, возможность купания или риск подтопления. Самих таких выводов интерфейс не делает.

Пустой доступный слой означает, что в выбранном снимке/области не найдены площадные контуры этой категории. Это не доказательство отсутствия объектов на местности. Недоступная геометрия, ошибка блока, загрузка и частичное покрытие имеют отдельные подписи. При частичном покрытии показывается только известная часть, а не выдуманные нули.

## Контракт и ограничение объёма

Нового источника/эндпоинта нет. Существующий `GET /api/v1/addresses/{id}/profile?radius_m=300|500` дополнен `map.area_layers.{parks,vegetation,water}`. Каждый элемент — `{status,data,message}`; `data` — FeatureCollection с покрытием, радиусом, source, dataset_import_id, observed_at, source_updated_at и качеством. Ошибка геометрии изолируется savepoint и не меняет блоки показателей. Если прежний блок не рассчитан, соответствующий слой также недоступен.

`OsmAreaMapService` получает те же зафиксированные ID снимков и оценку покрытия, что расчёты этого профиля; повторного выбора активного снимка нет. Передаются только фрагменты, имеющие площадное пересечение с областью:

`scope = ST_Intersection(ST_Buffer(point_32646, radius, 'quad_segs=64'), data_geom_32646)`.

Сначала выполняется bbox-фильтр по существующему GiST и ID снимка/признаку, затем пересечение каждого кандидата со scope, извлечение площадных частей и исключение пустых геометрий. Ответ преобразуется в EPSG:4326 lon/lat, GeoJSON с девятью знаками. Исходный полный контур большого парка или реки и полный городской слой в браузер не отправляются. Геометрия за пределами data_geom не передаётся. UNKNOWN/OUTSIDE_SERVICE_AREA или отсутствие набора дают пустой **недоступный** слой.

Три ограниченных набора входят в обычный ответ профиля даже при выключенных флажках; переключение меняет только видимость fill/line и не делает сетевых запросов. Новых показателей, радиусов, схемы, состава/активности снимков и исходных данных нет. Формулы существующих показателей не изменены. Отображение контура обрезки использует метрический круг расчёта площадей EPSG:32646; существующий круг радиуса карты из транспортного API сохранён.

## Сохранность

Браузер/сверка работали на временном read-only PHP-стенде, с отдельным временным storage, array-сессиями/кэшем и `PGOPTIONS=-c default_transaction_read_only=on`. Только тестовый PHP-процесс отключал read-only и принудительно использовал новую изолированную БД. Рабочая БД не получала записей. Хеши всех строк 11 таблиц до/после совпали: снимки, покрытие, остановки/маршруты/связи, адреса, здания, дороги, пути, зелень, вода. Все прежние поля 10 профилей, включая показатели/качество/транспорт и старые map-поля, совпали после исключения времени расчёта и нового map.area_layers.

Существующие правки не сбрасывались; код добавлен поверх них. Проверены 722 существовавших файла, включая 65 файлов data/raw и .env: удалений и неожиданных изменений нет. Новые локальные артефакты проверок — `data/reports/area-map-layers-2026-10-20/` (игнорируется Git): исходные/итоговые сверки, bounded-проверки, browser script/results/screenshots, логи, отчёт сохранности файлов. Старые отчёты не переписывались. Временный стенд и созданная тестовая БД удалены по завершении. `git diff --check` пройден.

Для повторения frontend-проверок: `docker compose exec -T node npm test` и `docker compose exec -T node npm run typecheck`. GIS-тест `tests/Integration/OsmAreaMapTest.php` требует отдельной разрешённой тестовой БД с текущей схемой; в рабочую БД его запускать нельзя. Браузерный сценарий использует только тестовое перехватывание MapLibre-конструктора, продуктовых hooks нет. Новые слои к следующему этапу не переходят.
