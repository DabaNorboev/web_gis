# Локальный поиск адресов

Текущий контракт локального поиска и явного выбора объекта. Предполагаемая задача поиска не меняет API этим документом. Прежние замеры и результаты проверок — [история](../history/ui-contract-notes-2026-11-01.md#поиск-исправление-и-замеры-20-октября).

`GET /api/v1/addresses/search?q=Мира%2010` ищет только в активном снимке OpenStreetMap/addresses. Внешних запросов нет. Параметр `q` — строка от 3 до 160 символов; неправильный ввод возвращает JSON/422. Не более 120 запросов в минуту на IP, до 10 результатов.

Ответ: `data` — до 10 адресных групп с `id`, `label`, `match_type`, `object_count`, `bounds` и `objects`. У каждого объекта — OSM `id`, `lon`, `lat`, исходная `geometry`, `point_method`, `object_type`, известная `levels`; `meta` — источник, ID снимка, даты и качество. `meta.unknown_locality_allowed` явно сообщает, что городской контекст допускает объекты без указанного населённого пункта; это не подтверждение их принадлежности Красноярску. ID группы `address:<sha256>` вычисляется из нормализованных населённого пункта, улицы, места и номера и не обозначает каноническое здание. ID конкретного объекта вида `osm:way:403615986` сохраняет тип OSM-объекта; внутренний ключ строки не используется как постоянный ID. При отсутствии снимка список пустой и availability=UNAVAILABLE. Пустой результат доступного снимка не доказывает отсутствия адреса на местности. observed_at неизвестна, freshness=UNKNOWN; timestamp базы OSM не подменяет наблюдение.

## Правила поиска

- `osm_address_normalize` приводит регистр, ё/е, пробелы, пунктуацию и сокращения ул./пр-т/просп./пр./пер./д./дом. Исходные подписи и теги сохраняются.
- Исходный вычисляемый `search_text` сохраняется. Поиск читает производную `osm_address_search_entries`: поисковую подпись, ключи номера/населённого пункта/группы и заранее определённый объект для каждой исходной строки. GIN/[pg_trgm](https://www.postgresql.org/docs/16/pgtrgm.html) индексирует производный текст; B-tree — снимок/номер и снимок/группу. Пространственное сопоставление выполняется при подготовке снимка, не при HTTP-запросе. Выдача только сериализует геометрии выбранных объектов.
- Сначала ищутся все слова с совпадением начала слова, независимо от порядка. Если результатов меньше десяти, добавляются приблизительные совпадения для слов от четырёх символов; порог word_similarity — 0,6, задан в транзакции запроса. Они помечаются `match_type: approximate`; строгие совпадения идут первыми.
- Последний числовой токен после текстовой части считается номером дома и сравнивается отдельно целиком после нормализации. `10`, `100`, `10А`, `10/2А` не подменяются друг другом. Номера с несколькими токенами («10 корпус 2»), сложные варианты записи, транслитерация и любые опечатки не гарантированы; исходные вторичные адреса пока не участвуют.
- Адресная точка становится поисковым синонимом контура, если её покрывает ровно один адресный контур здания того же снимка с совпадающими улицей/местом и номером. Населённые пункты должны совпадать либо отсутствовать у одной из записей; противоречащие известные значения запрещают сопоставление. При неоднозначных контурах точка остаётся самостоятельным объектом. Подсказка использует контур, но находится и по исходной подписи точки, включая явно указанный город. Сырые строки не удаляются. Одинаковые нормализованные части адреса объединяются только в одну подсказку. Разные населённые пункты и улицы, в том числе улица/проспект Мира, остаются разными группами. Контуры и точки не сливаются в БД, все несокрытые объекты группы доступны для отдельного выбора. Лимит 10 применяется к группам, а не объектам. Общие границы группы вычисляются на backend из исходных геометрий; близость не является критерием группировки.
- Точные отдельные слова `Красноярск` / `Krasnoyarsk`, в том числе с `г.` / `город` и после адреса, задают контекст локального поиска и исключаются из адресных токенов до разбора номера. Контекст допускает записи с неизвестным населённым пунктом и исключает явно указанные другие населённые пункты. Это не подтверждение принадлежности каждой неизвестной записи Красноярску: граница набора не равна границе населённого пункта. Ограничение сообщается в `meta.quality.reason`. Запрос только с названием города не возвращает весь набор. Без этого контекста поиск по другим населённым пунктам сохраняется.
- `osm_address_locality_key` нормализует `Красноярск`, `Krasnoyarsk`, `г. Красноярск`, регистр и пробелы в производных ключах групп и сопоставлений. Исходные `locality`, `label`, теги и геометрии не изменяются; неизвестное значение остаётся неизвестным. Противоречащие известные населённые пункты не объединяются. ID текстовой группы может измениться после нормализации/уточнения адреса и не является постоянным ID места.

## Подготовка поиска

Миграция `2026_10_20_000001_prepare_osm_address_search` создаёт производную таблицу, индексы и функции, затем заполняет поиск для уже существующих успешных адресных снимков. Применение: `docker compose exec php php artisan migrate`. Перескачивать или переимпортировать исходник не требуется. Откат новой миграции удаляет только производную таблицу/функции и добавленное ограничение; исходные строки и `pg_trgm` сохраняются. Код сервиса и миграцию развёртывать согласованно: новый поиск требует подготовленной таблицы.

Будущий импорт вызывает `osm_address_search_rebuild(import_id)` после записи адресов, перед переключением активного снимка, в одной транзакции. Сбой подготовки оставляет старый снимок и его поиск активными; новая попытка получает `failed`. Backfill миграции использует ту же advisory-блокировку, что импорт адресов. Составные FK запрещают поисковым связям пересекать снимки. Это производный поисковый индекс, не канонический реестр мест; исходные снимки остаются независимыми и неизменными.

## Главная

На главной добавление/замена А/Б открывает немодальное окно с доступной общей картой; поиск в редакторе важного места использует тот же механизм выбора. Прямые профиль и сравнение сохраняют собственные поля и карту вариантов. Поиск не рассчитывает окружение до выбора объекта, но подтверждение адреса А/Б в работающей версии автоматически загружает профиль. Сценарий без автоматической аналитики — [предложение](../plans/search-task-contract.md).

Ввод → debounce 300 мс → локальный API → явный выбор подсказки → выбор конкретного объекта. До выбора показаны геометрии текущей выдачи. Группа с несколькими объектами не назначает главный; единственный объект выбирается только после явного подтверждения подсказки. Наведение/фокус дают подсветку, не меняют текущий адрес или URL. Примерные совпадения подписаны.

Стрелки перемещают выделение подсказки, Enter подтверждает её; без выделения Enter запускает поиск. Escape закрывает список, не подтверждая объект. Кнопки объектов доступны стрелками, Enter/Space и нажатием; hover для телефона не обязателен. Нажатие объекта в списке или на карте передаёт его точный OSM ID без дополнительного подтверждения. Номера объектов согласованы в списке/карте; экранные подписи не сдвигают исходную геометрию.

Старый запрос отменяется, поздний ответ игнорируется, timeout — 10 с. Новый ввод/очистка снимают прежний preview; первый ответ не подтверждается автоматически. Пустая выдача, ошибка/повтор, загрузка и недоступный набор различаются. Этажность берётся из исходных тегов; ни номер в списке, ни контур не доказывают подъезд или физическое отдельное здание.

После выбора поведение определяется страницей: [профиль](address-profile.md), [сравнение](address-comparison.md), [поездки](trips.md). Свободная точка на главной получает [адресную подпись](point-analysis.md) без транспортного анализа и не подменяет сохранённые А/Б. Приблизительная подпись не присваивает точке ID. Камера и приоритеты preview — [контракт карты](home-workspace-map.md#предпросмотр-адреса-цели--v2).

## Проверка и измерение

Выбор тестов и побочные эффекты — [testing](../testing.md). `scripts/benchmark-address-search.php` измеряет установленную реализацию, не восстанавливает старую; before/after — метки. Воспроизводимое сравнение требует двух закреплённых ревизий, одного снимка и сопоставимой среды/нагрузки, с новыми выходными путями без перезаписи. Прежние таблицы не являются свежим benchmark.
