# Локальный поиск адресов

На основном экране [Г6.4](#план-два-режима-поиска-г6) строка поиска по умолчанию использует локальный снимок OSM. Пользователь может переключиться на [Geoapify через Laravel](#переход-на-внешние-геокодеры). Ниже описан локальный API.

`GET /api/v1/addresses/search?q=Мира%2010` ищет только в активном снимке OpenStreetMap/addresses. Внешних запросов нет. Параметр `q` — строка от 3 до 160 символов; неправильный ввод возвращает JSON/422. Не более 120 запросов в минуту на IP, до 10 результатов.

`data` — до десяти групп `{id,label,match_type,object_count,bounds,objects}`. Объект: OSM `id` (например, `osm:way:403615986`), `lon/lat`, исходная `geometry`, `point_method`, `object_type`, известная `levels`, необязательный `display`. `address:<sha256>` — хэш нормализованных населённого пункта, улицы, места и номера. `meta`: источник, ID снимка, даты, качество. `observed_at` неизвестна, `freshness=UNKNOWN`. Без снимка `availability=UNAVAILABLE`.

У конкретного OSM-объекта необязательный `display: {address_line, house_number, district}`: сохранённые `street` (включая `associatedStreet`) или `place`, полный номер и `addr:district` либо `null`. Поля также доступны в `address.display` resolver и [ориентире точки](point-address.md#api-и-пространственная-методика). Старый ответ без `display` показывает `label` целиком.

## Правила поиска

- `osm_address_normalize` приводит регистр, ё/е, пробелы, пунктуацию и сокращения ул./пр-т/просп./пр./пер./д./дом. Исходные подписи и теги сохраняются.
- Исходный вычисляемый `search_text` сохраняется. Поиск читает производную `osm_address_search_entries`: поисковую подпись, ключи номера/населённого пункта/группы и заранее определённый объект для каждой исходной строки. GIN/[pg_trgm](https://www.postgresql.org/docs/16/pgtrgm.html) индексирует производный текст; B-tree — снимок/номер и снимок/группу. Пространственное сопоставление выполняется при подготовке снимка, не при HTTP-запросе. Выдача только сериализует геометрии выбранных объектов.
- Сначала ищутся все слова с совпадением начала слова, независимо от порядка. Если результатов меньше десяти, добавляются приблизительные совпадения для слов от четырёх символов; порог word_similarity — 0,6, задан в транзакции запроса. Они помечаются `match_type: approximate`; строгие совпадения идут первыми.
- Последний числовой токен после текстовой части считается номером дома и сравнивается отдельно целиком после нормализации. `10`, `100`, `10А`, `10/2А` не подменяются друг другом. Номера с несколькими токенами («10 корпус 2»), сложные варианты записи, транслитерация и любые опечатки не гарантированы; исходные вторичные адреса пока не участвуют.
- Точка становится поисковым синонимом, если её покрывает ровно один адресный контур здания того же снимка с совпадающими улицей/местом и номером. Населённые пункты совпадают либо неизвестны у одной из записей. При неоднозначности точка остаётся самостоятельной. Подсказка с контуром доступна и по подписи точки, включая город. Хранятся все исходные строки. Ключ группы — нормализованные части адреса, разные улицы и населённые пункты дают разные группы. Лимит десяти действует на группы, каждый несокрытый объект выбирается отдельно. Bounds вычисляются из исходных геометрий.
- Отдельные слова `Красноярск` / `Krasnoyarsk` (также с `г.` / `город` и после адреса) задают контекст и удаляются из токенов до разбора номера. Он исключает другие известные города и допускает неизвестные (`meta.unknown_locality_allowed`), без подтверждения принадлежности Красноярску. Ограничение указано в `meta.quality.reason`. Запрос только с городом не возвращает весь набор. Без контекста доступны и другие города.
- `osm_address_locality_key` нормализует варианты `Красноярск`, `Krasnoyarsk`, `г. Красноярск`, регистр и пробелы в ключах групп и сопоставлений. `locality`, `label`, теги и геометрии остаются исходными. ID текстовой группы может измениться при уточнении адреса или нормализации.

## Подготовка поиска

Миграция `2026_10_20_000001_prepare_osm_address_search` создаёт производную таблицу, индексы и функции, затем заполняет поиск для уже существующих успешных адресных снимков. Применение: `docker compose exec php php artisan migrate`. Перескачивать или переимпортировать исходник не требуется. Откат новой миграции удаляет только производную таблицу/функции и добавленное ограничение; исходные строки и `pg_trgm` сохраняются. Код сервиса и миграцию развёртывать согласованно: новый поиск требует подготовленной таблицы.

Импорт вызывает `osm_address_search_rebuild(import_id)` после записи адресов перед активацией в той же транзакции. Сбой оставляет старый поиск активным, попытка получает `failed`. Backfill использует advisory-блокировку импорта. Составные FK запрещают связи между снимками.

## Главная

Локальная выдача сохраняет группы API.

Пауза ввода 300 мс запускает поиск. Стрелки выделяют объект, Enter выбирает его или запускает поиск, Escape закрывает выдачу. Tab переводит фокус на кнопки списка и карты. Enter, Space и клик передают точный OSM-ID в resolver, затем запускается анализ v1.

В группе из нескольких объектов подписи различают здания, адресные точки и контуры. Номер варианта совпадает в списке и на карте. У одиночного объекта подпись и маркер показаны без номера варианта. Приблизительные совпадения помечены.

Камера берёт bounds первой группы или группы объекта под курсором или фокусом. Для предпросмотра действуют отступы карты и предел масштаба 16,5, чтобы сохранить контекст улицы. Список и карта подсвечивают один вариант по исходному контуру или точке. Перекрытые кнопки раздвигаются с линией к исходной позиции. При пересечении геометрий выберите номер. Атрибуция локального OSM размещена на карте.

Предпросмотр сохраняет место и анализ. Ввод, очистка, закрытие выдачи, свободная точка и смена режима снимают предпросмотр и отменяют запросы. Поздние ответы игнорируются. Таймаут — 10 с.

После выбора — [анализ](place-analysis.md#8-независимость-и-поздние-ответы); [ориентир точки](point-address.md#ориентир-точки-на-analysis) не присваивает ей адресный ID.

Воспроизводимое сравнение требует двух закреплённых ревизий, одного снимка и сопоставимой среды/нагрузки, с новыми выходными путями без перезаписи. Прежние таблицы не являются свежим benchmark.

## План: два режима поиска Г6

**Г6.4 локально активирован, владельческая приёмка открыта.** [Запуск и приёмка](../runbook-local.md#локальная-активация-г64), [очередь и диагностика](../plans/roadmap.md#г6-два-режима-поиска-и-выбор-точки).

- По умолчанию локальный поиск; в верхней панели кнопка «Поиск: локальный» / «Поиск: Geoapify». Без fan-out/автоматического fallback. Смена режима сохраняет текст и закрывает выдачу без запроса. В Geoapify уведомление о тексте стоит у поля, уведомление о координатах — у кнопки внешнего поиска поблизости.
- В Geoapify Enter в поле поиска открывает предпросмотр выделенной подсказки из открытой выдачи. Без такой подсказки Enter запускает один явный поиск по текущему тексту. Сброс выдачи, в том числе при смене режима или отмене предпросмотра, снимает выделение и очищает `aria-activedescendant`.
- Режим сохраняет место/радиус/результаты и сроки/reconfirm внешнего выбора. Поздние search/reverse/confirm/errors/finally другого режима игнорируются.
- Локальный выбор — OSM-объект/resolver/v1, внешний — snapshot/token/v2. Группа не ID; сопоставление по тексту/близости и общая серверная идентичность не вводятся.
- Короткие статусы различают сбой, недоступность и пустую выдачу. При пустом HTTP 200 учитывается `meta.quality.availability`. Анализ точки доступен независимо от поиска.
- [Компактное представление Г6](../frontend-structure.md#план-компактного-поиска-г6) используется в подсказках, предпросмотре и выбранном адресе. Одинаковые подписи получают номера вариантов в пределах выдачи.
- [Карточка точки](point-address.md#план-единая-карточка-точки-г6) одинакова в обоих режимах: анализ исходной точки или явный переход к локальному адресу.

## Переход на внешние геокодеры

**Г3–Г4 локально активированы на Г5; владельческая приёмка открыта.** Один адаптер Geoapify, без LocationIQ/fan-out/fallback; `building:null`, без автопривязки. [Г1](../research/geocoders-g1.md): 26/31 — текстовые совпадения; точность координат и домовая идентичность ИЖС/СНТ не подтверждены.

### API Г3

Публичные POST JSON без query/регистрации, только объявленные поля. Обязателен новый `request_id` (UUID v4) на каждую попытку, включая повтор. Тело ≤8 KiB; `Content-Type`/`Accept: application/json`. Координаты: конечные JSON numbers EPSG:4326 (`lon, lat`). Успех: `{data, meta}`; `meta` содержит `contract_version: 1`, эхо `request_id`, `provider: "geoapify"`, `scope_id: "krasnoyarsk-2026-10-07"`, `scope_sha256`, `received_at` (UTC ISO-8601), `cache: "MISS"|"HIT"|"NONE"`, `attribution` (массив `{text,url}`). `received_at` — исходное получение, не наблюдение; при HIT неизменно, без данных — `null`.

| Endpoint | JSON кроме `request_id` | `data` HTTP 200 |
|---|---|---|
| `/api/v1/geocoding/search` | `q`: 3–160 Unicode-символов после trim; `mode`: `autocomplete` или `search`, обязательно | `{status, reason, candidates}`; до 5 кандидатов. `autocomplete` после debounce, `search` по Enter/кнопке; без одновременного запуска. |
| `/api/v1/geocoding/reverse` | `lon`, `lat` в пределах WGS84 | `{status, reason, point:{lon,lat}, candidates}`; до 5 кандидатов; `point` — точный ввод. Внешний запрос только внутри scope. Вне scope — 200 `EMPTY / OUTSIDE_SCOPE` без сети. |
| `/api/v1/geocoding/confirm` | `candidate_token`: строка до 6144 байт; `position_confirmed: true` | `{selection_id, selection_token, expires_at, snapshot_expires_at, place}` — снимок адреса без сети. `cache: NONE`. |
| `/api/v1/geocoding/reconfirm` | `selection_token`: до 6144 байт; `position_confirmed: true` | Та же форма; [переподтверждение](#переподтверждение-снимка), без Geoapify. |

Для search/reverse `status`: `OK` (есть подтверждаемый адрес), `NO_SELECTABLE_RESULTS` (есть только ориентиры), `EMPTY` (кандидатов нет). `reason`: соответственно `null`, `POSITION_REQUIRES_POINT`, `NO_RESULTS`; если все результаты отфильтрованы территорией — `NO_IN_SCOPE_RESULTS`. Пустота не доказывает отсутствия дома. Строки: label ≤512 символов, provider_id ≤1024 байт, street ≤256, прочие ≤128; превышение — 502 без усечения. Кандидат:

| Поле | Контракт |
|---|---|
| `candidate_id` | UUID конкретного снимка; не ID места и не OSM-ID. |
| `provider_id` | `place_id` Geoapify или `null`; без ID подтверждение запрещено. Не канонический ID дома. |
| `label`, `components` | Исходная подпись; `{country_code, locality, street, number, district?}`. Обязательные компоненты с неизвестным значением равны `null`. `district` — непустая строка из одноимённого поля Geoapify длиной до 128 символов. Район опускается при отсутствии, непригодном значении или нехватке места в токене. `number`: `{raw, key, base, fraction, letter, corpus, structure, parse_status}`; `parse_status: COMPLETE|UNKNOWN`, неизвестные части — `null`. `raw` не теряется. |
| `point`, `point_reason` | `{lon,lat}` либо `null / COORDINATES_MISSING`; при наличии точки `point_reason: null`. |
| `precision` | `{level, reason, accuracy_m:null, accuracy_reason:"NOT_VALIDATED"}`. `level`: `house|street|locality` (`reason:null`) либо `null / PROVIDER_LEVEL_UNKNOWN`. Заявленный уровень, не измеренная ошибка/точность входа. |
| `number_match` | `EXACT`, `MISMATCH`, `UNKNOWN`, `NOT_REQUESTED`; по полному номеру ввода. Reverse — `NOT_REQUESTED`. |
| `within_scope` | `true` после PostGIS-проверки; `null` без координат. Внешние точки исключены из выдачи. |
| `source` | `{provider:"geoapify", provider_result_type, observed_at:null, source_updated_at:null, received_at, normalization_version:1, attribution}`. |
| `can_confirm`, `restrictions` | Boolean и массив фиксированных причин: `COORDINATES_MISSING`, `PROVIDER_ID_MISSING`, `HOUSE_REQUIRED`, `NUMBER_MISMATCH`, `NUMBER_UNVERIFIED`. Пустой массив только у подтверждаемого адреса. |
| `candidate_token`, `expires_at` | Зашифрованный снимок ≤6144 байт (больше — 502) на 15 минут; только при `can_confirm:true`, иначе `null`. Без текста запроса. |

`house`: только `result_type=building` + улица/полный номер/координаты. `street` → `street`; `city|town|village|suburb|district|county|state|country|postcode` → `locality` как укрупнённый ориентир; остальные типы → `null` с причиной. `confidence`/подпись уровень не повышают. Улица/местность/неизвестный уровень — только предпросмотр и уточнение **свободной точки**. Участок СНТ/ИЖС без уровня дома не становится домом.

### Территория и полный номер

Scope закреплён по существующему `data/raw/boundaries/krasnoyarsk/2026-10-07/boundary.geojson`, SHA-256 `0a631518e68855b2eba44a72429b9a11fa95e0de075c013f523eafa4b84ef5f8`. Сервисная OSM-граница, не юридическая/буфер POI. Адаптер search/autocomplete передаёт жёсткий `filter=rect:west,south,east,north` по bbox этой границы, `lang=ru`, `limit=5`, `format=json`; proximity bias не используется. PostGIS проверяет `ST_Covers(boundary, point)`: граница включена, внутренности отверстий исключены. Reverse проверяет исходную точку и результаты независимо от фильтра API. Нет валидной границы/hash — 503 `GEOCODING_UNAVAILABLE` без сети. Внешние результаты/чужая страна отбрасываются без расширяющего запроса. Граница поиска не меняет правила покрытия анализа свободной точки.

Нормализация v1: NFC, trim/сжатие пробелов, регистр/ё–е только в ключах, подписи отдельно. Номер сравнивается целиком: базовые цифры, дробь, литера, корпус и строение. Однозначные формы: `к|корп|корпус` → корпус, `стр|строение` → строение, `лит|литера` → литера; `10/2`, `10 к2`, `10 стр2`, `10А`, `100` различны. Слеш не превращается в корпус; латинские/кириллические буквы не сливаются; части не отбрасываются, даже если Geoapify их потерял. Разбор — только однозначное адресное окончание (`д.|дом` допустимы), не цифры названия улицы. Альтернативы через запятую/неоднозначная грамматика → `UNKNOWN`, без усечения. Части извлекаются из `housenumber`, не POI-названия. Алиасов/транслитерации в v1 нет.

`can_confirm:true` требует `within_scope:true`, provider ID, `level:house`, `number.parse_status:COMPLETE` и `number_match:EXACT|NOT_REQUESTED`. Пропуск/неоднозначность номера → `UNKNOWN`, отличие части → `MISMATCH`. Без номера ввода допускается явный выбор дома (`NOT_REQUESTED`). При несовпадении показывается ограничение: исправить ввод либо выбрать свободную точку без адресной идентичности.

### Подтверждение и передача в анализ

UI: `idle → debouncing → loading → results|empty|error`, выбор → `preview → confirming → selected`; timeout — `error`, отмена — `idle`. Черновик/preview не заменяют выбранное место и его анализ до успешного подтверждения. Смена черновика отменяет его подтверждение.

Кандидат → предпросмотр точки/подписи/уровня/источника → «Подтвердить положение» → confirm; строка сама не подтверждает. Сервер берёт снимок только из candidate-token (Laravel Crypt/APP_KEY, JSON v1, `purpose:geocoding_candidate`, снимок/проверки номера/scope/issued_at/expires_at). Bearer-секрет, без хранения; проверяются MAC/схема/purpose/срок/provider, критерии выбора и текущий scope (смена — 409 `SCOPE_CHANGED`). `position_confirmed:true` подтверждает действие UI, не точность.

Confirm выдаёт `selection_id` (UUID), `selection_token` (≤6144 байт, JSON v1, `purpose:geocoding_selection`, ID/снимок/issued_at/expires_at/snapshot_created_at/snapshot_expires_at). При первом выборе `snapshot_created_at=now`, `snapshot_expires_at=now+7 суток`, `expires_at=now+24 часа` (UTC). Это технические сроки, не лицензионные TTL. Повтор confirm может дать новый ID; для прежнего выбора — reconfirm. `place` имеет `{kind:"address", selection_id, label, point, address, building:null}`; `address` содержит `provider_id`, `components`, `precision`, `number_match`, `source`, `scope_id`, `scope_sha256`. Токен/внешний OSM-ID не локальная идентичность.

В `POST /api/v1/place-analysis` явно запрашивается v2: `{analysis_version:2, place:{kind:"address", selection_token:"…"}, radius_m:500, blocks:["poi"]}`; прочие параметры — [контракт анализа](place-analysis.md#2-вход). V2 только для внешнего адреса; точка/OSM остаются v1 без `analysis_version`. Смешение ID/координат/токена запрещено. Проверив токен/срок/схему/критерии снимка, сервер строит круг по его point без Geoapify/кэша. Валидный selection независим от provider/cache, scope hash берётся из снимка без пересчёта по новой границе.

Ответ v2: конверт блоков, `analysis_version:2`, `place` из confirm без токенов/фиктивного OSM `object`. UI сверяет версию/selection_id/весь снимок и обычные параметры/epoch. Три независимых запроса блоков используют один selection_token. При `now>=expires_at` — 410 `SELECTION_EXPIRED`; выбор/результаты неизменны, UI предлагает явное переподтверждение. Автоматического продления, reload/URL/долговременного хранения нет.

Свободная точка, reverse и переход к адресу — [сценарий Г5](point-address.md#внешний-ориентир-г5). Они не меняют legacy resolver.

### Переподтверждение снимка

Reconfirm принимает прежний selection-token из памяти страницы, не клиентские координаты/подпись. Проверяются MAC/схема/purpose/provider, критерии снимка и действующий scope/hash. Истёкший `expires_at` допустим только здесь, candidate-token запрещён. Обязательно: `snapshot_expires_at=snapshot_created_at+7 суток`, `snapshot_created_at<=issued_at<expires_at<=min(issued_at+24 часа,snapshot_expires_at)`, `issued_at<=now`. При `now>=snapshot_expires_at` — 410 `SNAPSHOT_EXPIRED` и новый поиск/выбор; смена scope — 409 `SCOPE_CHANGED`; непроверяемый токен — 422 `INVALID_SELECTION`.

Явное reconfirm сохраняет selection_id, place, исходные даты/атрибуцию и snapshot-времена; меняются только `issued_at=now`, `expires_at=min(now+24 часа,snapshot_expires_at)` и шифротекст. Повтор старого токена и цепочка обменов потолок не сдвигают. Запрос идёт к Laravel, без Geoapify/кэша; `meta.cache=NONE`, `received_at` исходный. UI: timeout 5 с, epoch-проверка; ошибка сохраняет выбор. Переподтверждение не обновляет данные источника.

Токены stateless, индивидуального отзыва нет; очистка кэша/выход из UI копии не отзывает. Новый APP_KEY при пустом APP_PREVIOUS_KEYS инвалидирует все токены; смена ключей вне задания. Expiry запрещает серверное принятие, не удаляет копии у клиента. UI убирает токены при сбросе/закрытии и абсолютном expiry; готовые результаты сохраняются на экране. Восстановления после закрытия и таблицы мест нет.

### Бюджеты и полное время операции

Бюджеты малого MVP, не SLA; меньшие лимиты тарифа приоритетны. Защиты общие для workers, отказ — 503.

| Предел | Значение и смысл |
|---|---|
| Клиент | debounce 350 мс, минимум 3 символа; один запрос search/reverse в работе и один заменяемый ожидающий ввод. Очереди по каждому нажатию нет. |
| API по IP | search+reverse суммарно 30/мин; confirm+reconfirm суммарно 60/мин. Фиксированные окна 60 с; анализ сохраняет свой лимит. IP берётся только через доверенные proxy, хранится как HMAC, не raw IP. |
| Внешняя сеть | 1 в работе на IP (все вкладки/режимы); 4 на приложение; старты не чаще одного за 500 мс, без burst. Занято/частота — 429, не очередь ожидания. Cache hit не занимает внешний слот. |
| Суточная квота | 2000 попыток на приложение за UTC-сутки, предварительное атомарное списание перед сетью, включая ошибки/таймауты. Не сбрасывать при рестарте; меньшая известная квота тарифа имеет приоритет. Запас к 3000 credits Г1, не подтверждение тарифа ключа. |
| Попытки | Один HTTP к Geoapify на cache miss. Redirects и автоматические retries выключены. Один ручной повтор после сбоя на неизменный ввод/точку; новая генерация поиска после редактирования не отменяет серверные лимиты. Успешную пустоту не повторять автоматически. |
| Время и размер | Connect ≤2 с, **весь внешний HTTP ≤8 с**, ответ ≤1 MiB после распаковки. UI: search/reverse ≤10 с, confirm ≤5 с, без гарантии остановки сервера. |

Г3: cURL `CURLOPT_CONNECTTIMEOUT_MS=2000`, `CURLOPT_TIMEOUT_MS=8000`, без redirect/retry, фиксированный HTTPS host/path Geoapify, TLS verify. Требуются `CURL_VERSION_ASYNCHDNS` и c-ares (`curl_version().ares` непустой); иначе 503 без перехода на stream/socket timeout. Таймер включает DNS/TCP/TLS/ожидание/чтение, write callback ограничивает распакованные байты. В целевом PHP: synthetic DNS/connect/headers/body stall, медленные чанки и размер. Ограничен transfer, не PHP/прокси/БД; deadline не обещается до проверки механизма.

Слот — DB advisory lock выделенного соединения — удерживается до закрытия cURL, включая abort клиента, без клиентского TTL. Счётчики атомарны. Смерть процесса освобождает lock; потеря lock в живом процессе останавливает transfer. Неопределённая попытка квоту не возвращает. HTTP вне GIS-транзакции; фильтрация отдельно с `statement_timeout=2s`, `lock_timeout=500ms`.

Abort, смена ввода/точки, закрытие и повтор увеличивают UI epoch; получение response/error/finally проверяет epoch, `request_id`, текущий ввод/точку и selection. А→Б→А не оживляет старый А. Через 10 с loading снят; поздняя выдача игнорируется. Занятый слот запрещает параллельный повтор. После timeout — только явное действие, после завершения — debounce актуального ввода. При успехе confirm выбранный снимок закрепляется, поздний поиск/reverse его не меняет.

### Ошибки

Для geocoding: `{code, message, request_id, retry_after_s}`; безопасное фиксированное `message`, без личных данных. `retry_after_s` — целые секунды/`null`, согласован с `Retry-After`. При неверном UUID/до Laravel `request_id:null`. Ошибки не превращаются в пустую выдачу.

| HTTP | `code` |
|---|---|
| 405 / 413 / 415 / 422 | `METHOD_NOT_ALLOWED` / `REQUEST_TOO_LARGE` / `UNSUPPORTED_MEDIA_TYPE` / `INVALID_REQUEST`; 422 также для неверного JSON, типов, диапазонов, query/лишних полей. |
| 422 | `INVALID_SELECTION` — повреждённый токен, чужое назначение/схема; не передавать детали криптографии. |
| 409 / 410 | `SCOPE_CHANGED` / `CANDIDATE_EXPIRED` (confirm) или `SELECTION_EXPIRED` (анализ), `SNAPSHOT_EXPIRED` (reconfirm). |
| 429 | `RATE_LIMITED` (локальная частота), `GEOCODING_BUSY` (слот), `PROVIDER_RATE_LIMITED` (upstream 429). Для busy повтор не ранее 2 с; для upstream минимум 60 с или большее валидное `Retry-After`. |
| 502 / 504 | `PROVIDER_RESPONSE_INVALID` (схема/размер/неожиданный HTTP) / `PROVIDER_TIMEOUT` (полный transfer timeout). |
| 503 | `GEOCODING_UNAVAILABLE` (ключ/транспорт/граница/locks/неподдержанный runtime), `GEOCODING_QUOTA_EXHAUSTED` (локальный суточный бюджет или явно установленная квота поставщика). |

Upstream 401/403 выключает сеть до исправления; generic 403 не квота. 429 — общий cooldown ≥60 с/Retry-After без спящих запросов. Локальная квота — до следующих UTC-суток; upstream-квота без reset — cooldown 1 ч с указанием неизвестного срока восстановления. Сбой confirm сохраняет выбор, без запуска анализа адреса.

Коды токенов действуют и в анализе v2; конверт его ошибок прежний.

### Кэш, выбранное место и приватность

| Данные | TTL |
|---|---|
| Нормализованные search/autocomplete | 5 минут, независимо для mode |
| Reverse для точной исходной пары | 1 час |
| Пустота HTTP 200 | 60 секунд; `NO_SELECTABLE_RESULTS` — обычный положительный кэш ориентиров |

5 минут ограничивают вариативные подсказки, 1 час — повтор reverse; это стартовые TTL, не свежесть источника. Ошибки не дают отрицательного кэша; cooldown отдельно. Details HTTP/кэша выбранных мест нет: координаты уже в выдаче, снимок в selection_token. Candidate-token выдаётся заново из проверенного кэша (15 минут), даты исходных данных сохраняются.

Ключ: HMAC-SHA256 с серверным ключом от версии контракта/нормализации, provider, method/mode, scope hash, языка/limit/filter и полного нормализованного ввода либо точных IEEE-754 lon/lat (без округления, −0→0). Обычный hash запрещён. Суффиксы/дроби/алфавиты различаются; неизвестный разбор сохраняет полную строку.

Выделенный database-cache prefix: ≤5000 записей, ≤16 MiB зашифрованных значений, ≤32 KiB/запись; превышающий размер ответ не кэшируется. Атомарное вытеснение под lock: просроченные, затем старейшие до обоих лимитов; HIT не продлевает TTL. Laravel Crypt, только нормализованные данные, без raw/ввода/токенов. Очистка при обращениях, без scheduler: просроченное не читается, физически остаётся до обращения. Защитные счётчики отдельно: rate/IP ≤24 ч, суточный до конца окна +24 ч, cooldown до reset; без ввода/координат. Переполнение запрещает запись; отказ защиты сети — 503.

Кэш не меняет ID/точку/подпись/происхождение/точность выбора. Необязательный `components.district` сохраняется от кандидата до снимка и при переподтверждении. Старые записи кэша и токены читаются с прежним набором полей, версия схемы и сроки сохраняются. Снимок/токен — память экрана, не storage/URL. Старые OSM API/ID/данные сохраняются. Старый `place.address_id` разрешается только локальным resolver; provider ID и токены туда не принимаются, соответствие по тексту/координатам не создаётся.

До ввода — уведомление о передаче текста в API Geoapify. У карты — `Powered by Geoapify` со ссылкой `https://www.geoapify.com/` и атрибуция источников; OSM — `© OpenStreetMap contributors`, `https://www.openstreetmap.org/copyright`. Массив `{text,url}` включён в `source.attribution` защищённого снимка, показывается при использовании; атрибуция подложки его не заменяет. [FAQ хранения](https://www.geoapify.com/geocoding-api/) разрешает хранение с атрибуцией; тариф проверяется до подключения. Reverse — по [явному действию](point-address.md#внешний-ориентир-г5). Во внешний API передаются только текст либо lon/lat, язык/scope/limit, серверный ключ/IP; без browser IP/ID, cookies, Referer, selection_token, радиуса, станций и результатов.

Новые пути/анализ v2 наследуют [защиты POST](place-analysis.md#21-приватность-нового-post): no-store/no-referrer, безопасные логи/ошибки, без spool тел. Nginx/FPM/APM/HTTP-клиент не журналируют тела/заголовки/токены/исходящие URL с ключом и вводом; только фиксированный код/метод/длительность/счётчики. Исключения без message/arguments, включая debug; CORS чужим origin закрыт. Ключи не попадают в bundle/отчёты, .env не перезаписывается.

**Г5:** локально активирован Geoapify Free; владельческая приёмка открыта. [Запуск/возврат](../runbook-local.md#локальное-геокодирование-г5), [проверки/ограничения](../testing.md#локальная-проверка-г5).
