# Парки, растительные территории и площади

Категории `parks`, `vegetation`, `water` сервиса `OsmAreaAnalysisService` подключены к [профилю](address-profile.md), [сравнению](address-comparison.md) и их [картографическим слоям](map-area-layers.md). Это картографические площади OSM, отдельные от спутникового NDVI.

## Независимые признаки

Миграция `2026_10_20_000003_add_independent_green_area_flags` добавляет в `osm_green_areas` вычисляемые хранимые boolean-поля. Они автоматически заполняются из `raw_data.tags` для существующих и будущих строк:

| Поле | Условие |
|---|---|
| `is_park` | `leisure=park` |
| `is_garden` | `leisure=garden` |
| `is_vegetation` | `natural=wood,scrub,grassland,heath` **или** `landuse=forest,grass,meadow,village_green,orchard` |

Парк с `natural=grassland` обладает обоими признаками. Парк без растительного тега не становится растительной территорией. Сад не объявляется парком; при растительном теге он может входить в растительные территории. `access=private` не удаляет исходный объект и не превращает его в общественный парк: исходное значение доступа возвращается у ближайшего объекта, ограничения объясняются в качестве результата. Отсутствие тега доступа не означает разрешённый проход.

`feature_type` / `representation` остаются историческим описанием **основного тега отбора** по прежнему приоритету. Сырые теги и геометрии не переписываются. `representation_counts` в старых отчётах импорта — статистика основного представления, не полный перечень парков. Для продуктовых категорий использовать независимые флаги, а не `representation='recreation_boundary'`. Так Татышев и Гвардейский парк не теряются из списка парков.

Применение: `docker compose exec php php artisan migrate`. Переимпорт и скачивание не нужны. Миграция использует блокировку импортера зелени; откат удаляет только новые производные столбцы. Исходные снимки и их поля сохраняются. Независимые признаки входят в версию методики `osm_area_union_utm46_flags_v1`; при изменении правил требуется новая миграция/версия методики.

## Площадь и доля

Для заданной точки и радиуса 300 или 500 м:

1. Точка преобразуется из EPSG:4326 в EPSG:32646 (UTM 46N). Строится `C = ST_Buffer(point_utm, radius_m, 'quad_segs=64')` — круг, аппроксимированный 256 отрезками.
2. По активному снимку и независимому признаку отбираются кандидаты; существующий GiST по геометрии используется для bbox-фильтра `geom && ST_Transform(C,4326)`.
3. Каждый полигон переводится в EPSG:32646 и пересекается с `C`. Из пересечения извлекаются площадные части: `ST_CollectionExtract(ST_Intersection(...),3)`.
4. Пересечения **объединяются**: `U = ST_UnaryUnion(ST_Collect(...))`. Площадь `A = ST_Area(U)`. Это убирает повторный счёт перекрытий, одинаковых геометрий разных OSM-объектов и вложенных контуров. Отверстия сохраняются; исходные строки не удаляются и не сливаются.
5. Доля равна `100 * A / ST_Area(C)`. Площадь — м² с округлением до 0,01 м², доля — проценты с четырьмя знаками. Сумма площадей исходных полигонов для этой формулы не используется; произвольного ограничения результата до 100% для маскировки ошибок нет.

Каждая категория рассчитывается отдельно. Полигон с обоими признаками может входить и в парк, и в растительные территории. Доли этих категорий **нельзя складывать**. Вода также самостоятельна: пересечения картографических категорий не превращаются в общую оценку территории.

Радиус площади задан в согласованной метрической проекции. Это отличается от геодезического круга на величину искажения проекции и аппроксимации. Транспортные расстояния и проверка пространственного покрытия по-прежнему используют geography; отображаемый на карте полигон — приближение. Формула площади не вычисляется в градусах.

## Ограничения и качество

Результат описывает **картографические территории с согласованными тегами OSM**. Он не является измеренной долей растительности, крон деревьев, благоустройства, NDVI или оценкой пригодности места для жизни. Даже `100%` означает только покрытие круга такими исходными полигонами. Парк может включать дорожки, воду и здания; водный полигон не гарантирует постоянную воду или доступный берег. Пропущенные и отклонённые при импорте объекты остаются ограничением источника.

Сервис один раз фиксирует активные `dataset_import_id` зелени и воды; парки и растительные территории используют один снимок. Наборы независимы: отсутствие воды не скрывает доступные показатели зелени и наоборот. `method_version`, источник, ID импорта, `observed_at`, `source_updated_at`, `calculated_at` и `quality` сопровождают показатели. Версия базы OSM не подменяет наблюдение; `freshness=UNKNOWN`, пока нет согласованного правила достаточной актуальности. Метод — `DERIVED` для расчёта по картографическим данным, без результата — `null`.

[Покрытие](coverage.md) проверяется по каждому источнику. Нет источника, неизвестный охват или точка вне территории — `value=null` / `UNAVAILABLE`; неполный радиус — площадь и доля `null` / `INSUFFICIENT_DATA`. Пустое пересечение при доступном снимке и полном радиусе — **0** именно по выбранным картографическим тегам, а не подтверждение отсутствия зелени на местности.

Ближайший объект выбирается точным расстоянием geography до геометрии. Ноль означает попадание в контур, а не наличие входа. Поиск ограничен подтверждённой областью данных; без найденного объекта расстояние `null` / `INSUFFICIENT_DATA`, а не ноль. Расстояние может превышать радиус подсчёта площади. Исходные ID, имя и известный тег `access` сохраняются в результате.
