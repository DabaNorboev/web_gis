# Автомобильная уличная привязка и явный выбор

Документ относится к автомобильной привязке; пеший контракт — [walking-backend](walking-backend.md). Новых проверок runtime при переносе не было. Общие обещания и лимиты — [trips](trips.md).

## Реализация и правило выбора

`RoutingGeometryGuard::resolve` читает только проверенные
ячейки прежнего runtime; пространственные операции выполняются в PostGIS,
в транзакции READ ONLY с statement_timeout1500ms. Новых источников/графов нет.

Кандидаты — локальные минимумы расстояния до исходных сегментов автомобильных
ways. Соседние отрезки прямой не превращаются в множество вариантов, но два
положения на одном hairpin-way остаются разными. Дороги с неподтверждённым
автомобильным доступом/применимыми условиями, indoor/area/construction исключены.
Иерархия `motorcar → motor_vehicle → vehicle → access` сохранена.

Внутри прежних35м ближайший безопасный кандидат используется автоматически,
если в полосе **1м** от его расстояния нет другого варианта. Это консервативное
инженерное правило: четыре прежних допуска геометрического совпадения0,25м и
существующий1м запас у конца соединителя в проверке пересечения дороги. Оно не
объявляется измеренной точностью OSM/GPS или доказанным городским нормативом.
Граница полосы проверена на симметричных сторонах, разнице около0,56/1,34м,
раздельных source IDs, общей вершине и изгибе одного way. Неоднозначность всегда
требует выбора. Прежний35м радиус не расширен ради сохранения успешных пар.

Дубли объединяются только в одной исходной OSM-вершине при совпадении точки
в пределах0,25м. Параллельные линии с разными IDs не объединяются по близости.
Если найдено более16вариантов в близкой полосе, результат консервативно
отклоняется: список не обрезается до якобы единственного кандидата.

Ручной выбор проецируется к локальной дороге в тех же пределах35м от исходной
точки и с теми же проверками. При указании закрытой/недопустимой ближайшей дороги
поиск не перепрыгивает на существенно более дальнюю безопасную альтернативу.
Близкие равноценные положения вновь требуют выбора. Точка из URL не считается
доверенной и проверяется заново. После разрешения OSRM получает дорожные точки
с radiuses0,25;0,25; фактические концы линии должны совпасть с выбранными в том
же допуске, а с исходными — оставаться в35м. Самостоятельная перепривязка OSRM
к другой стороне не принимается.

`connector-issues.sql` общий для поиска и проверки итогового пути. Разрешён
только непрерывный начальный участок соединителя внутри содержащего исходную
точку здания; дорожная точка внутри здания, выход с повторным входом, другие
здания, явные стены/ограды, private/unknown gate-nodes, вода, железная дорога,
пересечение другой проезжей части и выход за пилот блокируют привязку. Это
смысловая связь точки здания с дорогой, **не доказанный проход через вход**.
Пунктир не включён в метры/секунды. Неразрешённый реальный доступ остаётся
неизвестным. Общая проверка автомобильной линии по node annotations, private
edges любой длины, gate access, направлению и препятствиям сохранена.

## Интерфейс и ссылка

Исходный маркер S/1–3 сохраняется. Отдельно показаны белая дорожная точка,
тонкий пунктир и расстояние привязки. Кандидаты — жёлтые точки с номерами и
доступными с клавиатуры кнопками; есть приближение к вариантам. Кнопка изменения
дорожной точки переводит карту в явный режим; выбор другого положения не меняет
исходные координаты. Добавление нового места возвращает режим исходной точки.

Расстояние вынесено главным числом, у каждого времени отдельная подпись
«модельное время без актуальных пробок». Рядом указано, что парковка и путь от
здания до дороги не учтены. Для вручную выбранной точки формулировка говорит о
выбранной проезжей части, без обещания, что она ближайшая. Таблицы скоростей,
поворотные штрафы OSRM и сортировка вариантов не менялись. Для оценки обычного
городского времени нужны независимые наблюдения поездок/режимов светофоров/
замедлений и проверка скоростей на кривых; такая калибровка — отдельное задание.

Совместимая схема version1 расширена необязательным `road:{lon,lat}` у start
и каждого place. Исходные координаты/подписи и выбранные road-положения находятся
в `/trips#trip=...`, без query и без округления. Старые version1-ссылки без road
поддержаны; старый query мигрирует по прежнему безопасному правилу. Автоматический
выбор дописывается через replaceState в текущую запись истории, ручное изменение
создаёт новую запись. Reload/back/forward восстанавливают обе точки и проверяют
их снова; результат маршрута не архивируется. Редактирование исходной точки
сбрасывает её road-выбор и немедленно убирает старые линии; поздние ответы не
возвращают их. Чужой отказ не скрывает успешную пару.

## Явный выбор кандидата

- `SNAP_CHOICE_REQUIRED` — синее немодальное ожидание: маршрут пока не рассчитан,
  нужно выбрать сторону/проезд. Отказы по доступу, ограде, отсутствию кандидата,
  пути, границе и недоступности сохраняют свои сообщения.
- В соответствующей карточке список с теми же индексами, что на карте. Каждый
  вариант показывает расстояние от исходной точки; название берётся только из
  `name` проверенной исходной дороги. У общего узла с разными названиями имя
  опускается. Назначение проезда не предполагается.
- Маркеры — кнопки с доступными подписями и `aria-pressed`. Hover/focus связывают
  подсветку списка и карты; последнее взаимодействие определяет подсветку,
  выбранный вариант остаётся зелёным с галочкой. Близкие значки разнесены только
  в пикселях с тонкими указателями к реальным позициям; координаты неизменны.
- Явный выбор передаётся провайдеру как прежний road hint и заново проходит
  resolver, обе привязки и GIS-защиту. До выбора этой пары HTTP к OSRM нет.
  Исходный маркер сохраняется, выбранная дорожная точка показана отдельно с
  пунктирным соединителем. Соединитель не включён в длину/время.
- Пока выбранный вариант проверяется, его старая линия/метрики очищены;
  соседняя успешная поездка остаётся видимой. Карта, форма и варианты доступны.
  Ответы после изменения исходной точки игнорируются; старый road hint, список
  и результат очищаются. Ошибочный сохранённый hint не помечает неоднозначный
  вариант выбранным.
- Ссылка использует прежний `#trip=` с исходной и дорожной точками; query не
  добавляется. Reload/back/forward заново проверяют выбор. В пределах текущего
  расчёта альтернативы остаются для переключения; ссылка сохраняет выбранную
  точку, а не кэш остальных кандидатов. После открытия она перепроверяется,
  прежние номера альтернатив не являются постоянными идентификаторами.

Полный исходный протокол сохранён в [истории](../history/local-routing-snap-2026-10-21.md); читать только по прямому указанию.
