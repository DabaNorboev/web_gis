dcdc# Схема данных

Миграции создают транспортную схему и отдельные снимки адресов, зданий, линий и площадных объектов OSM в PostgreSQL/PostGIS. Импортеры и транспортный HTTP API реализованы. Запуск — в [инструкции импорта](data/transport-import.md).

| Таблица | Содержимое |
|---|---|
| `dataset_imports` | Источник/набор, версия, даты, SHA-256 входа и конфигурации, статус, результат, активность |
| `dataset_coverages` | Сервисная территория и область отбора одного импорта, буфер в метрах и хеши границ; географическое покрытие отдельно от полноты/актуальности источника |
| `transport_stops` | ID остановки в источнике, название, адрес, точка, `raw_data`, связь с импортом |
| `transport_routes` | Исходный ключ, `mode`, `ref`, `raw_data`, связь с импортом; без геометрии трассы |
| `transport_stop_routes` | Уникальная связь остановки и маршрута одного снимка |
| `osm_buildings` | Контуры зданий и частей, флаг границы, исходные связи, исключения повторного счёта и происхождение |
| `osm_green_areas` / `osm_water` | Исходные растительные территории, границы парков/садов и водные площади с происхождением |
| `osm_roads` / `osm_railways` | Исходные линии крупных дорог / железнодорожных путей, тип, флаг границы и происхождение |
| `osm_addresses` | Адресный OSM-объект в снимке, структурные части, исходный контур/точка, точка анализа и происхождение |
| `osm_address_search_entries` | Производные поисковые ключи и связи исходных адресных строк с выбираемыми объектами того же снимка; не реестр мест |

## Снимки и идентификаторы

- Логический ключ остановки: `(source, dataset_key, source_id)`. Для CSV `source_id` — строковый `id`; стабильность между версиями не подтверждена. Для OSM в ключ входит тип: `node/123`, `way/123`, `relation/123`.
- В снимке уникален `(dataset_import_id, source_id)`. Внутренний `id` меняется между снимками и не является постоянным внешним ID.
- Ключ маршрута — `mode:ref`, например `bus:7`. Виды: `bus`, `trolleybus`, `tram`, `unknown`; уникален также `(dataset_import_id, mode, ref)`. Направления одной линии не считаются разными маршрутами.
- Новый импорт создаёт отдельные строки. Составные внешние ключи запрещают связи между снимками; удаление связанных строк ограничено.
- На `(source, dataset_key)` допускается один активный успешный импорт. Загрузка строк и переключение активного снимка атомарны; при ошибке старый снимок остаётся активным, попытка получает `failed`.
- Повтор успешного входа определяется по SHA-256 файла и конфигурации (64 строчных hex-символа); частичный уникальный индекс запрещает дубликаты. Неудачу можно повторить. Повтор исторического входа не реактивирует его.
- Для нескольких SQL-расчётов одного запроса фиксировать активный `dataset_import_id` один раз. Исчезнувшие объекты исключаются из текущей выдачи, история сохраняется; это не доказывает закрытие объекта. Очистка истории требует отдельного решения.

## Даты и качество

`source_version`/`source_updated_at` описывают исходник; `observed_at` — известную дату наблюдения. Дата публикации или импорта не заменяет наблюдение. Время обработки — `started_at`/`finished_at` (`timestamptz`); обмен датами — UTC.

Статусы: `running` (без завершения), `succeeded`, `failed` (завершение не раньше начала). `row_count` — число принятых объектов соответствующего набора, `null` при неизвестном результате. Статистика и предупреждения — `result`, причина сбоя — `error_message`. Исходные поля остаются в `raw_data`. Неизвестный тип и пустой перечень маршрутов не означают ноль маршрутов.

## GIS и проверки

- Точки — непустые двумерные `geometry(Point, 4326)`. Порядок: `lon, lat`; диапазоны ±180/±90. Ошибочные координаты не подменяются; отбор города выполняется границей.
- Расстояния/радиусы — метры через `geom::geography`. Для площадей — `ST_Transform` в EPSG:32646 (WGS84 / UTM 46N); формулу и SRID фиксировать для показателя.
- GiST-индексы созданы отдельно для `geom` и выражения `geom::geography`. Индекс geometry не заменяет индекс выражения. Пример поиска: `ST_DWithin(geom::geography, ST_SetSRID(ST_MakePoint(:lon, :lat), 4326)::geography, 500)`.
- Миграция подключает PostGIS; её откат сохраняет расширение. Применение: `docker compose exec php php artisan migrate`.
- GIS-тесты: `tests/Integration`, отдельная `web_gis_test`, запуск `sh scripts/init-test-db.sh` и `docker compose exec php composer test:postgis`. Проверяются ограничения, индексы, метры, снимки и откат/повтор миграций в изолированной тестовой схеме. Обычные тесты используют SQLite; предметная GIS-схема требует PostgreSQL.

[PostGIS ST_DWithin](https://postgis.net/docs/ST_DWithin.html).

С 20.10.2026 остановки, линии и площади OSM публикуют запись `dataset_coverages` атомарно со своим снимком. `service_geom` / `data_geom` — валидные непустые 2D Polygon/MultiPolygon4326, область данных покрывает сервисную. Первичный/FK `dataset_import_id` запрещает подмену области между снимками; выбор записи по этому ключу, отдельный GiST для единственного полигона снимка не требуется. Буфер подготавливается в EPSG:32646, доступный радиус проверяется по geography. Старые снимки без метаданных не получают выдуманного покрытия. [Формулы, API-статусы и текущие буферные снимки](features/coverage.md).

## Адресные снимки OSM

`osm_addresses`: уникальность `(dataset_import_id, osm_type, osm_id)`, FK на журнал, `source_geom` Point/Polygon/MultiPolygon и `geom` Point в EPSG:4326. Точка покрывается исходной геометрией; для узла сохраняется исходная координата, для контура — ST_PointOnSurface. GiST создан для обеих геометрий и выражения `geom::geography`. Текст адреса не уникален; одинаковые подписи не объединяются. Данные импортируются отдельным активным набором OpenStreetMap/addresses; дата наблюдения неизвестна. [Команда, правила и ограничения](data/osm-addresses.md). Вычисляемый search_text, GIN/pg_trgm и локальный API реализованы в Stage 5; [правила поиска](features/address-search.md).

С 20.10.2026 HTTP-поиск читает `osm_address_search_entries`. Одна запись на исходный `address_id`, выбираемый `object_id`, `dataset_import_id`, нормализованные `group_key`, `house_key`, `locality_key`, исходная поисковая подпись и текст. Составные FK на `(id,dataset_import_id)` запрещают связи между снимками. Пространственная проверка синонимов — в `osm_address_search_rebuild`, при импорте до атомарной публикации; миграция заполняет существующие успешные снимки. Индексы: GIN текста, B-tree снимка/номера, снимка/группы и выбираемого объекта/снимка. Нормализация населённого пункта применяется только к производным ключам, не меняет `osm_addresses`. Подробности городского контекста, миграции и замеры — в [правилах поиска](features/address-search.md).

## Снимки зданий OSM

`osm_buildings`: уникальность `(dataset_import_id, osm_type, osm_id)`, FK на журнал, валидная непустая 2D Polygon/MultiPolygon `geom` в EPSG:4326, GiST по geometry. `feature_kind` разделяет building/part; `crosses_boundary` отмечает сохранённый целиком контур на границе. `parent_relations` сохраняет OSM-ссылки; `count_exclusion` отмечает way, покрываемую валидным зданием-relation с явной ролью outer. Объект при этом не удаляется. Отдельный dataset_key=`buildings`, без переключения адресов/остановок. [Команда и правила](data/osm-buildings.md). География/проекция и соответствующие индексы для будущих расчётов выбираются при реализации показателей.

## Линейные снимки OSM

`osm_roads` / `osm_railways`: независимые dataset_key roads/railways, уникальность `(dataset_import_id, osm_type, osm_id)`, FK на журнал, тип только way, валидная непустая 2D LineString EPSG:4326. `feature_type`, `name`, `ref`, `crosses_boundary`, исходные теги/узлы/метаданные в `raw_data`. GiST отдельно по `geom` и `geom::geography`; индексы OSM ID и типа в снимке. Ограничения сверяют допустимый тип с исходным тегом. Линии не обрезаются/не сливаются; топология и маршрутизация отсутствуют. [Отбор, воспроизведение и ограничения](data/osm-linear.md).

## Снимки зелени и воды OSM

`osm_green_areas` / `osm_water`: независимые dataset_key green_areas/water. FK на журнал; уникальность `(dataset_import_id, osm_type, osm_id)`, type way/relation, версия/время правки, `feature_type`, `representation`, `name`, валидная непустая 2D Polygon/MultiPolygon4326, `crosses_boundary`, исходные теги/узлы/members в `raw_data`. GiST по geom и geom::geography, индексы идентификатора и представления в снимке. Ограничения сверяют тип/представление с тегом. Растительное землепользование и границы парков различаются; перекрытия сохраняются, суммировать их площади нельзя. [Классификация, команды и ограничения](data/osm-areas.md).

Новая миграция от 20.10.2026 добавляет в `osm_green_areas` хранимые GENERATED ALWAYS `is_park`, `is_garden`, `is_vegetation` из исходных тегов. Флаги независимы, заполняются и для старых снимков, вручную не присваиваются. Первичные `feature_type`/`representation` и все исходные поля остаются прежними. Продуктовый поиск парков использует `is_park`; расчёты площади — объединение пересечений с радиусом отдельно по каждой категории в EPSG:32646. Существующие пространственные индексы используются для кандидатов, дополнительные индексы на boolean на этом объёме не добавлялись. [Методика и проверка Татышева/Гвардейского парка](features/area-analysis.md).
