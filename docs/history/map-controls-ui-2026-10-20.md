# Панель слоёв и регулируемая ширина — 20.10.2026

Продолжение UI-аудита PlaceLens. Изменено представление шести существующих слоёв, без новых источников, показателей, API, расчётов, импортов, миграций или изменения снимков. Рабочее дерево до задания содержало многочисленные изменения; они сохранены. `.idea/workspace.xml` не редактируется и не восстанавливается.

## Поведение

- Профиль и сравнение используют `MapLayersPanel`: флажок, картографический образец и название в одной строке. Официальные остановки — синие точки; парки — зелёный контур; растительные территории — оливковый пунктирный контур; вода — синий контур; крупные дороги — оранжевая линия; железнодорожные — фиолетовый пунктир. Цвета/геометрии самого `CityMap` не менялись. Парки и растительность независимы.
- Отдельного раскрытия общей легенды нет. Кнопка «Слои» сворачивает список, сохраняя активные слои и камеру. В свёрнутом состоянии видны количество и компактные обозначения включённых слоёв с названиями. Нет автоматического раскрытия большого блока при включении слоя. При начальном открытии desktop список раскрыт, на мобильном свёрнут; сами слои выключены по прежним правилам.
- «О данных» открывает сведения только конкретного слоя; за раз открыта одна такая секция. Повторное нажатие, «Закрыть сведения» или Escape закрывают её. Escape/кнопка закрытия возвращают фокус к исходной кнопке. Сведения доступны и при выключенном слое, с явной подписью об этом. Это действие не включает слой.
- В сравнении панель одна, флажки общие для двух карт. Сообщения об отсутствии объектов, загрузке, недоступности и частичном покрытии подписаны А/Б. Сведения об источнике и датах имеют отдельные секции сторон, не используют метаданные соседнего адреса. Пустой снимок не объявляется отсутствием объектов на местности. Данные для строки берутся из текущего профиля этой стороны; старый профиль очищается прежним composable при замене/радиусе.
- В URL состояния слоёв и раньше не было. Адреса, радиус, pushState/popstate и каноническая ссылка сохранены. Замена адреса, радиус и история внутри страницы сохраняют флажки; полный переход/refresh начинает с выключенных слоёв. Ширина также не добавляется в URL.

Источники прежние: официальные остановки 24bpd (публикация 31.05.2025, наблюдение неизвестно), локальные снимки OSM (версия источника 18.10.2026, наблюдение неизвестно). Реальные даты/ID берутся из API, констант дат в новом UI нет. Методики и лицензии — [остановки](../features/map-stops-layer.md), [площади](../features/map-area-layers.md), [линии](../features/map-linear-layers.md). Цвета базовой подложки не зависят от флажков дополнительных слоёв.

## Ширина боковой панели

Разделитель есть на главной и в профиле при viewport от 768 px и ширине рабочей области от 700 px. В сравнении сохранён документ с двумя колонками, нового бокового меню нет. На телефоне разделитель не монтируется, остаётся прежний вертикальный порядок: на главной панель перед картой, в профиле результаты перед картой.

Для фактической ширины рабочей области `W`:

```
минимум панели = 320 px
резерв карты = min(440, floor(W / 2)) px
максимум панели = max(320, min(640, floor(W × 0.55), W − резерв карты − 12)) px
```

12 px — отдельная колонка разделителя. Это границы раскладки, не показатель данных. Резерв относится к колонке карты; рамка может уменьшить canvas на 1–2 px. Например, в браузере при viewport 768 px рабочая область профиля была 753 px: допустимый диапазон 320–365 px, canvas при максимуме — 375 px. Сохранённая широкая панель автоматически ограничивается текущим окном, без горизонтального переполнения. Сужение окна само по себе не перезаписывает сохранённое предпочтение.

Перетаскивание использует Pointer Events/capture. Разделитель достижим Tab, имеет `role=separator`, вертикальную ориентацию, aria-controls, минимальную/максимальную/текущую ширину и текст в пикселях. Стрелки меняют ширину на 16 px, Shift+стрелки — на 48 px, Home/End — до границ. Фокус виден. Кнопка ↺ с доступным именем и двойной щелчок возвращают исходную ширину: профиль 480 px, главная 360 px (400 px при рабочей области от 1440 px), всегда с ограничением текущими границами.

Ширина сохраняется только после действия пользователя в `localStorage` с раздельными ключами `placelens:sidebar:home:v1` и `placelens:sidebar:profile:v1`. Сброс удаляет соответствующий ключ. Неверное значение ограничивается/игнорируется; запрет localStorage не ломает управление. Это предпочтение браузера, без серверных записей. Прежний ResizeObserver карты вызывает `map.resize()` при изменении контейнера; новый UI не вызывает fitBounds и не перемонтирует CityMap при сворачивании или изменении ширины.

## Проверки и безопасный запуск

Frontend-проверки не используют БД:

```bash
docker compose exec -T node npm test
docker compose exec -T node npm run typecheck
```

Прошли 53 теста, включая пять новых проверок независимости состояний А/Б, отсутствия автоматических сведений, адаптивного ограничения сохранённой ширины, pointer/keyboard/reset и отказа localStorage. Существующий SSR-тест сравнения получил заглушку нового дочернего компонента. Прежние проверки геометрий и независимости всех комбинаций слоёв сохранены. Production build выполнен без сети во временный каталог контейнером с read-only проектом/зависимостями; установки пакетов нет. Предупреждения о MapLibre-бандле и необязательном fontaine прежние.

Браузерные проверки выполнялись только через отдельный временный PHP-стенд: проект и сборка read-only, tmpfs storage/compiled views/cache, array-сессии/кэш, отдельная cookie и `PGOPTIONS=-c default_transaction_read_only=on`. Перед SQL-сверкой проверяется `SHOW default_transaction_read_only`. Записывающие тесты и отдельная тестовая БД не потребовались. Стенд не следует заменять рабочим HTTP-сервисом с обычными сессиями/кэшем. Схема безопасного запуска также описана в [итоговой проверке слоёв](map-layers-final-check-2026-10-20.md).

Проверены Chrome desktop и мобильный viewport около 390 px: последовательное включение всех шести слоёв на профиле и сравнении, выключение, смешанные выборы, сворачивание/раскрытие и обозначения активных слоёв, источники каждого слоя, Escape/возврат фокуса, мышь и клавиатура разделителя, обе формы сброса, localStorage после refresh, фактическое изменение размеров canvas, адаптивное ограничение на 768 px, радиусы 300/500, назад/вперёд, прямая ссылка сравнения, замена/удаление стороны, реальный пустой слой и неизвестный ID при рабочей второй стороне. Для сравнения использованы центр (Ленина 102), граница сервиса (2-я Линейная 3), замена на Молокова 28. Отсутствие данных одной стороны не скрывает другую.

Проверенные ширины: 320 и 390 px (мобильная компоновка), 768, 1024, 1280 и 1440 px. В журнале 57 контрольных записей: 51 состояние интерфейса и шесть просмотров источников. В зафиксированных состояниях горизонтального переполнения не обнаружено; фокус разделителя — видимая обводка 3 px. Пример перестройки главной: панель 360 → 500 px, canvas 908 → 768 px при той же рабочей области; после обновления сохранённая ширина восстановилась. На сравнении сворачивание сохранило масштаб обеих карт (500 м на шкале до/после); проверена также увеличенная карта профиля после завершения анимации.

Полные контрольные суммы 11 рабочих таблиц совпали, 10 профилей (пять адресов × два радиуса) совпали по всем полям, кроме `calculated_at`. Сборка установлена в локальный `public/build` после проверок: заменён manifest с резервной копией в локальном отчёте, добавлены только новые assets. Старые assets не удалялись. Временный PHP-стенд остановлен и удалён, постоянные сервисы/volumes не менялись.

## Ограничения

Это техническая проверка интерфейса, не исследование с людьми. Физические телефоны, touch-перетаскивание на планшете, Safari/Firefox, экранный диктор, синхронизация между вкладками, длительные сеансы и все адреса города не проверялись. localStorage работает в пределах браузера/origin, включая отдельный origin безопасного стенда; предпочтения не пересылаются со ссылкой. Полный отказ внешней подложки в этом UI-этапе отдельно не моделировался. Новая панель не меняет полноту/актуальность наборов и не добавляет выводов о качестве района, доступе, шуме, воздухе или безопасности.
