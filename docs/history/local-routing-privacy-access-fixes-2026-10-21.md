# Исправления приватности и доступа автомобильного пилота — 21.10.2026

Исправлены четыре проблемы независимого аудита. Режимы и территория пилота не
расширены. Граф, runtime, исходные данные, .env, зависимости, миграции и рабочие
геоданные не менялись. Все новые проверки используют придуманные точки/геометрии,
без контрольных поездок по реальным местам и без внешней маршрутизации.

## Ссылки и хранение

Новый формат — `/trips#trip=<JSON>`, схема данных version1 сохранена. Фрагмент
содержит точные исходные lon/lat, порядок и подписи мест. Это **не шифрование**:
получатель ссылки и браузер могут прочитать содержимое. В форме до передачи ссылки
явно сказано, что получатель увидит координаты и подписи всех сохранённых точек;
указано сохранение ссылки в истории браузера.

При загрузке страницы фрагмент не входит в HTTP URL. Расчёт отправляет данные
отдельным POST JSON на фиксированный локальный `/api/v1/trips/analyze`. Нет
добавления координат в API query, внешнюю аналитику или local/sessionStorage.
Запрос fetch использует no-store/no-referrer. Ответы Nginx, включая ошибки и assets,
имеют `Referrer-Policy: no-referrer`; HTML содержит ранний meta referrer.

Старый query-формат поддержан. После чтения корректной старой ссылки текущая
history entry заменяется фрагментной через replaceState, без добавления лишней
ступени истории. Первоначальный запрос старого URL уже ушёл серверу: клиентский
JavaScript не может отменить это задним числом. Обработанные некорректные старые
query заменяются статическим invalid-фрагментом; неоднозначный query+fragment
отклоняется, расчёт не выполняется. Сброс, прямое открытие, reload, popstate и
hashchange поддержаны; внутренние ссылки к форме/содержанию не затирают сценарий.
При повторном открытии производится новый расчёт, прошлый результат не архивируется.

Публичная GET-страница `/trips` не запускает сессию и не сохраняет старый URL как
Laravel `_previous.url`. Остальные страницы не менялись. API по-прежнему stateless;
rate limiter хранит счётчики, а не тело поездки. Неожиданные исключения trips
журналируются только фиксированным сообщением и именем класса: без exception
message, SQL bindings, stack arguments, URL или тела. Даже с app.debug клиент
получает обобщённую ошибку500. При передаче HTTP в FPM задан
`zend.exception_ignore_args=1`; CLI-конфигурация не менялась.

## Nginx и уже накопленные записи

В access log записываются метод, фиксированный класс маршрута, протокол, статус,
число байтов, время и IP. Не записываются URI/path/query, Referer, User-Agent,
другие пользовательские заголовки или тело. Класс маршрута выбирается map из
фиксированного списка, неизвестные пути превращаются в `other`.

Request-specific error log для этого server выключен через `/dev/null`: штатные
сообщения Nginx нельзя отформатировать для безопасного удаления request/query.
Диагностика запуска/конфигурации сохраняется в глобальном журнале, HTTP-статусы —
в безопасном access log, ошибки приложения — в описанном обезличенном формате.
Это сознательная потеря деталей request-specific ошибок ради приватности.

Trip endpoint имеет предел8KiB и буфер16KiB: принятые тела не сбрасываются в
client-body temp files. Превышение размера отклоняется до PHP. Изолированная
проверка проверяет также отсутствие тела в журнале при upstream502 и отказ413.

Конфигурация проверена `nginx -t` и применена graceful reload, без остановки
контейнеров. Существующие журналы не удалялись, не обрезались и не переписывались.
Сохранённые записи не исчезают после смены формата.

Безопасный агрегированный подсчёт через Docker logs (без вывода/сохранения строк)
показал63 потенциально затронутые записи в Nginx; столько же оставалось после
reload. В доступных Docker-журналах PHP/router признаков trip query/OSRM route URL
не найдено. В storage/logs/laravel.log совпадений не найдено. Это поиск признаков,
а не доказательство отсутствия любых личных данных во всех архивах/резервных копиях.
READ ONLY-проверка сессий показала2 записи с признаком старого trip query; они
сохранены без изменений.

Nginx `/var/log/nginx/access.log` — symlink на `/dev/stdout`, глобальный error.log —
на `/dev/stderr`. Фактическое хранение — Docker logging driver `json-file`, файл
`/var/lib/docker/containers/<nginx-container-id>/<nginx-container-id>-json.log`.
Точный действующий LogPath безопасно определяется:

```bash
docker inspect web_gis-nginx-1 --format '{{.LogPath}}'
```

Сессии находятся в рабочей PostgreSQL-таблице sessions; app log —
`storage/logs/laravel.log`. Содержимое ссылок, строк журналов и payload сессий
в этот документ не включается. Для удаления исторических записей нужно отдельное
согласование: определить охват Docker-файлов/архивов/backup и сессий, способ
контролируемой ротации или очистки. Не обрезать активный Docker json-file вручную.
Никаких cleanup-команд в рамках исправления не выполнялось. Browser history,
синхронизация и уже переданные старые ссылки автоматически не удаляются.

## Правила доступа

Для ways и известных node features используется иерархия
`motorcar → motor_vehicle → vehicle → access`. Более специфичный статический
разрешающий тег имеет приоритет над менее специфичным запретом. Применимый
conditional на выбранном уровне не интерпретируется без времени/контекста:
результат UNKNOWN. Менее специфичный conditional не отменяет более специфичное
безусловное разрешение. Прочие условия на используемых источниках также дают
консервативный отказ.

На обычной дороге без access сохраняется предположение автомобильного графа.
На известном barrier-node без явного разрешения доступа этого предположения нет:
UNKNOWN. Private/locked узел в исходной цепочке не принимается; motorcar=yes
может переопределить vehicle=private, но не locked=yes или применимый conditional.

Исходные annotations связываются с OSM node IDs и направленными парами узлов.
Если такая пара принадлежит известному запрещённому way, решение не зависит от
длины геометрического overlap: закрытый участок1,87м также отклоняется.
Соседние/поперечные ways и nodes с другими IDs не получают теги маршрута по одному
геометрическому пересечению. Неопределённые исходные рёбра остаются UNKNOWN.

Для clipped первого/последнего ребра, которое может не содержать полную пару
annotations, проверяются общий крайний source node ID и совпадение **всего**
крайнего геометрического сегмента в пределах0,25м. Допуск задан константой
`RoutingGeometryGuard::SOURCE_TOLERANCE_M`, соответствует точности OSRM GeoJSON
и не является минимальной длиной private-участка. Проверяются также известные
запрещённые source nodes на совпавшем крайнем ребре у фактических концов линии.
Без достаточных annotations, включая неопределённую нулевую линию, — UNKNOWN.

Отказы не публикуют route, distance/duration values или method. Успехи других
пар сохраняются. Вход/парковка/реальный доступ сегодня по-прежнему не гарантируются.
Полнота проверки ограничена известными OSM features подготовленного runtime;
данные не пересобирались и новые узлы из OSM не скачивались. Историческая доля4/5
не использовалась для ослабления проверок; на реальных координатах после этих
исправлений она заново не измерялась.

## Проверки и воспроизведение

Все проверки запускаются на уже существующих зависимостях. Composer test не
использовать: его script очищает config cache. Полный GIS-suite не запускать:
другие tests могут мигрировать/импортировать данные.

```bash
docker compose exec -T -e APP_ENV=testing -e DB_CONNECTION=sqlite -e DB_DATABASE=:memory: -e DB_URL= -e CACHE_STORE=array -e SESSION_DRIVER=array -e LOG_CHANNEL=stderr -e VIEW_COMPILED_PATH=/tmp/placelens-routing-fixes-views php vendor/bin/phpunit --do-not-cache-result --no-logging --no-coverage
docker compose exec -T -e LOG_CHANNEL=stderr -e 'PGOPTIONS=-c default_transaction_read_only=on' php vendor/bin/phpunit -c phpunit.postgis.xml --do-not-cache-result --no-logging --no-coverage tests/Integration/RoutingGeometryGuardTest.php
docker compose exec -T -u node node node --test tests/frontend/*.test.mjs
docker compose exec -T -u node node node_modules/.bin/vue-tsc --noEmit
PYTHONDONTWRITEBYTECODE=1 python3 tests/security/test_trip_nginx.py
git diff --check
```

Nginx test создаёт отдельный process/PID/port/config/logs только в собственном /tmp
в уже существующем nginx-контейнере. Он использует synthetic query/Referer/body и
закрытый upstream, не вызывает рабочие PHP/БД/OSRM и завершает только свой процесс.
Выводятся статусы проверок, никогда raw URL/logs. Временные тестовые файлы не являются
рабочими журналами. PHP-тесты — SQLite in-memory; GIS-тесты — только CTE SELECT
с синтетическими геометриями в web_gis_test с принудительным READ ONLY.

Frontend-тесты проверяют фактический script TripsPage: прямой fragment, reload,
back/forward без повторного запроса от hashchange, reset, миграцию старого формата,
invalid/ambiguous link, SSR-предупреждение, no-referrer POST, отмену устаревшего
ответа и частичные результаты. Feature-тест подтверждает UNKNOWN/null после
отказов private-node/private-edge при сохранении соседнего AVAILABLE.

Фактический итог: обычный PHP-suite21tests/109assertions; GIS11tests/35assertions;
frontend62/62; Nginx security1/1; typecheck и временная production-сборка успешны.
Проверены только безопасные suites/подмножества, полный мигрирующий GIS-suite
не запускался. Существующая выборка реальных автомобильных пар не пересчитывалась.

Реальный браузерный прогон выполнен на новой production-сборке через временный
локальный сервер с полностью синтетическим API. Подтверждены предупреждение,
reload/back/forward, legacy migration, invalid-link, сохранение fragment при
переходе к содержанию. БД и OSRM не вызываются; тестовые значения не связаны с
реальными местами. Сквозная поездка по рабочему графу и натурная проверка доступа
этим прогоном не подтверждаются.

Vite build выполнялся из отдельной /tmp-копии resources/config с собственным
font-cache/output, зависимостями через read-only использование установленных
пакетов. Предупреждения optional fontaine/large chunk сохранены. В public/build
добавлены7новых файлов, старые assets не перезаписывались/не удалялись. Manifest
обновлён атомарно после проверки отсутствия конфликтов и сохранения исходной
версии в `/tmp/placelens-routing-fixes-9chgqh0r/manifest-before-promotion.json`.

Фактическая команда сборки из подготовленной временной копии
`/tmp/placelens-routing-fix-build.PjdMd8` внутри node-контейнера:

```bash
APP_URL=http://localhost node /var/www/html/node_modules/vite/bin/vite.js build --configLoader native --outDir /tmp/placelens-routing-fix-build.PjdMd8/public/build --emptyOutDir
```

`--emptyOutDir` применялся только к новому временно́му output, не к public/build
рабочего checkout. Финальная сверка исходных файлов данных и прежних assets
совпала; storage/logs/laravel.log не изменился. Старые пользовательские изменения
не сбрасывались, новые зависимости не устанавливались, контейнеры не пересоздавались.
