# Дорожные точки автомобильного пилота — 21.10.2026

## До реализации: результат этапа и критерии приёмки

Ожидаемый результат: точка на здании сохраняется как исходная, единственный
подходящий дорожный кандидат используется автоматически. Это выбор конца
автомобильной линии, а не расчёт подхода или подтверждение входа/парковки.
Несколько близких допустимых кандидатов требуют явного выбора. Ручная дорожная
точка проходит те же серверные проверки. Исходные точки и дорожной выбор
сохраняются только во фрагменте ссылки, включая reload/back/forward.

Радиус не расширяется: прежние35м из закреплённого runtime. Допуск совпадения
исходных геометрий — прежние0,25м. Неоднозначность определяется относительно
ближайшего безопасного кандидата; её правило и границы проверяются синтетическими
геометриями. Отдельные направления разделённой дороги не объединяются только
по близости. При неполном поиске/неизвестном доступе — отказ.

Единственное планируемое изменение проверки зданий: разрешить непрерывный выход
соединителя из содержащего исходную точку контура. Это пунктир, не маршрут.
Другие здания, повторный вход в тот же контур, стены, private gates/roads,
короткие private edges, вода, пересечение другой дороги и границы остаются
блокирующими. Весь автомобильный путь проверяется по исходным annotations.

Расстояние — главное число. Рядом с каждым временем — «модельное время без
актуальных пробок»; парковка и путь от здания до дороги не учтены. Скорости
OSRM, сортировка по минутам и коэффициенты замедления не меняются/не добавляются.

План безопасной проверки: PHP HTTP-contract с fake router/SQLite in-memory;
PostGIS CTE SELECT с придуманными features и принудительным READ ONLY;
frontend-state/SSR/map-layer tests; typecheck; build в отдельном /tmp без
перезаписи прежних assets; реальный браузер desktop/mobile/keyboard и история
на полностью синтетическом локальном стенде. Импортов/миграций/очистки нет.
Обязательны auto/ambiguous/manual/no candidate, private gate/short edge/wall/
boundary, частичный успех, очистка устаревшей линии, URL/reset/reload/back/forward.

Исходная ведомость файлов и копии изменяемых исходников:
`/tmp/placelens-road-choice-ptucs3vw/`. Существующее рабочее дерево содержит много
незакоммиченной работы; сбросы/clean/переключение веток не выполняются.

Аудит времени прочитан из `/tmp/placelens-time-audit-5n4ydk0x/report.md`:
два результата согласованы вычислительно, но профиль оптимистичен на малом
кольце; обычное городское время не подтверждено. Нет оснований считать ручные
точки пользователя ошибкой выбора адресного объекта приложением: точки в том
тесте пользователь ставил самостоятельно. Личные координаты/ссылки в документ
не включаются.

Статус до правок: реализация и проверки этого этапа ещё не выполнены.

## Реализация и правило выбора

Этап реализован. `RoutingGeometryGuard::resolve` читает только проверенные
ячейки прежнего runtime; пространственные операции выполняются в PostGIS,
в транзакции READ ONLY с statement_timeout1500ms. Новых источников/графов нет.

Кандидаты — локальные минимумы расстояния до исходных сегментов автомобильных
ways. Соседние отрезки прямой не превращаются в множество вариантов, но два
положения на одном hairpin-way остаются разными. Дороги с неподтверждённым
автомобильным доступом/применимыми условиями, indoor/area/construction исключены.
Иерархия `motorcar → motor_vehicle → vehicle → access` сохранена.

Внутри прежних35м ближайший безопасный кандидат используется автоматически,
если в полосе **1м** от его расстояния нет другого варианта. Это консервативное
инженерное правило: четыре прежних допуска геометрического совпадения0,25м и
существующий1м запас у конца соединителя в проверке пересечения дороги. Оно не
объявляется измеренной точностью OSM/GPS или доказанным городским нормативом.
Граница полосы проверена на симметричных сторонах, разнице около0,56/1,34м,
раздельных source IDs, общей вершине и изгибе одного way. Неоднозначность всегда
требует выбора. Прежний35м радиус не расширен ради сохранения успешных пар.

Дубли объединяются только в одной исходной OSM-вершине при совпадении точки
в пределах0,25м. Параллельные линии с разными IDs не объединяются по близости.
Если найдено более16вариантов в близкой полосе, результат консервативно
отклоняется: список не обрезается до якобы единственного кандидата.

Ручной выбор проецируется к локальной дороге в тех же пределах35м от исходной
точки и с теми же проверками. При указании закрытой/недопустимой ближайшей дороги
поиск не перепрыгивает на существенно более дальнюю безопасную альтернативу.
Близкие равноценные положения вновь требуют выбора. Точка из URL не считается
доверенной и проверяется заново. После разрешения OSRM получает дорожные точки
с radiuses0,25;0,25; фактические концы линии должны совпасть с выбранными в том
же допуске, а с исходными — оставаться в35м. Самостоятельная перепривязка OSRM
к другой стороне не принимается.

`connector-issues.sql` общий для поиска и проверки итогового пути. Разрешён
только непрерывный начальный участок соединителя внутри содержащего исходную
точку здания; дорожная точка внутри здания, выход с повторным входом, другие
здания, явные стены/ограды, private/unknown gate-nodes, вода, железная дорога,
пересечение другой проезжей части и выход за пилот блокируют привязку. Это
смысловая связь точки здания с дорогой, **не доказанный проход через вход**.
Пунктир не включён в метры/секунды. Неразрешённый реальный доступ остаётся
неизвестным. Общая проверка автомобильной линии по node annotations, private
edges любой длины, gate access, направлению и препятствиям сохранена.

## Интерфейс и ссылка

Исходный маркер S/1–3 сохраняется. Отдельно показаны белая дорожная точка,
тонкий пунктир и расстояние привязки. Кандидаты — жёлтые точки с номерами и
доступными с клавиатуры кнопками; есть приближение к вариантам. Кнопка изменения
дорожной точки переводит карту в явный режим; выбор другого положения не меняет
исходные координаты. Добавление нового места возвращает режим исходной точки.

Расстояние вынесено главным числом, у каждого времени отдельная подпись
«модельное время без актуальных пробок». Рядом указано, что парковка и путь от
здания до дороги не учтены. Для вручную выбранной точки формулировка говорит о
выбранной проезжей части, без обещания, что она ближайшая. Таблицы скоростей,
поворотные штрафы OSRM и сортировка вариантов не менялись. Для оценки обычного
городского времени нужны независимые наблюдения поездок/режимов светофоров/
замедлений и проверка скоростей на кривых; такая калибровка — отдельное задание.

Совместимая схема version1 расширена необязательным `road:{lon,lat}` у start
и каждого place. Исходные координаты/подписи и выбранные road-положения находятся
в `/trips#trip=...`, без query и без округления. Старые version1-ссылки без road
поддержаны; старый query мигрирует по прежнему безопасному правилу. Автоматический
выбор дописывается через replaceState в текущую запись истории, ручное изменение
создаёт новую запись. Reload/back/forward восстанавливают обе точки и проверяют
их снова; результат маршрута не архивируется. Редактирование исходной точки
сбрасывает её road-выбор и немедленно убирает старые линии; поздние ответы не
возвращают их. Чужой отказ не скрывает успешную пару.

## Фактические проверки

Пройдено после последней правки:

- PHP25tests/137assertions: SQLite in-memory, fake HTTP, array cache/session.
- GIS23tests/79assertions: только CTE SELECT с придуманными features, web_gis_test,
  PGOPTIONS READ ONLY. Включена сквозная цепочка настоящего provider/resolver/
  geometry guard с fake OSRM; добавление стены блокирует запрос до router.
- Frontend68/68: фактические script/SSR/GeoJSON страницы, исходные и дорожные
  точки, кандидаты, история, stale responses, partial results, подпись времени.
- TypeScript — успешно; privacy-тест Nginx1/1 — успешно, отдельный процесс/порт/
  журналы в собственном /tmp, рабочие журналы не очищаются.
- Production build — из отдельной /tmp-копии resources/config с собственным
  font cache/output, без установки зависимостей. Остались прежние предупреждения
  optional fontaine/large chunk. Рабочий public/build не использован как output.
- Реальный браузер на этой сборке и полностью синтетическом локальном API:
  auto-маркеры/пунктир, ручная перестановка, варианты на карте/Enter, исходные
  точки без переноса, частичный UNKNOWN без минут, отсутствие кандидатов,
  stale-clear, reset/direct/reload/back/forward, legacy/invalid links,
  клавиатура карты, ширины1280/390/320. Горизонтального переполнения нет.
  На финальном открытии runtime console errors нет. Найденный режим добавления
  места после дорожного выбора исправлен и проверен в браузере и регрессией.

Браузерный API — заглушка: рабочие БД и OSRM не вызываются. Доказательство GIS
отделено от UI-проверки и получено настоящими пространственными SELECT на
синтетических features. Новые поездки по реальным местам, прежние контрольные
пары, полное городское покрытие и натурный доступ не проверялись. Это ограничения
свидетельств, а не утверждение об универсальной пригодности всех зданий.
