# Видимое уведомление о действиях в `/trips` — 21.10.2026

До правок причины и варианты были только в карточках ниже формы. Исходное
дерево зафиксировано по SHA-256 в `/tmp/placelens-action-notice-cfnor0kj/`.
Ожидаемый результат: немодальная сводка по местам, видимая без прокрутки,
переход/фокус к действию, закрытие без потери карточки, отсутствие устаревших
сообщений; desktop/mobile, клавиатура и ARIA. Существующие изменения сохранены.

## Реализация

- Сводка появляется после расчёта только для поездок, требующих действия.
  Номер места, причина и кнопка берутся из существующего `tripFailureMessage`.
  `SNAP_CHOICE_REQUIRED` обозначен как выбор с числом вариантов; это не ошибка.
  При неоднозначности обеих привязок число указано отдельно для старта и места.
- Сводка занимает собственную полосу под шапкой. Только `/trips` получает
  viewport-компоновку с отдельной прокруткой формы/карты/результатов. Полоса
  не наложена поверх контента, не использует модальный слой и не перехватывает
  фокус при появлении. Для трёх длинных причин на коротком экране предусмотрена
  прокрутка самой полосы с ограничением 40dvh/320px.
- «Выбрать вариант» прокручивает карточку и фокусирует первый вариант ещё
  не выбранной привязки; выбор не выполняется. «Уточнить точку» и «Повторить
  расчёт» фокусируют соответствующую кнопку карточки. Фокус и его рамка остаются
  в доступной области прокрутки; действия работают с Enter/Tab.
- Закрытие скрывает только сводку и возвращает фокус в именованную рабочую
  область. Статус, список вариантов и результаты сохраняются. Новый расчёт
  сбрасывает закрытие и скрывает прежнюю сводку до нового ответа. Правка точки
  очищает старый результат; разрешённые состояния исчезают из сводки. При полном
  успехе полосы нет. Успешная соседняя карточка сохраняется при выборе кандидата.
- Сохранён один постоянный `role=status`, `aria-live=polite`, `aria-atomic=true`
  для объявления расчёта/результатов. Сводка — именованный region с кнопками,
  связанными с причиной через `aria-describedby`; это не dialog/alert и не
  ловушка фокуса. Личные подписи, координаты, внутренние коды и raw reason в
  краткую сводку не добавляются.

Изменены только представление `/trips`, утилита сообщений, frontend-тесты и
документация. GIS, радиус, OSRM, время, геоданные, fragment-ссылки и правила
выбора кандидатов не менялись. Новых зависимостей, запросов или хранения нет.

  группировку/частичный успех/ARIA/полный успех; закрытие/повтор/правку/разрешение;
  переход к варианту или действию без нового расчёта и автоматического выбора.

## Обновление реального localhost

Проверка после сообщения о невидимой сводке выявила устаревшую локальную
сборку. Открытая пользовательская страница и свежий `GET /trips` использовали
`/build/assets/app-D3UWwxpj.js`; связанный `TripsPage-gkp_MtW1.js` не содержал
`trip-action-summary`. `public/hot` отсутствовал: страница работала через
`public/build`, а не Vite dev server. Пользовательские URL/точки не читались:
в открытой вкладке проверялись только script src и наличие сводки.

Перед обновлением исходники рабочего дерева, бинарный diff, статус Git и
прежний `public/build` скопированы в `/tmp/placelens-localhost-assets-5dcrrecv/`
(`working-tree/`, `tracked-before.patch`, `build-before/`). Затем выполнено:

```bash
docker compose exec -T -u node node npm run build
docker compose exec -T -u node node npm run typecheck
docker compose exec -T -u node node node --test --test-reporter=dot tests/frontend/*.test.mjs
```

Сборка, typecheck и 82 frontend-теста прошли. Сохраняются предупреждения о
необязательном fontaine и большом JS chunk; зависимости не менялись.
Свежий localhost теперь отдаёт `app-CaSnXe4l.js` и `TripsPage-LhB1MNnV.js`,
в котором присутствуют сводка и её заголовок. Dev server не понадобился.

Проверка выполнена в отдельной вкладке **http://localhost/trips**, без preview
и подмены API: новые синтетические точки введены в форму, выполнен один расчёт.
Настоящий Laravel вернул `NEEDS_REFINEMENT`, `SNAP_NO_SAFE_CANDIDATE` и причину
«Безопасная дорожная точка в пределах 35 м не найдена». Координаты в этот отчёт
не включены. Отказ происходит при проверке привязки, до запроса пути к OSRM.

- Сводка видна сразу: карточка ниже окна, полоса над рабочей областью.
- «Уточнить точку» / Enter переводит к карточке и фокусирует её действие.
  После прокрутки видны и сводка, и прежняя причина.
- Кнопка масштаба карты видима и проходит hit-test, ввод доступен с клавиатуры.
- На реальном localhost проверены 1280×900, 390×844 и 320×740: сводка и целевое
  действие видимы, горизонтального переполнения нет. Ошибок консоли нет.

Причина была только в assets; компоненты, сообщения, маршрутизация и GIS не
исправлялись, новый регрессионный тест не понадобился. Для уже открытой вкладки
нужно обновление страницы (Ctrl+Shift+R), затем расчёт. Пользовательская вкладка
не перезагружалась; её текущий ввод не менялся. Созданная для проверки вкладка
закрыта, viewport восстановлен. БД и геоданные не изменялись, импортов/миграций,
очистки журналов и перезапуска контейнеров не было.
