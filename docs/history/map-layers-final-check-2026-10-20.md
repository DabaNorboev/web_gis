## Контракт и ограничения

Все шесть слоёв по умолчанию выключены. В сравнении общие флажки управляют двумя картами выбранных вариантов; выделение остановки остаётся отдельным для каждой карты. В профиле выбор остановки в списке включает её слой, выключение снимает выделение. Главная и карты поиска сохраняют прежний режим.

Ссылки хранят адресные OSM ID и общий радиус 300/500 м. Флажки слоёв **не входят в URL**: прямое открытие/refresh начинает с выключенных слоёв. Назад/вперёд внутри страницы восстанавливает адреса/радиус и сохраняет выбор флажков. Полный переход к другому профилю начинает состояние заново. Пока запрос загружается, прежние геометрии очищаются; поздний ответ не должен смешиваться с новым выбором.

Используется существующий API профиля: `map.stops_in_radius`, `map.area_layers` и `map.linear_layers`. Переключение видимости не вызывает новых аналитических запросов. Остановки — точки выбранного радиуса. Полигональные/линейные фрагменты обрезаны кругом анализа EPSG:32646 и `data_geom` снимка, возвращаются в EPSG:4326 lon/lat. Полный городской аналитический слой браузеру не передаётся. Перемещение камеры не расширяет область анализа; базовая подложка и её цвета/подписи независимы от флажков.

Парк и растительная территория — независимые признаки; общий OSM ID может быть в обоих слоях. Пересечения, отверстия, разные проезжие части/пути и отдельные исходные ID сохраняются. Доли категорий не складываются. Линейные источники сохраняют `tolerance: 0` из предыдущего этапа; нового упрощения/слияния в этом задании нет.

Пустой доступный слой означает только отсутствие найденных объектов нужного типа в выбранном снимке и области. Ошибка, отсутствующий источник, UNKNOWN/OUTSIDE_SERVICE_AREA и PARTIAL отличимы от пустой выдачи. PARTIAL не превращается в фиктивный ноль. Контуры не подтверждают вход, проход или доступ к берегу; линии не подтверждают соединение/движение. Нет выводов о качестве района, шуме, воздухе, безопасности, зелени двора, купании или подтоплении. Длины линий и общий балл в интерфейсе не показываются; прежние поля длины API оставлены без изменений.

## Найденный и исправленный дефект

На мобильном экране при неполных транспортных данных две подписи «Недостаточно данных» задавали минимальную ширину колонок и выталкивали содержимое за границу страницы. В проверенном случае ширина документа была 392 px при viewport 390 px.

Исправление ограничено транспортным блоком профиля: две колонки используют `minmax(0,1fr)`, длинный текст допускает перенос; только подписи при `value === null` получают размер 16 px. Обычные числа сохраняют прежние 22 px. Существующий SSR-тест нулевого значения теперь допускает атрибуты у `<strong>`, сохраняя проверку самого нуля. Значения, доступность, форматирование результата и формулы не менялись.

Регрессионный случай воспроизведён браузером с имитированным PARTIAL/отсутствующими значениями. Никакие реальные данные ради этого не менялись. Проверяется ширина документа и обе колонки на 320/390 px, а также desktop. Других подтверждённых дефектов слоёв при выполненной выборке не выявлено.

## Безопасный повтор проверок

Из корня проекта безопасные frontend-проверки:

```bash
docker compose exec -T node npm test
docker compose exec -T node npm run typecheck
```

Браузер и проверка рабочих данных запускались **только на отдельном PHP-стенде**: read-only проект/сборка, tmpfs storage/cache/view, array-сессии/кэш, отдельная cookie, `PGOPTIONS=-c default_transaction_read_only=on`. `verify.php`, `inventory.php`, `bounds-areas.php`, `bounds-lines.php`, `verify-stops.php` прекращают работу, если соединение не read-only. Они только читают существующие наборы; импорт/миграции/получение новых данных не нужны.

Воспроизводимые команды старта/проверки/остановки и принудительные phpunit-конфигурации сохранены в локальных артефактах `data/reports/map-layers-final-2026-10-20/`. Для повтора из корня проекта после проверки наличия свободного `127.0.0.1:8813`:

```bash
bash data/reports/map-layers-final-2026-10-20/safe-readonly-checks.sh
# Отдельно, только если нужны транзакционные GIS-проверки:
bash data/reports/map-layers-final-2026-10-20/safe-gis-checks.sh
```

Первый скрипт создаёт временный стенд, проверяет read-only, выполняет SQL-сверки/браузерные сценарии, сравнивает данные и останавливает только созданный им контейнер. Артефакты оставляет в новом `/tmp/placelens-layer-audit.*`. Второй создаёт только новые тестовые БД, копирует структуру без данных и удаляет лишь успешно созданные им БД из явного разрешённого списка. Если имя уже занято, он останавливается без очистки существующей БД. Существующая `web_gis_test` не используется. Для другой установки нужно заранее проверить названия существующих Docker image/network/DB-контейнера в этих скриптах. Оба скрипта проверены `bash -n`; фактический прогон этого этапа выполнен теми же отдельными командами, а не повторным запуском обёрток.

Браузерным сценариям нужны уже имеющиеся Chrome/Playwright (пути можно передать `CHROME_PATH` и `PLAYWRIGHT_MODULE`); они не устанавливают зависимости. Перехват MapLibre-конструктора существует только в проверочном браузере, продуктовых hooks нет. Не направлять эти сценарии на рабочий HTTP-сервис с обычными сессиями/кэшем.

Записывающие GIS-тесты запускались только в новых `placelens_area_layers_test_202610201` и `placelens_linear_layers_test_202610201`. Конфигурации принудительно задают DB_DATABASE и пустой DB_URL; тесты проверяют имя БД и откатывают транзакции. Лишь их отдельный PHP-процесс отключает PGOPTIONS read-only. Рабочую БД, существующую `web_gis_test`, volumes, `.env` и ключи этот порядок не меняет. После тестов подтверждён ноль тестовых записей; созданные БД и временный стенд удаляются.
