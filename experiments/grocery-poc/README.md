# Продуктовые магазины: изолированный PoC

Это отдельный локальный эксперимент. Он не подключён к Laravel/Vue, профилю,
основному сравнению, их поиску или БД. Все адреса, магазины и уличные линии
подготавливаются из **уже сохранённого** OSM PBF. Никаких новых загрузок данных,
миграций и установок зависимостей команды ниже не выполняют.

## Уже подготовленный PoC

Из корня проекта:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 experiments/grocery-poc/server.py
```

Открыть [http://127.0.0.1:8765](http://127.0.0.1:8765). Сервер слушает только loopback.
Завершение — `Ctrl+C`. Для другого свободного локального порта есть `--port`.
Снимок находится в `.runtime/data/`, библиотека карты — в `.runtime/vendor/`.
Эти производные файлы игнорируются **только локальным `.gitignore` эксперимента**;
существующий `.gitignore` проекта не меняется. При отсутствии снимка сервер
завершится с ошибкой; он не начнёт подготовку или скачивание автоматически.

## Воспроизведение подготовки

Нужны уже существующие `web-gis-osm-etl:local`, node-контейнер с установленным
MapLibre и указанный сохранённый PBF. Образ не собирать и зависимости не ставить.
Новая подготовка требует **нового** выходного каталога: существующий `data`
скрипт не перезаписывает. Ниже команда первого запуска, если такого каталога нет:

```bash
mkdir -p experiments/grocery-poc/.runtime
docker run --rm --network=none --read-only --memory=1800m --cpus=2 \
  --user "$(id -u):$(id -g)" \
  -v "$PWD/data/raw:/input:ro" \
  -v "$PWD/experiments/grocery-poc:/poc:ro" \
  -v "$PWD/experiments/grocery-poc/.runtime:/output:rw" \
  -w /poc web-gis-osm-etl:local python /poc/prepare.py \
  /input/osm_pbf/2026-10-19-geofabrik/siberian-fed-district-261018.osm.pbf \
  /input/boundaries/krasnoyarsk/2026-10-07/boundary.geojson /output/data
docker cp web_gis-node-1:/var/www/html/node_modules/maplibre-gl/dist experiments/grocery-poc/.runtime/vendor
docker cp web_gis-node-1:/var/www/html/node_modules/maplibre-gl/LICENSE.txt experiments/grocery-poc/.runtime/vendor/LICENSE.txt
```

Копирование MapLibre выполняется один раз в отсутствующий `vendor`; повторное
копирование каталога Docker может создать вложенный `dist`. При повторении
использовать отдельный новый runtime-каталог и явные пути, не затирать снимок.
Контейнер подготовки не имеет сети, БД, volumes приложения или права записи в raw.
Временный дисковый индекс всех узлов удаляется после чтения. Результат содержит
SHA-256 источника/границы, время версии OSM, правила, статистику и проверку 11 ways.

## Метод и ограничения

- Категория строго `shop=supermarket|convenience|grocery`, для node/way и
  поддерживаемых multipolygon relations. Никаких объединений по имени/адресу/близости.
- Сначала восстанавливаются полные координаты ways из всего PBF. Затем применяется
  bbox территории сервиса с внешним запасом 0,03° долготы / 0,02° широты. Геометрии
  сохраняются целиком. Адресная служебная точка должна лежать в сервисной геометрии.
- Дистанция до точки либо ближайшей части геометрии в локальной сферической
  азимутальной равнопромежуточной проекции (AEQD), центр — адрес, R=6 371 008,8 м.
  Между спроецированными вершинами используются отрезки. Это документированная
  метрическая модель PoC, не PostGIS geography / не эллипсоидальная UTM.
  Сфера отличается от эллипсоида; пограничные значения не считать геодезической
  гарантией. Числовой тест радиуса выполняется **до округления**.
- Полигон учитывается по расстоянию до его геометрии, даже если его служебная точка
  вне круга. Внутри полигона расстояние равно нулю; это не подтверждение входа.
- Адреса из PBF — отдельный экспериментальный каталог элементов с улицей/местом
  и номером дома. Одинаковые подписи не склеиваются, OSM ID виден при выборе.
  Исходный населённый пункт не дописывается по границе. Это не замена поиска PlaceLens.
- Список и карта получают одну FeatureCollection. Карта не использует внешние
  тайлы, шрифты, коммерческие API и декоративные POI; для ориентира есть локальные дороги.
- Полнота и актуальность OSM неизвестны. Время изменения элемента и версия базы
  не являются датой наблюдения. Ноль — отсутствие найденного в снимке, не магазинов.
- Для relation соединение колец — только по общим node refs, с явным отказом при
  неподдерживаемых/неоднозначных members. Это не полноценный валидатор полигонов;
  исходники не чинятся. Ошибки записываются в manifest, не превращаются в нули.

## Безопасные проверки

```bash
PYTHONDONTWRITEBYTECODE=1 python3 experiments/grocery-poc/test_poc.py
PYTHONDONTWRITEBYTECODE=1 python3 experiments/grocery-poc/verify_snapshot.py
docker compose exec node node --check experiments/grocery-poc/app.js
git diff --check
```

Тесты работают с временными фикстурами и отдельным PoC-снимком, без БД. Браузерный
сценарий `check-browser.mjs` читает cases.json после `verify_snapshot.py`,
использует уже установленный Playwright и локальный
Chrome; путь к модулю можно передать через `PLAYWRIGHT_MODULE`, к Chrome — через
`CHROME_PATH`. В ходе этого задания он запускается с имеющимся bundled runtime,
без установки npm-пакетов. Результаты и ограничения — в отдельном отчёте в `docs`.
