# Goal 5: контроль обычного выбора точки

Выборка закрепляется до изменения алгоритма. Это целевая диагностика, не оценка
покрытия города. Только публичные OSM-объекты и синтетические опасные контроли.

Восемь ориентиров: Ленина, 102; соседний квартал; Солнечный; правый берег;
Капитанская; район вокзала; стадион; промышленная окраина. По каждому берётся
ближайший самостоятельный контур площадью не менее 150 м² в сохранённом runtime,
без отбора по результатам маршрутизации. В EPSG:32646 задаются внутренняя точка,
четыре смещения на 3 м, ближайший к ориентиру край, первая вершина, два смещения
края на 3 м и внешняя точка в 5 м от края по направлению от внутренней точки.
Последняя не объявляется доступным двором. Реальные клики по видимым зданиям и
дворам фиксируются отдельно с координатами из формы и описанием действия.

Итоговый аудит: 80 закреплённых случаев содержат 79 различных координат — край
и первая вершина Капитанской совпали. Выборка не переписывается после замеров;
`summarize.py` дополнительно считает результат по уникальным координатам.

Каждая точка проверяется как старт до публичного контроля проспекта Мира и как
цель от него. Старые 11 маршрутных контролей сохраняются отдельной группой.
Все результаты сохраняются до правок; тот же JSON используется после правок.

Ожидания и критерии:

- Единственный допустимый кандидат в 35 м — SELECTED; равноценные стороны — CHOOSE;
  отсутствие подходящего кандидата — NONE с доказанной причиной, не фиктивным нулём.
- Отдельно считать привязку каждого исследуемого конца и окончательный маршрут:
  SELECTED/CHOOSE/NONE, AVAILABLE/прочее, расстояния и изменение при ±3 м.
- Причины: расстояние, неоднозначность, препятствие, доступ, неполные данные,
  ошибка реализации. Причин может быть несколько; неизвестность не приписывать
  ближайшему концу. Сопоставлять результат с исходными тегами/геометрией.
- Любое новое принятие требует разбора линии и обеих привязок. Известные private,
  private-ребро менее 2 м, ворота без доступа, стены, вода, чужое здание, повторный
  вход в контур, другая проезжая часть, граница и неполные данные должны продолжать
  давать отказ. Синтетические проверки не заменяют реальные пары.
- Ошибочный допуск означает конфликт с известным источником/контролем; отсутствие
  такого конфликта не доказывает физический доступ. Натурная доля ошибок неизвестна.
- Порог 35 м, скорости, runtime и рабочие геоданные не меняются. Контур здания
  не подтверждает вход. Соединитель не входит в метрики. API расширяется совместимо;
  UI остаётся для отдельного Goal 6.

`freeze.php` читает только подготовленный runtime и выполняет PostGIS SELECT под
READ ONLY. Отказывается перезаписывать выборку. `measure.php` проверяет закреплённые
точки настоящим provider → OSRM → GIS, также с READ ONLY; вывод в новый файл.

## Повтор на существующем runtime

Выполнять из корня проекта. Новая выборка — только отдельная версия задания;
для сравнения использовать уже замороженные JSON. Output должен отсутствовать.

```bash
docker compose exec -T -e LOG_CHANNEL=stderr -e 'PGOPTIONS=-c default_transaction_read_only=on' php php experiments/routing-clicks/measure.php experiments/routing-clicks/controls.json data/reports/goal5-repeat-main.json
docker compose exec -T -e LOG_CHANNEL=stderr -e 'PGOPTIONS=-c default_transaction_read_only=on' php php experiments/routing-clicks/measure.php experiments/routing-clicks/browser-controls.json data/reports/goal5-repeat-clicks.json
docker compose exec -T -e LOG_CHANNEL=stderr -e 'PGOPTIONS=-c default_transaction_read_only=on' php php experiments/routing-clicks/historical.php data/reports/goal5-repeat-historical.json
```

`PLACELENS_BASELINE_ROUTING` позволяет загрузить PHP/SQL из сохранённого каталога
прежней реализации, не перезаписывая действующие исходники. Рабочая копия этого
задания: `data/reports/goal5-routing-2026-10-23/resume/original-routing/`.
Не указывать произвольный чужой код. Данные runtime не пересоздаются.

`inspect.php`, `inspect-snaps.php`, `boundary-probe.php`, `explain.php` — отдельные
читающие диагностические инструменты. Они сохраняют публичные raw-сведения в
каталог отчёта; не применять к личным точкам. `audit-admissions.php` сверяет каждую
новую принятую линию старой/новой проверкой и raw OSRM. Для накопления всех raw в
этом CLI-аудите используется `php -d memory_limit=512M`; HTTP-лимит не меняется.
`http-check.php` отправляет семь публичных сценариев на внутренний опубликованный
Nginx. `summarize.py <каталог отчёта>` проверяет соответствие выборок и сохранение
прежних успехов, затем создаёт `comparison-final.json`, не затирая прежний файл.

Итог и ограничения: `docs/local-routing-clicks-2026-10-23.md`.
