# Локальное сравнение маршрутизаторов

Изолированный эксперимент по заданию от 21.10.2026. Laravel/Vue, рабочая БД,
Compose, исходные данные и существующие PoC сохраняются. Нет публичного роутера.
Исторический аудит: `docs/research/local-routing-audit.md`.

## Этап 2: ожидаемый результат и проверки

До запросов движков закрепить реальные координаты, способ выбора, одинаковые
данные, правила принятия и ресурсные ограничения. Проверить происхождение точек,
покрытие, обязательные сложные случаи и контрольную сумму выборки.

Выборка `controls.json`: 11 пар × 2 режима. Пять пар выбраны по исходным вершинам
улиц из существующего grocery-снимка (центр, Солнечный, правый берег, мост,
железная дорога). Три пары восстановлены из журнала 18.10: главный вход «Кванта»,
стадион и внешний старт гостиницы. Две пары начинаются со служебных точек
реальных адресных объектов: они **не являются входами**. Последняя пара проверяет
выход за пилот. Эта выборка не репрезентативна для оценки городского покрытия.
Выбор ближайшей исходной вершины выполняется только при составлении уличных
контролей, записан в manifest и не является скрытой привязкой пользовательского ввода.

SHA-256 выборки: `27926bfefa29e9113c943cf2649097ede430a3c34b2c92361d56239c2a1b2e06`.
После первого запроса менять её нельзя; исправление требует новой версии и полного
повтора обоих кандидатов с объяснением. Сырые ответы пишутся в новый каталог,
повторный запуск не затирает старые результаты.

## До теста: правила решения v1

1. **Обе привязки.** Для walking максимум 20 м, для driving 35 м на каждом конце.
   Это верхние пределы для предложения уточнить точку, а не доказанная точность OSM.
   Уличные вершины имеют 7 знаков координат (округление менее метра), исторические
   клики — неизвестную погрешность; адресные центры могут быть далеко от входа.
   20 м допускает небольшой ручной клик, но отсечёт прежние 35/55/86 м;
   35 м для автомобиля допускает отступ до проезжей части/соседней полосы.
   Пример стены стадиона 15,6 м всё равно обязан быть отклонён пространственной
   проверкой. Порог нельзя увеличивать по результатам теста.
2. **Соответствие цели.** Для любой длины snap отклонить соединитель через
   стену/здание/воду/неразрешённые ворота или на другую сторону дороги без
   подтверждённого перехода. Вход, парковка и место посадки не выводятся из
   автопривязки. Служебная точка здания требует уточнения снаружи. Историческая
   площадка не получает подтверждения из совпадения с прежним тестом.
3. **Геометрия.** Сверить исходные и фактические концы, полную линию и исходные
   OSM ways/tags. Пересечение в плане не соединяет мост, тоннель и railway.
   Проверить доступ/направление для режима. Indoor, эскалатор, проход без
   подтверждённого выхода/режима доступа → `UNKNOWN`, без пользовательских минут.
   Неисследованный конфликт → `UNKNOWN`, а не автоматический успех.
4. **Статусы.** `ACCEPTED` — линия и оба конца прошли все проверки модели;
   `NEEDS_REFINEMENT` — координату надо уточнить; `NO_PATH` — явный ответ графа
   об отсутствии пути при допустимых привязках; `UNKNOWN` — таймаут, ошибка,
   неподтверждённая геометрия или неполный матричный результат;
   `OUTSIDE_PILOT` — вне заранее ограниченной территории. `NO_PATH` не означает
   невозможность поездки в реальности. Только `ACCEPTED` имеет пользовательские
   расстояние/время; остальные имеют null. Диагностический raw ETA сохраняется
   отдельно. Нерассчитанные соединители в длину/время не включаются.
5. **Матрица.** 3 старта × 3 цели из manifest, дополнительно недопустимая цель.
   Успешные пары не теряются из-за одной ошибки. Ячейка не принимается без
   проверки её геометрии/концов; при отсутствии геометрии требуется route для пары.
   Нет `fallback_speed`, прямых линий вместо отказов или нулей вместо null.
   Дополнительная маленькая синтетическая разорванная сеть может проверить
   протокол `NO_PATH`; это не доказательство реальной городской проходимости.
6. **Покрытие.** Одинаковый существующий региональный PBF, одна извлечённая область
   [92.70,55.90,93.20,56.20] для обоих кандидатов, полные выбранные ways.
   Принятые линии не должны подходить ближе 1 км к границе графа; иначе неизвестно,
   не потерян ли более подходящий обход. Вне bbox запрос отклоняется до роутера.
   Проверка границы — не утверждение полноты OSM. Сравнение с прямой дистанцией
   показывает только величину обхода, не заменяет маршрут.
7. **Ресурсы.** Подготовка каждого профиля/движка: не более 10 мин, 2 CPU,
   2 GiB RAM, без swap; общий производный диск до 3 GiB. Движки тестировать
   последовательно: сейчас доступно ~4,65 GiB RAM, swap заполнен.
   Сервис: 2 CPU / 1 GiB; warm n=20 после 3 прогревов, route p95 ≤500 мс,
   matrix 3×3 p95 ≤1500 мс, жёсткий timeout 3 с; cold отдельно.
   Это бюджет интерактивного прототипа на имеющемся компьютере, не SLA.
   Записать CPU seconds, wall time, peak memory и размер, не подменять измерение
   установленным лимитом. Если метрика недоступна — явно неизвестно.
8. **Go отдельно для walking/driving.** Не менее 4 из 5 обычных уличных контролей
   приняты; все выявленные опасные привязки/маршруты надёжно подавлены;
   нет ошибочно принятых отрицательных контролей; пройдены матрица/отказы,
   ресурсы и воспроизводимость. Это минимальная проверка пилота, не процент
   городского покрытия. Одного успеха на уличных вершинах недостаточно: должен
   работать безопасный путь уточнения произвольных точек. Неоценённые проверки
   не означают Go.
9. **Области поиска жилья.** Изохрона допустима только после независимой проверки
   барьеров/дыр/направления и привязок её кандидатов. Альтернатива — конечный
   набор явно проверенных адресных/уличных точек с матрицей и пропусками, без
   сплошного полигона и утверждений между точками. Наличие API изохрон само по
   себе не даёт Go. Неподтверждённая область не блокирует отдельный честный маршрут.

OSRM требует отдельного подготовленного графа для foot/car: название режима
в URL не меняет профиль. Для Valhalla фиксируются pedestrian/auto и все параметры.
Профили сравниваются по геометрии/пригодности, ETA разных стандартных моделей
скорости не трактуется как ошибка реального времени поездки.
Официальные основания: [OSRM build](https://github.com/Project-OSRM/osrm-backend/blob/v5.27.1/README.md),
[foot profile](https://github.com/Project-OSRM/osrm-backend/blob/v5.27.1/profiles/foot.lua).

## Этап 3: ожидаемый результат и проверки

Изолированно получить воспроизводимые route/matrix результаты обоих движков на
одном PBF, выполнить проверки выше и записать ресурсы. Не публиковать порты,
не менять приложение/БД, не скачивать новые геоданные и не ставить системные пакеты.
При отсутствии исполняемых движков сначала зафиксировать это ограничение;
не выдавать документацию или исторические demo-ответы за новый локальный тест.

Этапы 4–6 начинаются только после полного подтверждения предшествующего этапа.

## Воспроизведение без перезаписи имеющихся результатов

Нужны уже сохранённый PBF и локальные образы (digests закреплены в `run.py`).
Никакие команды установки системных пакетов или получения новых геоданных не нужны.
Для нового повтора выбрать **новый отсутствующий** каталог отчёта:

```bash
export PLACELENS_ROUTING_POC_OUTPUT="$PWD/data/reports/local-routing-replay"
mkdir -p "$PLACELENS_ROUTING_POC_OUTPUT/prepared"
docker run --rm --network=none --read-only --memory=1800m --memory-swap=1800m --cpus=2 \
  --user "$(id -u):$(id -g)" \
  -v "$PWD/data/raw/osm_pbf/2026-10-19-geofabrik:/input:ro" \
  -v "$PWD/experiments/local-routing-poc:/experiment:ro" \
  -v "$PLACELENS_ROUTING_POC_OUTPUT/prepared:/output:rw" \
  web-gis-osm-etl:local python /experiment/extract.py
PYTHONDONTWRITEBYTECODE=1 python3 experiments/local-routing-poc/run.py
PYTHONDONTWRITEBYTECODE=1 python3 experiments/local-routing-poc/diagnostic_run.py
PYTHONDONTWRITEBYTECODE=1 python3 experiments/local-routing-poc/diagnostic_run.py capability
PYTHONDONTWRITEBYTECODE=1 python3 experiments/local-routing-poc/audit.py
docker exec -e 'PGOPTIONS=-c default_transaction_read_only=on' \
  -e PLACELENS_ROUTING_POC_OUTPUT=/var/www/html/data/reports/local-routing-replay \
  web_gis-php-1 php -d memory_limit=512M experiments/local-routing-poc/review.php \
  > "$PLACELENS_ROUTING_POC_OUTPUT/geometry-review.json"
PYTHONDONTWRITEBYTECODE=1 python3 experiments/local-routing-poc/directions.py
PYTHONDONTWRITEBYTECODE=1 python3 experiments/local-routing-poc/finalize.py
```

`run.py` отказывается перезаписывать каталоги графов. Диагностика проверяет отсутствие
выходного файла до запуска. Подготовка отказывается перезаписывать PBF.
Графы/ответы/выводы направляются только в каталог отчёта. PHP-ревью требует
принудительно read-only соединение. Файлы исходной БД не импортируются и не мигрируют.
Контейнеры движков работают `network=none`; helper подключается только к их
сетевому пространству имён. Все временные серверы удаляются в `finally`.

Проверки нового кода:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 experiments/local-routing-poc/test_contract.py
docker exec -e 'PGOPTIONS=-c default_transaction_read_only=on' web_gis-php-1 \
  php experiments/local-routing-poc/check_geometry.php
git diff --check
```
